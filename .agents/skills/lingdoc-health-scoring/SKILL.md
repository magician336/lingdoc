# LingDoc 项目健康度评分

使用本 Skill 时，先读取仓库根目录的 [项目健康度评分协议](../../../docs/项目健康度评分协议.md)。它是权重、评分等级、评分时点和当前基线的唯一依据。

## 适用范围

- 用户要求评估 LingDoc、某个 Spec 或 PR 的设计健康度、维护风险或仓库集成程度。
- 用户要求给出 `H_L`、`F_R`、0–100 分或 A/B/C 置信度。
- 用户要求比较 Spec 完成时和 PR 合并前的评分变化。

不要把 `F_R` 解释为整个 WeKnora 仓库的质量分数；它只表示 LingDoc 与宿主仓库的契合度。

## 工作流程

1. 确认 Git 根目录、当前 SHA、目标 Spec 或 PR，以及评分阶段。
2. 按项目 `AGENTS.md` 使用 CodeGraph 理解代码；必要时先确认 `.codegraph/` 已初始化并保持索引最新。
3. 阅读当前 Spec、`CONTEXT.md`、`GLOSSARY.md`、相关接口契约、测试、CI 和验收材料。区分当前依据、历史记录和设计意图。
4. 分别计算 `H_L` 和 `F_R`。两者使用相同六维权重，但 `H_L` 观察 LingDoc 内部，`F_R` 观察 LingDoc 与宿主仓库的边界。
5. 每个二级指标给 0–5 分，并记录证据路径、验证命令、置信度和改进动作。不要用文件数、代码行数或测试数量直接代替复杂性判断。
6. Spec 阶段把尚未实现的代码证据标记为待验证；PR 阶段重新检查真实代码、失败/权限/恢复路径、CI 和文档同步，并记录 `ΔH_L`、`ΔF_R`。
7. 报告健康等级、关键阻断项和未覆盖风险。若关键维度低于 2/5，单独列为阻断风险。

## 证据与环境约束

- A 级置信度需要自动化测试、CodeGraph、CI 或可复现运行结果；B 级允许代码抽样和文档证据；C 级表示主要依赖未验证假设。
- “未知的未知”不直接评分，使用未知发现速度、失败诊断、可观测性、回退和假设验证来评估。
- Go 测试优先使用项目约定的 WSL2 Ubuntu、Go 1.26 和 Linux SQLite 环境。`sqlite3.h`、cgo、CRT 或 MinGW 工具链错误先记录为环境限制，除非业务断言本身失败。
- 不要把未运行的测试写成通过；记录 PASS、FAIL、BLOCKED 或 NOT RUN 及确切命令。

## 输出要求

默认输出：

- `H_L`：LingDoc 系统健康度 /100 和置信度；
- `F_R`：LingDoc—仓库契合度 /100 和置信度；
- 六维分项表和关键证据；
- 与上一次评分的变化；
- 最高优先级的治理动作；
- Git SHA、Spec/PR、取样范围、验证命令和未覆盖风险。

需要快速填写评分卡时，读取 [评分卡模板](references/评分卡模板.md)。
