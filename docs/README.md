## 文档状态规则

- Spec、当前实施方案和验收协议是当前开发与验收依据。
- 历史计划、关闭 Issue 和旧验收报告保留原文，用于解释已经发生的实现和证据，不自动代表当前能力或下一阶段范围。
- 代码、真实运行结果和合并 PR 优先于静态计划；文档不能把“已写 Spec”或“已合并代码”直接写成“已通过真实验收”。
- 任何影响功能边界、依赖、权限或验收条件的变更，先更新对应文档和 Issue，再实现代码。

## 协作流程

开发前在飞书说明计划和依赖，并在对应 Issue 认领；开发结束后提交关联 Issue 的 PR，写明验证命令和结果；PR 合并到 `main` 后再关闭 Issue。
