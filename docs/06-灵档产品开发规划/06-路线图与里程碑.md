# 按交接结果推进的路线图

本轮按依赖推进，不按日期把三个人排满，任务均待领取。完整 Beta、生产治理和多模板扩展另行规划。

| 结果 | 对应任务 | 可以提前并行什么 |
|---|---|---|
| 主要技术未知有真实结果 | T01–T05 | 检索/生成、持久化/并发、DOCX 分别验证，代码可直接演进为功能 |
| 消费者可以独立开工 | T02、T06 及各提供方 | 模板/上下文/候选/交付输入先给固定实现，不等全部 HTTP 定稿 |
| 项目能持续写作 | T07、T08、T15、T16 | 页面使用契约 Mock 提前做 |
| AI 进入真实章节 | T09–T11、T17 | 采纳用固定候选先测版本与幂等 |
| 文件对应已确认内容 | T12–T14、T18 | 固定输入先试导出器；最终验证须接真实快照 |
| 失败后能继续工作 | T19、T20 及各提供方 | 错误场景随功能验证，不全部堆给最后的联调任务 |

真实依赖：生成需要 T08 上下文和 T09 来源；采纳需要 T10 候选和 T08 写入；冻结需要 T12 输入和 T09 当前来源检查；导出需要 T13 快照。它们是接真的依赖，不阻止用固定实现提前开发。

UI 可演示、真实接口可用、跨任务交接通过、完整流程通过分别记录。每次完成一个可描述的用户结果，不把三个局部演示合称闭环。

领取入口见[任务池](../TEAM_DEVELOPMENT_TASKS.md)，容量与重估触发见[范围与任务流程](../08-本轮实施方案/01-范围与任务流程.md)。
