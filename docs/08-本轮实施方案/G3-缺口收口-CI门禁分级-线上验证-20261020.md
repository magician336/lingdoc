# G3 缺口收口：纯格式提交门禁的线上验证（#288）

## 结论

**门禁在真实 GitHub Actions 上按设计工作**，而且这次验证**抓到了一个真缺陷并修掉了它**。

最终观测（head `c1e3fbf`，PR #289，第四次推送）：

| 观测点 | 实测 |
| --- | --- |
| 内容判定 | 6 个 scope job 全部 `format_only: true`，理由 `internal/lingdoc/workspacecore/impact_severity.go: comments and whitespace only` |
| **测试类 job** | App 的「Format, vet, test, and build」、Frontend 的「Test, type-check, and build」与「Docker multi-stage image」、LingDoc Mock、Workspace Concurrency、Interface Integration（integration + frontend）、F01 Runner —— **全部 `completed/skipped`** |
| **lint** | Go Lint 的「detect lint modules」与「golangci-lint (.)」—— **completed/success**（照跑） |
| 摘要与 PR gate | Minimal Acceptance Summary success；PR gate success（其内部 provider tests 与 frontend 两步 skipped，contracts 校验照跑） |

## 实验设计

一条 PR，四次推送，每次只改一处，用来把三个观测点分开看：

| 推送 | head | 改了什么 | 期望 | 实测 |
| --- | --- | --- | --- | --- |
| 1 | `fb37295` | 一条注释 | `opened` → **完整矩阵** | ✅ `run=true, format_only=false`；「Format, vet, test, and build」pass（2m32s）、`golangci-lint (.)` pass（7m39s）、frontend / concurrency / detect lint modules 全 pass |
| 2 | `bbd513b` | 再一条注释 | `synchronize` → **跳过** | ⚠️ 判定**正确**（`format_only=true` + 理由），但**测试 job 照跑** → 抓到缺陷 |
| 3 | `99d56ca` | 工作流 YAML + 守护测试 | 非格式改动 → **完整矩阵** | ✅ 跑通（同时是「非格式提交不跳过」的线上对照） |
| 4 | `c1e3fbf` | 再一条注释 | `synchronize` → **跳过** + lint 仍跑 | ✅ 全部达成（见上表） |

四次改动都是**只加注释**：注释改动满足判定器的第二个判据（「只改注释与空白」），且不改变任何行为——是最干净的可观察样本。

## 抓到的缺陷

这次验证抓到**两个**缺陷。第一个让门禁完全失效，第二个让「保护门禁的东西」自己没人跑。

### 缺陷一：job outputs 是白名单，快门禁在所有工作流上从未生效

#### 现象

第二次推送的 scope 判定完全正确，却**没有跳过**任何测试 job。

#### 根因

**job 的 outputs 是显式白名单。**

scope 步骤确实把 `format_only` 写进了 `GITHUB_OUTPUT`，但七个工作流的 scope job 只声明了 `run`：

```yaml
  scope:
    outputs:
      run: ${{ steps.scope.outputs.run }}      # ← format_only 没声明
```

于是 `needs.scope.outputs.format_only` 取到的是**空字符串**，`'' != 'true'` 成立，条件恒真 → job 照跑。**这条规则在所有工作流里都静默失效了。**

PR gate 里的两个测试步骤反而是好的：它们用 **step 级** 引用（`steps.scope.outputs.format_only`），step outputs 不需要声明——实测那两步确实 skipped。

#### 修复

- 六个会跳过测试类 job 的工作流（`app.yml`、`frontend.yml`、`lingdoc-mock.yml`、`lingdoc-workspace-concurrency.yml`、`lingdoc-interface-integration.yml`、`lingdoc-f01-runner.yml`）的 scope job 补上 `format_only: ${{ steps.scope.outputs.format_only }}`。
- 新增守护测试 `WorkflowWiringTests.test_every_gated_workflow_declares_the_format_only_output`：断言每个会跳过测试类 job 的工作流，其 scope job 都声明了这个 output。**已验证它能抓住缺陷**：临时去掉声明 → 测试红并明确报出「scope job must declare the format_only output」，恢复 → 绿。

#### 本地验证方法的漏洞

这次能抓到缺陷，本身说明**纯本地的求值验证不够**：此前那次「用真实工作流 `if` 表达式逐条求值」把脚本写出的**全部** GITHUB_OUTPUT 直接喂给求值器，**没有模拟 job outputs 的白名单**，于是本地显示「正确」、线上是「失效」。

守护测试现在覆盖了这一层：它读的是**工作流文件里声明的** outputs，而不是脚本写出的键。

### 缺陷二：守护测试自己没有任何工作流在跑

#### 现象

追问「谁在运行 `scripts/ci` 下的测试」时发现：CI 里只有 `lingdoc-review.yml` 跑 `test_lingdoc_pr_scope.py`。**`test_lingdoc_format_scope.py`（含刚加的守护测试）与 `test_lingdoc_change_scope.py` 从未在 CI 执行。**

#### 根因

PR #287 引入的分类器与守护测试只落地在仓内，没有任何工作流引用它们。门禁自己的回归保护没有接线——**保护网本身没被挂上**。

#### 修复

`lingdoc-review.yml` 新增两步：

```yaml
      - uses: actions/setup-go@v6          # gofmt 等价判据需要 gofmt 在 PATH 上
        with:
          go-version-file: go.mod

      - name: Test CI scope scripts
        id: ciscripts
        run: python -m unittest discover -s scripts/ci -p 'test_lingdoc_*.py' -v
```

这一步**无条件执行**：纯格式提交也必须跑它，否则守护测试就形同虚设。结果作为 `ciscripts` 写进 PR gate 的「Publish check boundary and results」。

`setup-go` 由此从原先「仅在 provider tests 要跑时安装」的条件步骤**上移并改为无条件**——`gofmt` 判据需要它，而这一步现在总是要跑。

## 复现方式

任何一次纯格式提交（`go fmt` 产物、只修订注释）推到一个已开的 PR 上：

1. 看该次 `Scope latest PR update` 的输出：`format_only=true` 且带判定理由；
2. 测试类 job 显示 **skipped**（不是 Pending、不是 cancelled）；
3. **lint 仍然执行并通过**。

第三点最关键：若某次格式提交被 lint 拦下，说明判定器把「有问题的格式改动」放过了，快门禁过宽，应当收紧判据并重开 #284。
