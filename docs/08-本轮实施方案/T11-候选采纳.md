# T11：候选采纳开发计划

## 1. 目标与边界

T11 交付“候选读取 → 服务端复核 → 原子整章替换 → 新版本读回”的用户结果，并同步交付候选预览与整章采纳确认界面。

本任务包含：

- `WorkspaceWriter.AcceptCandidate` 领域接口与 SQLite 持久化；
- 候选、章节版本、来源和研究条件的服务端复核；
- HTTP 薄适配与幂等处理；
- 候选预览、替换确认、错误恢复的前端 adapter 和最小组件；
- 契约、领域、数据库副作用和集成测试。

本任务不包含逐章确认、`DeliveryInput`、冻结、导出和下载；这些属于 T12–T14。

## 2. 已确认的设计决策

1. 先实现领域接口和 SQLite 原子持久化，再接 HTTP，最后接 Vue adapter。
2. 采纳始终是整章替换，不支持把旧正文与候选隐式合并。
3. 空章首次采纳传 `replace_existing=false`；已有正文必须由用户明确确认并传 `true`。
4. 采纳成功后前端重新读取章节，不做本地乐观拼接；取消不发送写请求。
5. 旧章节版本、旧待核项和旧处置/确认记录必须保留；新版本使用候选的新待核集合，并将确认状态置为无效/待重新确认。
6. `F21` 导出历史标签只作为 T14/T15 的跨任务回归项，不作为 T11 主验收。

## 3. 依赖与输入

### 接真依赖

- T08：章节版本、`expected_chapter_version_id`、`expected_spec_revision`、条件写入和一致读；
- T09：`SourcePolicy.Validate`、资料当前授权、来源存在性、定位和资料版本检查；
- T10：`CandidateReader.Get`、候选 `basis`、`validity`、引用和 `review_items`。

### 可先开发的固定实现

- 固定项目、章节、研究条件和章节版本；
- 固定 CandidateReader；
- 固定 SourcePolicy；
- 固定成功、过期和来源失效候选；
- 固定 SQLite 测试数据库及真实事务。

## 4. 分阶段实施

### 阶段 A：领域模型与事务边界

- 定义采纳命令、结果、领域错误和依赖接口；
- 明确授权检查、幂等检查、候选读取、来源复核、版本比较、事务写入的顺序；
- 建立章节版本不可变、当前版本指针、旧版本留存和待核集合替换规则；
- 约束 `source_ids` 与正文 `[[source:id]]` 集合一致；
- 对已有正文且 `replace_existing=false` 返回 `invalid_state`，任何失败均不写入。

### 阶段 B：SQLite 原子持久化

- 增加章节、章节版本、待核项/处置历史和采纳幂等记录所需迁移，沿用现有 LingDoc SQLite 迁移路径；
- 在一个事务中创建新章节版本、更新当前版本指针、递增项目版本并保存幂等结果；
- 通过唯一约束和条件更新防止并发采纳重复写入；
- 验证响应丢失后的同键重放先返回原结果，不被旧版本比较误判。

### 阶段 C：HTTP 薄适配

- 实现 `acceptCandidate` 路由和请求/响应 schema 校验；
- 从认证上下文取得租户和操作者，不接受客户端传入的身份；
- 复用统一成功/失败 envelope、`request_id` 和 `meta.replayed/refresh_required`；
- 映射 `401/403/404/409/422/429/503`，不在 HTTP 层复制领域判据；
- 补 OpenAPI、场景样例和请求副作用断言。

### 阶段 D：前端采纳切片

- 新增候选读取和采纳 API adapter，统一携带幂等键与预期版本；
- 新增候选预览抽屉/对话框，展示正文、引用、待核项和 basis；
- 空章显示直接采纳；已有正文显示替换影响并要求明确确认；
- 取消不发请求；采纳成功后重新 GET 章节；
- `409/422` 保留预览内容，提示重新读取、版本冲突或确认替换；
- 不新增平行业务状态，组件可挂载到后续工作台。

### 阶段 E：接真与交接

- 依次替换 CandidateReader、SourcePolicy 和章节写入固定实现；
- 跑两章连续流程中的生成→候选读取→采纳→重新读取片段；
- 记录 `mock`、`real_api_fake_model`、`real` 接入状态；
- 交付复现步骤、测试命令、数据库副作用查询和未支持项。

## 5. 必验测试矩阵

### 成功路径

- 空章首次采纳成功，生成不可变新章节版本；
- 采纳结果包含候选正文、引用和全部 `review_items`；
- 采纳后重新读取返回新版本，确认状态为待重新确认。

### 失败与并发路径

- `F15`：正文不含警示时，待核项仍被继承；
- `F18`：授权优先；同键同请求重放不重复写；同键不同请求返回 `idempotency_conflict`；
- `F20`：已有人工正文再次采纳时，旧版本、旧确认和旧待核/处置记录留存，新候选整章替换；
- 候选 `stale`、来源撤权、来源版本变化、项目或章节不匹配被拒绝；
- 预期章节版本或研究条件版本不一致返回 `409`；
- 已有正文但 `replace_existing=false` 返回 `422 invalid_state`；
- 取消预览不产生写请求；
- 并发相同采纳最多一个新版本，数据库中无重复副作用。

## 6. 验收标准

- 首次采纳正确，旧版本不可变且可查询；
- 已有章节必须显式确认整章替换，无隐式合并；
- 来源和候选 basis 经服务端重新复核，不能只信客户端字段；
- 旧章/旧处置/旧确认留存，新版必须重新确认；
- 同一幂等键重放不重复写，响应丢失可恢复；
- 前端取消无写请求，成功后能读回新版本，失败保留可恢复状态；
- 契约检查、领域测试、SQLite 集成测试和前端 adapter 测试均有明确 PASS/FAIL 记录。

## 7. 主要风险与交接证据

### 风险

- T08/T10/T09 接口形状尚未完全接真，需先用固定实现锁定调用顺序；
- `SourcePolicy.Validate` 依赖进程内来源对象，跨进程 HTTP 传输时不能退化成只检查授权；
- 旧章节确认与待核处置的历史留存若只靠静态响应，不能证明数据库副作用，必须查询真实数据库；
- 幂等记录与章节写入不在同一事务会产生“已写但未重放”或重复版本。

### 交接证据

- 可复现请求序列和固定输入；
- 领域、HTTP、SQLite 集成和前端测试命令及结果；
- 采纳前后章节版本、待核项、确认和幂等记录查询结果；
- 当前接入级别、未支持格式/行为和剩余风险。
