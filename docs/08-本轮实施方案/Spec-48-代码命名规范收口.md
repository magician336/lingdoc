## 3. 登记表设计要点

形态照 `scripts/lingdoc_parallel_surfaces.py`：

- **declarative 数据**：文件路径 → 拥有的知识、是否遗留、所属批次。
- **loader 校验**：路径不重叠（同一知识不被两个文件声明）、遗留基线一致、必填字段齐全。
- **非零退出**：坏登记表必须响亮失败，**不得静默降级**——沿用 `test_lingdoc_gate_scripts.py` 的 `KNOWN_SCRIPTS` 做法。

**登记表放在 `scripts/`，守护测试放 `scripts/ci/`。** 原因：`scripts/ci/` 是门禁判定层，必须保持「只有一个模块回答『什么会跑』」。

### 3.1 编号的三种形态与 #361 的覆盖补齐

代码层里「数字」有三种形态，都是缺陷，因为数字说的是「哪批工作」而不是「拥有什么知识」：

| 形态 | 例子 | 依据 |
| --- | --- | --- |
| 项目号 | `g5_policy.go`、`G5Policy` | Spec #48 本体 |
| 任务号 | `verify_t09_test.go`、`t09Call` | `T01`–`T16` 历史任务池；文档层保留，代码层不保留 |
| 段号 | `seg3_context_ports.go` | Spec #47 第三段，与 `G5` 同性质 |

#361 合入后复查发现三处覆盖漏洞，本节记录补齐方式（**登记表与守护测试本身不改形态，只补规则与清单**）：

1. **文件名干净、内部有编号标识符的文件没被登记。** 原规则只判文件名，于是这类文件不破任何规则 → 不进 `NAMED_FILES` → 它的标识符**没有归属票**，没有任何票会改名它们，守护测试也拦不住。
   **补法**：新增 `numbered_identifiers` 缺陷类型——文件体里定义带工作号的标识符，本身就是文件级缺陷。补登记 **25 个文件**（11 个「干净文件名 + 编号标识符」的文件、14 个 `seg3_*` 文件）。
2. **第三套编号「段号」没有规则。** `NUMBERED_NAME` 只覆盖 `g`/`t` 开头，`seg3_` 无人管。
   **补法**：新增 `segment_number` 缺陷类型（路径段**前缀**，与 `numbered` 同口径，目录名同样计入）与 `SEGMENT_NAME`（标识符前缀）。
3. **任务号不在规则里。** 现有 `ticket_number` 只覆盖 `issue<数字>` / `spec<数字>` / `ac<数字>`。
   **补法**：新增 `task_number` 缺陷类型（文件名内任意位置，与 `ticket_number` 同口径）与 `TASK_NUMBER`。

**验收台豁免**：`ACCEPTANCE_RIG_DIRS`（`impactCenterAcceptance/`、`frontend/scripts/`、`scripts/acceptance/`、`scripts/lingdoc_mock/`）里的 `G3*` / `T15*` 是验收台自己的词汇。新规则**不向验收台加债**（`RIG_EXEMPT_RULES`），其既有 `numbered` 条目保持原样。**单元测试文件不豁免**——测试助手是产品词汇，随包一起改名。

**棘轮基线**：本次把「已识别但从未登记」的存量债务一次性计入，基线由 `186/54/205` 上调到 `211/54/205`（文件档 +25；两档标识符计数不变，因为段号与任务号标识符此前已全部登记，只是其宿主文件没进清单）。**上调只此一次**，之后只减不增。

**本轮终值：`0/0/0`。** 八张执行票（#361–#369）落地后重新测量：210 个文件条目全部翻为 `legacy=False`，251 个仍声明的编号标识符全部是验收台词汇（`harness=True`，不计入棘轮）。合并基线时 main 的 Spec-47 新建的 7 个带编号测试文件与 2 个残留编号标识符，按「棘轮只许下降」一并改名收口。
