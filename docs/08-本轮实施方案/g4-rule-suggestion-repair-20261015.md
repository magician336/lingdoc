# G4 规则建议输出契约修复与真实合成验证

模板字段规则建议首次收到真实模型响应后，被严格解析器以 `invalid_model_output` 拒绝。旧输入没有提供具体可选类型，且 system 提示要求输出 basis/version、解析器却拒绝这些额外字段；模板中的五条全局 computed 检查也不能绑定到单个字段。本次让模型获得明确、目标适用的公开规则语法和合法参数示例，移除额外依据字段要求。严格解析、来源范围、权限和非阻断限制均保留。

## 变更与边界

- `rule_suggestion` system 只要求 `proposals/explanation`；版本与权限依据由服务端保存。prompt 标识从 `/1` 升至 `/2`，旧失败记录保留。
- 输入增加当前目标允许使用的公开服务端类型及参数约束；这些是输出语法，不增加传入模板的字段/章节/五条绑定，也不读取其他课题或资料。全局 computed 检查不作为字段候选。未来未定义参数契约的类型继续排除。
- 模型仍不能指定既有 `rule_id`、阻断等级、执行器或未授权来源。异常响应继续失败关闭，未保存原始 completion，没有自动重试或用固定成功样例替代模型。
- 建议区侧栏按内容高度排列；召回信息默认显示影响数量，编号按需展开，不查询额外课题正文/名称。
- Kimi 实测指出 JSON 错误信封不一定是 Error 实例。本次识别实际 `$httpStatus=409` 与 `version_conflict`，明确提示版本变化和重读，网络失败保持独立通用文案。草稿缓存和 CAS 不变。
