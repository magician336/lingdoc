# 第二阶段首版实施计划：持续写作与最小复核闭环

> 保留原文件名以兼容已有链接。本版替代原 G1–G7 全量推进顺序和 M0–M4 首版门槛，不重编号 T01–T16 或 G1–G7。
> 本文决定下一版范围，不宣称已有代码、真实验收或全体成员确认。采用以本次文档 PR 的独立评审和合并为准。
> [差距清点](17-T01-T16与Beta差距清点.md)与[G1–G7 蓝图](beta-gap-development-plans/README.md)继续保留，但不是本期承诺。

## 1. 只交一个可持续使用的结果

目标用户是参与内部试用的课题组写作者，使用一个明确版本的演示模板、两个代表性章节和项目内已授权资料。首版不冒充正式申报合规系统，也不承诺完整 Beta。

**用户能继续写作和恢复编辑，回看依据，比较并采纳 AI 改写；研究条件或来源变化后完成必要复核，再取得真实可编辑文件。**

从已验收的一阶段链路增加体验和复核能力，不重建项目、检索、模型、确认、导出或登录系统。界面可以只有一个工作台；后台对象分开，不等于用户必须填多套表单。

## 2. 与 T01–T16 收尾分工

T01–T16 的收尾主责留给已协调的协作者。本计划不接管其分支，不修改其验收标准，也不把它未完成的接线换一个 G 编号算新增成果。

第二阶段真实接线前，收尾负责人和消费方在现有 PR 留一份简短交接：已验收 main SHA、启动方法、可用接口、两章 F01 与关键失败证据、未验限制。合并数量和旧 CI 不能代替交接。

未取得所需接口时，可以做隔离原型和本切片契约；不得另造第二套业务实现。缺口阻塞哪个切片就回传哪个提供方。真实文件持久化、下载授权或带来源保存等一阶段欠账，不因缩小第二阶段范围而豁免。

## 3. 本期必须 / 触发后再做 / 暂不做

“本期必须”只包括下表的窄切片，不表示对应整条 G 线完成。触发条件只是重新评估的依据，不会自动扩大承诺。

| 能力线 | 本期必须 | 触发后再做 | 本期暂不做 |
|---|---|---|---|
| G1 建项 | 复用一阶段项目、条件、成员及立项入口，交接既有版本语义 | 试用反复出现建项协作或字段来源追踪困难，再引入草稿字段溯源与完整基线流程 | 新建 Owner 生命周期管理、全部草稿迁移界面 |
| G2 依据 | 项目内资料的稳定来源引用、版本、回看与待核提示；人工可补一条用途/限制备注 | 同一依据反复支撑不同结论、现有引用不能表达争议时，再引入 EvidenceCard/ResearchClaim；本地资料确实不足时再评估外部检索 | 通用 Research Agent、多渠道发现平台、要求每段先建主张才能写作 |
| G3 变更 | 研究主题/目标等首批明确字段的变更记录、已登记影响与待复核章节清单；重新确认后继续交付 | 出现多对象传播、多人分派或单表无法表达的真实案例，再扩 ChangeSet/DependencyRegistry/ImpactTask | 通用图谱编辑器、AI 批量建边、RouteNode 平台、通用稳定化引擎 |
| G4 模板规则 | 一个固定、可追溯模板版本，复用确定规则和冻结检查；不私改历史 | 固定模板经实际任务证明确实不足，再做项目副本；确有版本升级场景再做迁移 | 模板市场、完整规则运营、任意规则代码、复杂多模板编辑器 |
| G5 权限 | 复用现有租户/项目/来源授权，每次敏感操作再查，最小操作留痕；缺依赖拒绝 | 实际试用需要新增角色或资源委派时，逐项扩明确能力，不自造全部组合 | 通用 ACL 配置引擎、复杂邀请/转让界面、组织审批平台 |
| G6 质量 | 从第一张 PR 起记录失败、版本、运行模式，复用现有 CI；真实文件与第二人复现 | 稳定试用后再建设集中指标、灰度管理与统计页面 | 新建质量平台、无样本的效果百分比、全量观测字段工程 |
| G7 写作 | 工作副本与可靠自动保存、显式版本提交、单段 AI 差异预览/接受或拒绝、冲突恢复 | 单段改写可用后，根据试用再扩块级编辑、批注、多人审阅 | 实时协同/OT/CRDT、自动跨段合并、全格式富文本、自动写完整申请书 |

权限、来源真实性、并发不覆盖、失败不丢稿和真实文件验证始终保留。优先限制尚无保护的高风险动作，不以“首版”名义先支持再绕过保护。

## 4. 三个连续结果，而不是七组并行大包

| 顺序 | 用户能复现的结果 | 主要参考切片 | 必须一起通过的反例 |
|---|---|---|---|
| 先完成持续写作 | 编辑并恢复工作副本；单段 AI 改写先比较，采纳后再显式保存为新章节版本；沿用一阶段导出 | G7.1/G7.2/G7.4 的最小范围，G6 贯穿 | AI 等待中用户继续编辑、两个窗口同基线保存、响应丢失、撤权、模型失败，均不覆盖或泄露内容 |
| 再完成依据回看 | 在同一工作台选择/复用资料片段，看到来源版本与待核状态，保存后仍能回到依据 | G2.3/G2.6、G7.3 的轻量范围 | 错资料归属、来源消失、重解析变化、授权撤回不能靠旧缓存继续放行 |
| 最后完成最小变更复核 | 修改首批字段，查看已知影响和不确定范围，处理复核并重新确认/导出 | G3.1/G3.3 的有限范围，复用 T12–T14 | 漏登记依赖不能当作无影响；旧版本结果和旧确认不能放行当前交付 |

每一行都是页面、接口、持久化和失败处理的完整切片，可拆小 PR 早交接口，但不能各自用 fake 通过后宣称整行完成。先让第一行可用，再扩大下一行；不要求全部 G1–G5 完成才开始 G7。

G6 不是最后接手修所有问题的团队；功能作者随切片交验证，消费者核对实际调用。已有 CI 与请求层能复用就不另建框架。

## 5. 首批开工卡：先做 G7 持续写作切片

本卡是可领取范围，不是已分配或已完成状态。开工时在现有 Issue/PR 填实际负责人、消费者、独立评审人和剩余投入区间；不预估所有未来 G 线。

| 项目 | 约定 |
|---|---|
| 基线 | 收尾交接的 main SHA；核对项目读取、章节保存、候选、来源校验、确认和导出接口 |
| 用户入口 | 现有 LingDoc 工作台中的一个已立项章节，不另做平行产品页 |
| 复用 | 一阶段 Workspace、Generation/Candidate、SourcePolicy、DOCX/交付服务；具体实现路径按交接 SHA 核对 |
| 增量 | 工作副本恢复和保存状态；一个明确选中段落的 AI 改写、差异预览、接受/拒绝；显式生成新 ChapterVersion |
| 不改 | T01–T16 编号与验收；租户登录、正式模板要求、既有历史版本、导出授权与文件校验 |
| 停止条件 | 所需一阶段接口未交、正文映射无法保留引用/待核项、授权不确定、已有用户编辑可能被覆盖 |
| 交回内容 | 修复/实现 SHA、实际用户路径、成功与反例、PASS/FAIL/NOT RUN/BLOCKED、未覆盖格式；独立复审后再合并 |

首张实现 PR 只冻结这张卡需要的最小接口、成功样例和失败样例，不为未来模板市场、通用图谱或角色引擎预设扩展点。前后端和测试可以多人协作，但指定一个人负责本切片接真。

### 实现前要定下的少量选择

- 正文沿用交接基线的 `body_markdown` 和来源标记；首版只开放真实渲染器已验证的格式，不同时引入结构化块模型。引用和待核项必须往返保留。
- 工作副本可变，ChapterVersion 正文不可变。自动保存只保存带版本的检查点；接受 AI 先改变工作副本，用户显式提交才创建正式版本。恢复历史也创建新版本，不改旧指针冒充新写入。
- 每次 AI 请求固定章节基线、工作副本修订、选区原文/位置、输入来源版本和操作键。返回与接受时分别检查：工作副本已变化则不自动套用，展示冲突/重新生成入口；只比较正式 ChapterVersion 不够。
- 客户端可保留当前会话未提交的自写修改，但本首版不建设持久离线资料缓存。服务端恢复需重新鉴权，退出/撤权后清除受限原文、AI 摘录和可恢复缓存；不能承诺撤回用户已自行保存的外部副本。
- 复用一阶段 `project_version` / `spec_revision`；不把旧值改名成 Context Revision，也不自动给旧项目、来源或确认升级状态。需要新字段时说明默认值、兼容读取与回退，未知仍是未知。

## 6. 最小变更复核的边界

首批变更只覆盖交接契约中的研究主题/目标字段；适用字段清单和关联规则随该切片评审。记录旧值、新值、预期版本、操作人，以及来源引用或生成输入已经明确登记的章节关系。先给可读的章节清单，不先建通用图引擎。

“已知关联”与“尚未核对”分开展示。没有关系记录不能证明不受影响：保留一阶段的保守失效保护，将不确定章节列入人工核对；未核对不能自动恢复确认或放行导出。只有确定无影响且有复核依据的对象才能保留有效性；首版不宣称自动找全影响。

字段写入和复核标记必须有一致的条件写入边界；若不能原子保存，版本不匹配时交付必须保持阻断。普通保存不能代替确认；复核必须绑定当前条件和章节版本。该有限能力不宣称已实现完整 PCC/稳定化。

## 7. 跨文档歧义的首版处理

本期按下列窄规则实现；不重写全部长期设计，也不宣称已完成全套 G1–G7 逻辑审计。详细蓝图的冲突不得由开发者或 Agent 任挑一段作为放行依据。

| 分歧 | 本期规则与后续边界 |
|---|---|
| G2 与完整模拟的“先 Claim 还是先候选卡” | 首版沿用来源引用，不强制新增 Claim/Card；未来采用卡片时按 G2 渐进式规则：候选可暂缺 Claim，确认前必须补齐并同步模拟 |
| G7 将无权资料与待核资料并列 | 无权/授权不确定的正文和摘录不得进入任何 AI 上下文，标记待核不能使其合法；有权但未确认材料只能按明确模式带标记使用，不能伪造已确认证据 |
| G1/G4 的 blocking dismiss 差异 | 本期不新增通用 waive/dismiss 入口；既有处置按一阶段契约执行，权限、缺源、版本失配和无效文件不能人工豁免 |
| G3 稳定化与冻结的循环前置、旧 M 编号不完整 | 首版沿用一阶段冻结/检查/导出顺序和本计划的三条结果，不引入通用稳定化；以后启用完整 G3 时再明确状态顺序及验收覆盖 |
| G7 工作副本与版本创建时机 | 以本计划第 5 节为本切片基准；正文快照不可原地编辑，自动保存与正式提交明确分离 |

内部对象可以分开，用户入口不必分裂。一个“查看/关联依据”入口可以分别保存正确的来源和使用关系；默认展示“已保存、待核、不可用、需重新确认”，具体版本和依据按需展开。

## 8. 何时算首版可试用

三个连续结果在同一已合并 SHA 上，用同一套两章材料跑通；另一个成员能按仓库记录复现。正常保存、重试、冲突、撤权、来源变化、旧候选返回、导出失败的关键断言必须实际执行，失败或缺依赖不能写 PASS。

必须包括真实模型的至少一次选段改写、真实授权来源、服务重启后的工作副本/正式版本读回，以及真实导出文件在 Word/WPS 打开、编辑、保存和重开。Mock/真实 API 假模型用于提前开发，不能替代这些实测；单个真实调用不代表完整链路为 real。

试用记录只保留当前需要的事实：哪些步骤帮助了用户、主动操作时间、额外确认次数、失败和丢稿情况、依据能否回看、哪些变化曾漏处理。先记录个案与计数，不凭一次成功计算效率提升或宣称完整 Beta。发生越权、数据丢失、错误版本交付，先停相关入口修复再复测。

## 9. 延后能力怎样重新进入计划

产品负责人和实际消费者提供一个已遇到的阻塞案例，并回答：现有小实现为什么不够、有没有更小方案、现在不做将来的迁移代价是否不可接受。比较剩余投入与可用时间后，通过小范围计划/契约 PR 选入；不能由 Agent 因“以后可能需要”自动扩展。

本次不新建任务平台、质量平台或全量共同规范。G1–G7 保留为设计资料；首版完成也不等于这些能力线全部完成。回退本次文档变更即可恢复原推进方案，不涉及数据库、接口或业务代码回滚。
