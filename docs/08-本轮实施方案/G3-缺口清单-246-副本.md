### G3-GAP-09 阻断级规则问题「接受不处理」（dismiss）返回 500 的缺陷

- **缺什么**：阻断级规则问题调 disposition 的 `action=dismiss` 曾返回 500 `internal_error`（`resolve` 返回 201、`waive` 返回 400）。**根因已定位并修复**（#253，2026-10-20）；当前缺的是该 HTTP 场景在当前 head 的实跑落证。
- **根因**：授权审计行把「动作 + 资源 ID」的复合 capability 写进了有界的 action 分类列（`lingdoc_project_audits.action`，PostgreSQL `varchar(64)`），阻断级 dismiss 的 action 长 73 字符 → PostgreSQL SQLSTATE 22001 → 事务回滚 → 未映射的原始错误变成 HTTP 500；resolve 的 action 恰好 64 字符压线通过。**SQLite 迁移把该列声明为无界 TEXT，所以缺陷只在 PostgreSQL 暴露。**
- **已实现部分 + 证据文件**：修复为 action 列只写分类（`authorization.issue-dismiss-blocking`，36 字符），完整 capability 留在 `details.capability`；审计写失败改为自带对外形态的领域错误。证据 `docs/08-本轮实施方案/G3-缺口收口-4-验证报告-20261020.json`（#253），已在隔离 PostgreSQL（生产迁移）上复现（修复前 22001）并复验（修复后 201）。
- **当前卡点**：页面实跑落证尚未完成，行 `AC-G3-09` 记 `PASS (follow-up)`。
- **解除条件**：由 #257 之后的验收台重跑该场景落证（阻断级 dismiss 被受理、处置落库、审计行可读）；落证前不得记 `PASS`。
