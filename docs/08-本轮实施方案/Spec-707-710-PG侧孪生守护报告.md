**领域不变量与事务边界**
- 期望侧唯一出处不变：gorm 自己的解析器（`schema.Parse`）；
- 产物侧唯一出处不变：真实迁移链执行产物——PG 侧为 versioned 链在隔离演练 schema 的产物，经 `information_schema.columns` 读取（不加 `table_schema` 过滤会读到演练 schema 之外的杂物，`search_path` 首位即演练 schema，表全部落在其内）；
- 判定规则唯一出处不变：全部集中在 `row_shape_guard_test.go`（本票只做方言分档，不新增第二处判定语义）；类型比对方言分档 = PG 侧同族直比（#709 裁定表 + 风险①）；
- 登记完整性：清单 47 条原样复用，`runRowShapeGuardAgainst` 的身份断言（PkgPath/TypeName/TableName ↔ gorm 解析结果）对两个方言同样生效；
- 隔离与清理：演练 schema 带前缀、测试结束整块 DROP（既有助手行为），不碰用户库；守护纯只读，不写任何业务数据；
- skip 语义：无 DSN 显式 skip 且文案注明「跳过不是通过」；验收矩阵该行按 `NOT RUN` 口径记录，由 CI integration job 真实运行兜底——skip 从不计为通过。

**成功 / 失败 / 恢复场景**
- 成功：47 清单在真实 versioned 链上逐列零违规（绿样本）；同族直比钉扎绿；
- 失败：① 声明 `not null` 值字段 ↔ 实际可空列（#693 形态）→ 红；② 指针字段（无 `not null`）↔ 实际 NOT NULL 列 → 红；③ 类型不同族 → 红（PG 侧整数声明借不了 SQLite 等价的道）；④ 声明 `size` ↔ 产物侧长度不一致 → 红（PG 暴露 `character_maximum_length`，规则 4 在此真正生效）；⑤ 链未建到 000135 → 前置断言红（红夹具语义失效即红，不会静默通过）；
- 恢复：修漂移侧（结构体 / 迁移 / 归一化档），失败信息带表名 / 列名 / 两侧具体形状。

**持久化 / 并发 / 审计证据**

- 并发：N/A（纯只读守护；每个测试自建隔离演练 schema，互不干扰）；

**当前风险与未决决策**
- 风险 1：本地无 WSL2 内 docker daemon / 无 sudo——本地 PG 用 Windows Docker Desktop 起一次性 postgres:17（与 CI 同镜像、同凭据），WSL2 经 localhost 连接（镜像网络模式已验证）。若不可用则 PG 真实运行为 NOT RUN（原因：无本地 PG），CI 兜底——按实际情况在矩阵登记，不写成本地 PASS。
- 风险 2：规则 4（长度）在 PG 侧首次真正执行——若真实链存在声明 `size` 与 `varchar(n)` 长度漂移，按裁定程序处理（误报扩规则 / 真漂移按领域语义裁定），不允许降级为仅报告；结果记入裁定表。
- 风险 3：`information_schema` 侧 `data_type` 档（`postgresColumnTypeFamily`）首跑可能暴露未覆盖类型——按规则 3 棘轮：扩档，绝不静默接受；结果记入裁定表。
- 风险 4：Windows 宿主机 cgo/gojieba init 崩溃（环境限制，继承 #708/#709 登记；`internal/database` 同样触发）——全部 Go 证据经 WSL2 Ubuntu（go1.26.0 = CI 版本）产出，CI 为权威复核。
