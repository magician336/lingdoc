# 灵档术语表（Glossary）

> **后续设计参考**：本文保留完整产品方案；本轮范围见[实施方案](../08-本轮实施方案/01-范围与任务流程.md)，领取以[任务池](../TEAM_DEVELOPMENT_TASKS.md)为准。A/B/C 仅指领域，不分配人员。完整 PCC、复杂权限等不自动成为本轮前置条件。

## 使用规则

本表是 LingDoc 产品、研发、测试、答辩和对外沟通使用的统一词汇基线。术语首次出现时应使用中文全称，必要时在括号中给出英文/代码名；后续保持同一含义，避免以“版本”“知识库”“工作区”等泛词混称不同对象。

本文定义的是目标产品语言，并不表示所有对象已由当前 WeKnora 实现。

## 1. 产品与领域

| 术语 | 英文/代码名 | 定义 | 不应混同为 |
|---|---|---|---|
| 灵档 | LingDoc | 面向科研项目申报的证据驱动协作工作台。 | 单纯的基金文本生成器。 |
| Beta | Beta | 路线图 P4 交付的首个对外版本，其能力范围即本文档集描述的完整设计。 | 当前已实现的功能；Beta 之后的生产增强（P5）。 |
| 科研项目 | `Project` | LingDoc 的核心业务单元，包含成员、研究条件、项目资料、内容、模板和交付记录。实现文件可称 `research_project`。 | WeKnora tenant、workspace 或 knowledge base。 |
| 建项 | Project Establishment | 项目从创建记录到立项确认的整段过程，含可选的草稿阶段。 | 一次填完即结束的表单。 |
| 草稿阶段 | Draft Phase | 项目已创建（`draft`、`Context Revision 0`）但尚未立项的协作阶段：可停留、可邀请成员、可上传资料、可受控检索，但不产生章节、`ChangeSet` 或 `EvidenceCard`。 | 用户最后一次保存的任意编辑状态；可直接当作正式项目基线的状态。 |
| 立项确认 | Baseline Confirmation | `Owner` 对草稿期研究条件的确认动作；通过后生成章节骨架与 `Context Revision 1`，项目转为 `active`。 | 一次普通的项目语义变更；可由成员代行的操作。 |
| 项目工作台 | Workspace | 用户围绕一个科研项目组织资料、任务、章节、确认和交付的产品界面。 | 仅指文件夹或聊天会话。 |
| 研究条件 | `ProjectSpec` | 项目的研究对象、目标、方法、变量、资源与约束等结构化事实，按模板必要字段逐项带状态与溯源；草稿期是待确认的草拟值，立项确认后成为正式基线。 | 一段不受版本控制的自由提示词。 |
| 主张 | `ResearchClaim` | 申报书中需要来源、人工判断或明确待核状态支撑的关键论断。 | 一般段落、资料标题或模型回答。 |
| 章节 | `Chapter` | 与模板章节对应的协作内容单元，可有负责人、版本、批注和确认。 | 整个项目的一次全量文本。 |
| 技术路线图 | `RouteNode` / Route | 由研究步骤、依赖和难点预案组成的可编辑交付图形。 | 自动生成后无需维护的图片。 |
| 调研智能体 | Research Agent | 围绕用户新想法制定检索计划、调用已批准学术来源与联网发现层、整理来源候选并发起知识导入的 Agent。 | 仅作被动的搜索框；自动替用户确认文献或修改正式章节的 Agent。 |

## 2. 证据与知识

| 术语 | 英文/代码名 | 定义 | 不应混同为 |
|---|---|---|---|
| 项目资料 | `ProjectAsset` | 经授权关联到项目的 WeKnora 资料、外部来源或对话摘录及其处理谱系。 | 自动可跨项目共享的知识。 |
| 来源锚点 | `SourceAnchor` | 能回到材料中具体页、段、表、图或字符区间的位置描述；应支持重定位和失效检测。 | WeKnora 的裸 `chunk_id`。 |
| 证据卡 | `EvidenceCard` | 面向用户展示的证据载体，含原文定位、摘要、支持范围、限制、关联 ResearchClaim 与待核项。内部可保留支持关系字段。 | 由模型自动判定为真理的结论。 |
| 候选证据 | `EvidenceCandidate` | 检索或模型推荐的潜在资料/片段，尚未被人确认适用于某主张。 | 已确认的 EvidenceCard。 |
| 学术来源 | `AcademicSource` | 经机构目录批准的论文、政策或其他外部资料的来源元数据和可核验地址。 | 未批准的任意网页或搜索结果摘要本身。 |
| 发现层 | Discovery Layer | 复用 WeKnora `web_search` / `web_fetch` 的联网检索通道，用于判断“值不值得去读原文”；其搜索摘要没有可重定位的原文位置，因此不能直接支撑证据。 | 正式证据来源；可被引用的文献原文。 |
| 层级标记 | Tier Marking | 导入时对材料标注的可用层级：可作为候选证据 / 可作为背景线索 / 仅作发现入口。它决定材料**能否支撑证据**，不决定能否被导入；未标记时默认最低层，显式升级须留审计。 | 资料的处理状态（`PENDING`/`PROCESSING`/`READY`）；不可推翻的最终判定。 |
| 对话片段 | `ConversationExcerpt` | 从 AI 多轮会话中由用户选择导入的消息/轮次范围，保留作者、模型、工具和来源信息。 | 自动等同于研究事实的整段对话。 |
| 导入候选 | `ImportCandidate` | 用户尚未确认进入项目资料范围的学术来源、文献片段或对话片段。 | 已进入正式项目资料范围的 ProjectAsset。 |
| Source Truth | 来源真相 | A Evidence 域拥有的 ProjectAsset、锚点、EvidenceCard 与其有效性事实。 | 项目正文或交付是否放行的最终判定。 |
| 知识能力底座 | WeKnora | LingDoc 所复用的文档处理、检索、引用、Agent 和流式交互能力。 | LingDoc 的项目业务真相源。 |
| 知识库 | Knowledge Base | WeKnora 中可检索的资料集合；对 LingDoc 而言是受控能力范围。 | 一个科研项目。 |

## 3. 版本、变更与确认

| 术语 | 英文/代码名 | 定义 | 不应混同为 |
|---|---|---|---|
| 关联变更协调机制 | PCC, Project Change Coordinator | 记录实质修改、解析影响、路由领域任务、跟踪处置并让项目回到稳定状态的运行机制。 | 第四个可任意修改 A/B/C 的业务域或超级 Agent。 |
| 变更集 | `ChangeSet` | 对项目的拟议实质修改；先评估，再由负责人决定应用。 | 用户每一次无意义的编辑操作。 |
| 语义差异 | Semantic Delta | 从 ChangeSet 中识别出的研究对象、目标、方法、变量等项目事实变化。 | 纯排版差异。 |
| 上下文修订 | `ContextRevision` | 每次已应用的实质项目语义变化产生的单调递增全局序号。 | 材料、章节或模板自己的版本号。 |
| 资料修订 | `AssetRevision` | ProjectAsset 原始资料或其解析结果的版本/谱系。 | 项目语义变化。 |
| 资料范围修订 | `asset_scope_revision` | 某次任务实际允许使用的 ProjectAsset 集合版本；新资料加入有效范围时递增。 | 资料本身的解析版本或项目语义 Revision。 |
| 章节/主张版本 | `ChapterVersion` / `ResearchClaimVersion` | 章节或主张文本的版本，用于差异、恢复和确认绑定；`ContentVersion` 仅作兼容统称。 | 项目全局 Revision。 |
| 模板版本 | `TemplateVersion` | 申报类别/年度对应的结构和规则版本。 | 导出文件本身。 |
| 依赖图 | `DependencyRegistry` / `DependencyEdge` | 显式记录项目条件、材料、证据、主张、章节、路线图和交付项之间“谁依赖谁”的关系。 | 把所有原文复制进一张大表。 |
| 影响任务 | `ImpactTask` | 因 ChangeSet 产生、分派给 A/B/C 或人工处理的最小可追踪动作。 | 泛泛的提醒消息。 |
| 局部失效 | Invalidation | 仅使受影响对象进入待校验/待复核状态，而非重新运行整个项目。 | 自动删除旧内容或全量重写。 |
| 稳定基线 | Stable Baseline | 当前 Revision 的阻断影响已关闭、结果未陈旧且状态可作为后续操作基线的项目状态。 | 用户最后一次保存的任意编辑草稿（与「草稿阶段」的项目状态是两回事）。 |
| 确认 | `Confirmation` | 某用户对特定对象、特定版本和核查范围作出的明确确认记录。 | 对整个项目永久有效的批准。 |
| 确认失效 | `INVALIDATE_CONFIRMATION` | 实质变更使既有确认不再适用于当前版本；必须重新核查。 | 删除历史确认记录。 |
| 项目真相 | Project Truth | B Workspace 域拥有的 ProjectSpec、主张、章节、ChangeSet、确认与稳定状态。 | A 的来源事实或 C 的交付规则。 |

## 4. 交付与质量

| 术语 | 英文/代码名 | 定义 | 不应混同为 |
|---|---|---|
| 模板档案 | `TemplateProfile` | 按申报类别和年度版本化的章节结构、必要字段、可计算规则和适用范围。 | 一套永远适用的通用格式。 |
| 模板检查 | Template Check | 对**项目当前内容**执行的模板、格式与一致性检查，不需要先有 `ReleaseSnapshot`，写作过程中随时可跑；结果只落在 UI，不改变交付状态。 | 交付预检；对某个快照的放行判定。 |
| 预检 | Preflight | 在导出前对指定 ReleaseSnapshot 执行的格式、一致性、确认和交付规则检查。 | 对论证质量或学术价值的自动最终裁决。 |
| 校验问题 | `ValidationIssue` | 模板检查或预检发现的问题，含规则、**判定方**、严重度、目标对象和处理状态；可被修复、关闭、豁免或判定为误报删除。判定方 `computed` 表示由规则求值、`model` 表示由模型判定，两者进入同一问题清单、接受同一套处置。 | 必然正确的模型判断。 |
| 豁免 | Waiver | 责任人确认某条**警告/提示级**问题真实存在但本次接受，记录负责人、理由与风险清单后放行；**不适用于阻断级问题**。 | 判定规则误报；修复问题。 |
| 误报删除 | Dismiss | 责任人判定某条问题是规则或模型的误判、本不该存在，把它从问题清单中移除；适用于任一严重度（含阻断级）与任一判定方，须填理由并进审计，且只对当前规则与目标版本生效。 | 豁免；关闭已修复的问题。 |
| 阻断交付 | `BLOCK_RELEASE` | 存在未处置的高严重度问题，正式导出不可放行。 | 不能保存草稿或查看历史文件。 |
| 交付快照 | `ReleaseSnapshot` | 一次导出所固定的 Context Revision、章节版本集合、模板版本、确认汇总和预检结果。 | 当前项目的可变实时状态。 |
| 导出产物 | `ExportArtifact` | 由 ReleaseSnapshot 生成的可编辑文件及其校验、时间和审计记录。 | 交付快照本身。 |
| 交付真相 | Delivery Truth | C Delivery 域拥有的模板、模板检查、预检、交付快照、导出和放行状态。 | 项目内容的修改权。 |
| 交付损失 | Export Loss | 导出后关键数值、表格、图形、引用、分页或可编辑性发生的不一致。 | 主观上“不好看”。 |

## 5. 接口、任务与状态

| 术语 | 英文/代码名 | 定义 | 不应混同为 |
|---|---|---|
| 命令 | Command | 请求某个拥有者执行业务动作的消息，例如 `ApplyChangeSet`。 | 已经发生的事实。 |
| 事件 | Event | 已经发生且不可逆的领域事实，例如 `evidence.revalidated.v1`。 | 可以被任意消费者修改的指令。 |
| Outbox / Inbox | Outbox / Inbox | 可靠投递与幂等消费的记录机制，避免数据库提交与消息投递不一致。 | 仅用于临时缓存的队列。 |
| 关联 ID | `correlation_id` | 将同一用户操作/业务流程的命令、任务和事件关联起来的标识。 | 事件的唯一 ID。 |
| 因果 ID | `causation_id` | 指向触发当前事件的命令、事件或 ChangeSet 的标识。 | 项目 ID。 |
| 幂等键 | `idempotency_key` | 使重复提交/投递不会重复产生副作用的稳定键。 | Revision 号码。 |
| 基于修订 | `based_on_revision` | 异步结果读取项目上下文时所依据的 Context Revision。 | 结果写入时自动等于最新 Revision。 |
| 陈旧 | `STALE` | 结果返回时所依据 Revision 已落后于当前项目，不能覆盖最新状态。 | 任务失败或内容无价值。 |
| 上下文快照 | `ProjectContextSnapshot` | 对外提供的只读项目引用与状态汇总，用于跨域消费或审计。 | 复制全部材料和章节正文的统一数据库。 |
| 上下文装配器 | Context Assembler | 依据任务、权限和 Revision 生成最小 AI 上下文切片的组件。 | 把整个知识库无差别塞给模型。 |

## 6. 状态速查

| 状态 | 适用对象 | 用户可理解的含义 |
|---|---|---|
| `draft` | 项目 | 已创建记录、尚未立项；`Context Revision` 为 `0`，没有章节，不产生 `EvidenceCard`。 |
| `active` | 项目 | 已完成立项确认，可正常协作、变更与交付。 |
| `archived` | 项目 | 已归档，只读保留。注意：**丢弃**未立项的草稿不是归档，它写的是软删除标记 `discarded_at`。 |
| `PENDING` / `PROCESSING` / `READY` / `FAILED` / `REPLACED` | 项目资料 | 从上传、异步解析到可被检索引用的处理状态；与「层级标记」正交——前者说“处理到哪一步”，后者说“能否支撑证据”。 |
| `DRAFT` / `PENDING_CONFIRMATION` / `CONFIRMED` / `SUPERSEDED` | 研究条件（`ProjectSpec`） | 逐字段的状态：草稿值、AI 填入待人工确认、已确认进入项目基线、被更晚 revision 取代。AI 填入的值默认 `PENDING_CONFIRMATION`。它与字段的**来源**（人工填写 / AI 填写 / AI 填写后人工改动）是两个正交维度，不可合并。 |
| `CANDIDATE` | 证据卡 | 系统/用户提出候选，尚未确认可用。 |
| `NEEDS_REVIEW` | 证据卡 | 曾有确认或曾可用，因其依赖的对象（资料、研究条件、主张）发生变化而需要重新核查；是确认失效在证据卡上的落点。 |
| `CONFIRMED` | 证据卡 | 人已确认该证据卡的支持范围与限制描述准确，可作为章节的已确认依据。 |
| `INSUFFICIENT` | 证据卡 | 当前资料不足以支持该主张，不应补造。 |
| `STALE` | 证据卡 | 针对该证据卡的校验/检索结果返回时依据的 Revision 已落后，不能覆盖当前状态。 |
| `REVIEW_REQUIRED` | 内容 | 发生变化或发现问题，需要指定人员复核，复核前不得进入确认或交付。它同时是 B 域一个影响动作的名字（见 [`02-领域架构与PCC`](02-领域架构与PCC.md) 第 6 节），该动作正是把内容推进到这个状态的手段。 |
| `OPEN` | 校验问题 | 模板检查或预检已发现、尚未处置的问题。 |
| `RESOLVED` | 影响任务/校验问题 | 该影响或问题已处置完成，不再阻断稳定化与导出。 |
| `DISMISSED` | 校验问题 | 已被判定为误报（规则误判或模型误判）并删除，不再计入交付阻断；只对当前规则与目标版本生效。 |
| `AI_DRAFT` | 内容 | 由模型基于指定资料生成的候选文字，尚未经人编辑或确认。 |
| `HUMAN_EDITED` | 内容 | 人已改写过、但尚未确认的版本。 |
| `HUMAN_CONFIRMED` | 内容 | 人已对该对象的特定版本和范围确认。 |
| `SUPERSEDED` | 内容 | 已被更晚版本取代，保留历史。 |
| `DRAFT` | ChangeSet | 还未应用到正式项目状态的修改设想。 |
| `ASSESSED` | ChangeSet | 已完成影响评估，尚未应用到正式项目状态。 |
| `APPLIED` | ChangeSet | 已产生新的 Context Revision，正在处理影响。 |
| `REJECTED` | ChangeSet | 负责人决定不应用该变更设想，项目保持原 Revision。 |
| `STABILIZED` | ChangeSet/Revision | 关联阻断影响已完成处理，形成新基线。 |
| `NOT_READY` | 交付 | 立项确认后的初始状态：项目已成立，但尚未形成可交付的确认集合。（草稿项目没有交付对象，不属于本状态的适用对象。） |
| `PREFLIGHT_RUNNING` | 交付 | 正在检查指定交付快照。 |
| `BLOCKED` | 交付 | 存在不能忽略的问题，不能正式放行。 |
| `READY` | 交付 | 指定快照通过当前规则，可由负责人请求导出。 |
| `EXPORTED` | 交付 | 已按指定快照生成导出产物；快照不可变，后续变化会产生新的快照。 |
| `UPDATED` | 路线图节点 | 节点已按当前项目语义更新，与正文重新一致。 |

## 7. 权限与治理

| 术语 | 英文/代码名 | 定义 | 不应混同为 |
|---|---|---|---|
| 租户角色 | `TenantRole` | WeKnora 中用户在租户内的 Owner/Admin/Contributor/Viewer 身份，是所有 LingDoc 项目权限的上限和前置条件。 | 项目角色。 |
| 治理角色 | `GovernanceRole` | 项目身份轴，`Owner` / `Admin` / `Member` 三者必选其一，决定治理权与权限上限。`Owner` 是权限顶点，能力为全集且不携带职能轴。 | 职能角色；租户角色。 |
| 职能角色 | `FunctionRole` | 项目能力轴，`Author` / `Researcher` / `Reviewer` / `Observer`，可多选叠加并附带 scope；治理角色为 `Owner` 时不参与此轴。 | 单一数字等级；治理角色。 |
| 项目角色 | `ProjectRole` | 治理角色与职能角色的合称；原 Owner/Editor/Researcher/Reviewer/Viewer 是它的五种预设组合。 | 跨项目的组织管理员身份。 |
| 能力 | `Capability` | 对某项操作的明确许可，如 `content.edit`、`evidence.confirm` 或 `delivery.export`。 | 单一数字等级；不同角色可拥有非线性能力组合。 |
| 有效权限 | `EffectivePermission` | 租户身份、项目能力、资源共享级别和凭证 scope 相交后的最终允许结果。 | 前端是否显示按钮。 |
| 知识库共享角色 | `OrgMemberRole` | WeKnora 对共享知识库提供的 Admin/Editor/Viewer 级别。 | 项目成员资格或项目确认权。 |
| 资源范围 | `Scope` | 能力适用的具体对象范围。职能 scope 限定章节、材料集合或交付版本，且只约束写操作；**未指派时为空集**（并非全集，`Owner` 除外），所以“先给角色、后给范围”不会意外放权；知识库与 Agent 的范围由 WeKnora 的共享级别和凭证 scope 决定。 | 通过一个全局角色获得所有资源。 |
| 人工确认 | `HumanConfirmation` | 具备相应项目能力的用户对特定版本、对象和范围做出的确认。 | 模型生成、搜索命中或 API 成功响应。 |
| 默认拒绝 | Fail Closed | 身份、成员关系、资源分享或能力检查出错时，系统拒绝操作而不是放行。 | “暂时跳过权限检查”。 |
| 部分授权 | Partial Authorization | 一次请求的资料集合中只有一部分被授权、就绪或存在。**必须显式区分允许集与拒绝集**：不得把“返回无错误”当作全部授权成功，也不得静默地只处理允许的子集并报告成功。拒绝集须逐项带原因（未授权 / 未就绪 / 不存在 / 跨项目）。 | 全部授权成功；合法的权限过滤结果；只有允许集、没有拒绝记录的返回。 |
| 受限服务调用 | `ScopedServiceCall` | 带有明确项目和资源 scope 的 API Key/服务身份调用。 | 拥有系统管理员权限的通用机器人。 |
