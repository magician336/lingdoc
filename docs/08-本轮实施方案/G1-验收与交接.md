## HTTP 入口

草稿模板迁移支持：

- `GET /projects/:projectId/template-migration/preview?template_id=...&template_version=...`
- `POST /projects/:projectId/template-migration/preview`
- `POST /projects/:projectId/template-migration`（需要 `Idempotency-Key`）

生命周期入口：

- `POST /projects/:projectId/owner-transfer`
- `POST /projects/:projectId/owner-transfer/:transferId/accept`
- `POST /projects/:projectId/activate`
- `POST /projects/:projectId/discard`
- `POST /projects/:projectId/restore`

所有写请求都带 `Idempotency-Key`。版本冲突、非 Owner 确认、discard 后写入和必填字段缺失必须读回确认：项目状态、版本、章节数量和审计事件没有半完成副作用。

## 交接给 G2–G6 的事实

- G1 草稿字段使用 `SpecFields` 保存 `origin`、`status`、`provenance`、修改者和时间；AI 值默认保持 `pending_confirmation`。
- `project_version`、`spec_revision`、`current_context_revision` 是三个独立版本语义；active 后普通 `SaveSpec` 被拒绝。
- 模板迁移保留原始 `spec` 值；`orphaned` 只表示目标模板不再识别，不代表静默删除。
- active 只由当前 Owner 发起，成功时同一事务写入 active、Context Revision 1、章节骨架和审计。
- discard 是 draft 的软状态；列表隐藏，恢复仍回到 draft，丢弃期间所有写入口拒绝。
- Provenance 标记为不可访问时，读模型把字段/候选标记为 `needs_review`；真实来源系统的撤权事件接入仍需由来源域提供。
