# 写作工作台交互优化 · design-note（workbench-ux-refinement-20261012-01）

> 出具：Kimi·LingDoc 专职分支（Kimi Work）。基线：#111 冻结头 `1091758`（含 #106、#109 补丁、三栏接线、全部修复）。范围只限 `frontend/` 与本轮 docs；不改后端/接口/确认语义。

## 1. 布局取舍：一个开关对，一键专注

- **单一"目录"开关**（顶栏，文字标签 + aria-pressed）：宽屏收/展左栏，窄屏开/关左栏浮层；移除 rail 内旧的"收起目录"按钮与含混图标，保留窄屏浮层内的 × 作为同能力第二出口（Codex r3 修复，不撤）。
- **新增"辅助"开关**（顶栏）：收/展右栏检查器；收起只改可见性，组件常驻不销毁（v-show 语义），不丢候选/来源展开态。
- **专注**沿用研究/专注切换：只隐藏 rail 附加区与检查器，**不改 railOpen/inspOpen**，退出专注恢复进入前布局（布局偏好仅存布局，不存业务）。
- 1440 写作态正文实际宽度 = 1440−232(rail)−344(辅助) ≈ 864 ≥ 640 目标；rail 收起后 ≈ 1096。≤1279 辅助按需浮出（既有），≤899 目录转浮层（既有），1260/125%/150% 不缩字体硬塞三栏（既有）。

## 2. 待核：表单 → 人工审阅卡片（契约不变）

- **状态模型**：`未处理`（理由空）/ `已处理·已解决`（resolved+理由）/ `已处理·保留提醒`（retained_warning+理由）。只用既有 `resolved/retained_warning + reason` 两个值，**不提交任何新状态**；存储键仍为 `${chapter.id}:${item.id}`（稳定 id，非数组索引）。
- **交互**：手风琴卡片，一次展开一项，顶部"已处理 M/N"+细进度条；"上一项/下一项"导航；正文始终可见（右栏）。
- **动作措辞**：「我已核查并解决」（附注：人工确认该问题不再影响交付，不代表模型判定事实真伪）/「保留提醒」（附注：承认问题存在、本次接受，随版本保留）。未选择或理由为空 → 该项不算已处理，确认阻断照旧（`confirmationReasons` 未改）。
- **反馈**：已处理用中性灰徽章（不用大面积绿框，不制造"已证实"假象）；理由 maxlength 2000 保留；局部编辑态/已保存决策/确认有效性分开展示（"已记录，随章节确认生效"）。
- 抽纯函数 `reviewItemStatus/reviewProgress`（reviewPanel.ts）+ 单测；卡片内仍 v-model 绑既有 `reviewDrafts`，#109 未保存守卫与慢响应语义不受影响。

## 3. 项目选择：当前项目 + 切换弹层

- 左栏主角为**章节目录**；项目区压缩为：当前项目 chip（名称+草稿/已立项真实状态）+「切换项目」按钮。
- 弹层内含：搜索框（**只对已加载列表**本地过滤，不发 API）、过滤列表、底部保留创建表单（草稿建项入口不丢）。状态：加载中（既有 loading）、空（还没有项目）、无匹配（'没有匹配的项目'）、错误（既有 errorMessage）。
- 折叠/展开 rail 不触发 API 重取或重选第一项（组件常驻）；切项目仍走原守卫（confirm/慢响应身份检查）。

## 不做什么

不改后端/数据库/接口/授权/确认语义；不新增编辑器/富文本/资料选择器/模型验真/自动批准；不动旧 T12、治理文件、凭证、旧证据、5195/18084；不推送/合并/部署；不调用模型。
