# Kimi 最新前端 · 本地链路试用

2026-11-03，设计基线 `LD-V1-20261103-R1`，本地组件 `review-chain-0.2.0`。前端来自 gong 本次提供的 `LingDoc-LD-V1前端源码与交接.zip`，保留项目概览、原生写作、审阅与交付三空间；冻结交接包 7 个文件哈希与场景引用通过。

## 实际试用

入口：<http://127.0.0.1:7210/>，同项目别名 <http://localhost:7210/>。由独立后台 Node 进程承载 Go、解析器和 DS；不是只有当前聊天存在的临时承诺。数据在本目录 `runtime/trial/`。`Start-LocalTrial.ps1` 可在进程停止后继续打开原数据；`Stop-LocalTrial.ps1` 仅请求本实例退出。不要删除运行目录来重新开始。

1. 点“继续写作”。左侧读社区联系记录，右侧查看导师意见；中间是真实 WordCraft，原生菜单、格式和撤销保留。
2. 可在正文框选文字，再点“绑定当前原生选区”；也可展开“录入或修改人工意见”。选择“修改正文”并保存决定，直接在正文中修改，再点原生区域“保存”。填写实际处理说明，点“关联已保存版本并登记完成”。这几步是独立动作。
3. 点左侧“登记资料更新并生成回看”。资料从四社区到两社区，同时保留 v1；审阅页面会出现样本、进度和图表三条明确关系形成的回看项，正文不会自动变更。
4. 给回看项选择修改、暂缓或填写理由确认无需调整。正文修改仍需保存版本；图源和研究方案版本未接通，不能用正文保存冒充它们已处理。刷新或重开后检查记录；可导出真实 DOCX 副本。

“资料”和“意见与助手”独立收起；“专注写作”释放正文空间。原生宿主首次进入写作时初始化，之后切换页面不卸载。全文、选区和撤销记录不由 React 演示稿覆盖。页面刷新后原生锚点保留旧摘录，但需要用户重新定位；不会把新宿主中相同数字的 documentId/revision 当成旧锚点有效。

## 已接通与保留边界

- DOCX：继续使用既有 WordCraft → DS → Go/SQLite → 读回 → ack 保存链。
- 资料：真实 Go 上传、解析、资产绑定和原文读取。本批登记联系记录 v1/v2；连续关系是本地扩展显式记录，不冒称原有 Go 资产自动替换。
- 人工意见和变化回看：同源本地服务在 `review-chain.json` 原子持久化，带修订校验、幂等键、历史和实际保存版本。本对象是新增合同，不是旧 Go ImpactTask 的状态重命名。
- 完成表示用户确认，并有相应保存凭据或无需修改的理由；系统不宣称已经判断语义正确。
- AI 回复、研究方案版本、图源编辑仍为明确标出的演示。任意 DOCX 导入、多份资料的任意多版管理、精确锚点跨编辑自动重定位尚未完成。下载副本不等于正式申报冻结交付。
