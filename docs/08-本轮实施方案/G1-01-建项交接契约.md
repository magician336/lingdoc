# G1-01 建项交接契约

> 本文记录 `main` 当前可复用的建项入口和已验证边界。它是 G1 后续实现的交接基线，不把长期 G1 设计当成现有运行时能力。

## 当前入口

在已认证的 `/api/v1/lingdoc` 路由组下，当前提供：

| 方法 | 路径 | 当前行为 |
|---|---|---|
| POST | `/projects` | 以幂等键创建 `draft` 项目，`project_version=1`、`spec_revision=0`，创建者成为唯一 `owner` |
| GET | `/projects` | 只列出当前租户中有项目成员关系的项目 |
| GET | `/projects/:projectId` | 读取项目、条件版本、模板版本和成员；非成员返回统一不可见结果 |
| PUT | `/projects/:projectId/spec` | 按 `expected_spec_revision` 条件保存字段；成功递增 `spec_revision` 和 `project_version` |
| PUT | `/projects/:projectId/members` | Owner 按 `expected_project_version` 替换协作者集合；只接受租户 active 成员 |
| POST | `/projects/:projectId/activate` | Owner 按条件版本确认 draft；检查模板必要字段并生成章节骨架 |
| GET | `/projects/:projectId/chapters` | 读取当前章节和正文版本，并重新检查来源授权 |
| GET | `/projects/:projectId/access-status` | 返回项目资料访问状态，不返回未授权正文或标题 |

所有写请求都要求长度 8–128 的 `Idempotency-Key`。相同操作键和相同请求体会读回第一次结果；相同操作键对应不同请求体返回冲突。预期版本不匹配返回 `409 version_conflict`，不会覆盖已有写入。

## 已验证的状态和边界

- 当前项目持久状态只有 `draft`、`active`；数据库约束禁止其它状态。
- `draft` 创建时没有章节；`activate` 在同一事务中递增项目版本并插入模板章节骨架。
- 条件保存使用 `spec_revision`；当前代码尚未独立持久化 `current_context_revision`。
- active 项目仍可通过现有普通条件保存入口写入；G1-02 将把这个入口改为拒绝并引导 ChangeSet。
- 当前成员模型只有 `owner` 与 `collaborator`，没有待接受转让、章节 scope 或 `owner_unavailable`。
- 当前字段模型是 `map[string]string`，没有字段来源、字段状态或 ProvenanceRecord。
- 当前模板读取器提供固定演示模板；草稿换模板、字段迁移和模板副本尚未提供入口。
- 当前项目没有 draft 丢弃/恢复字段，也没有候选池与字段溯源关联。

## G1 实现约束

后续切片应复用 `Service` 的领域入口和 `Transaction` 的原子事务边界。新增字段应兼容读取已有行；新写入必须保留现有幂等、版本冲突和非成员不可见语义。任何新接口都必须在写入前重新执行租户成员、项目角色和资源授权检查。

## 验证方式

当前基线由 `internal/lingdoc/workspace` 与 `internal/lingdoc/workspacecore` 的 HTTP、SQLite/PostgreSQL 持久化和服务测试覆盖。G1 后续报告应引用具体测试命令和场景结果；未运行的真实服务、真实资料和独立复现步骤必须标记为 `NOT RUN` 或 `BLOCKED`。
