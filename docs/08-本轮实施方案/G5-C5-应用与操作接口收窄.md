# G5-C5：应用与操作接口收窄

## 本轮边界

本切片只收敛 Workspace 的应用依赖和内部 operation 描述，不新增路由、UI、数据表或权限能力。HTTP 响应仍由 `workspace.Handler` 映射，WorkspaceCore 继续保存现有幂等、重放、版本冲突、来源复核和错误语义。

## 应用端口

`workspace.Handler` 的路由依赖按现有用例组拆为：

- `ProjectApplication`：项目列表/读取、草稿候选、审计、激活差异和项目生命周期；
- `MembershipApplication`：成员保存与 Owner 生命周期；
- `ChapterApplication`：章节、工作副本、版本和重写；
- `TemplateApplication`：模板迁移、预览和项目模板副本；
- `ChangeSetApplication`：变更集创建、读取、应用和拒绝。

`HandlerDependencies.Service`、`Read` 和 `Write` 仅保留为兼容输入。`NewHandler` 在旧调用方仍传入 `ApplicationService` 时构造一次显式 `legacyApplicationAdapter`，Handler 内部只保存 focused ports；新组合根应直接注入 `Projects`、`Members`、`Chapters`、`TemplateApp` 和 `ChangeSets`。

### 剩余消费者与删除条件

| 兼容入口 | 当前消费者 | 删除条件 |
| --- | --- | --- |
| `HandlerDependencies.Service` | 旧 HTTP/测试装配和外部构造方 | 所有装配改为五组 focused ports，且路由/契约测试不再构造 `Service` 字段 |
| `HandlerDependencies.Read` / `Write` | 旧 HTTP/测试装配 | 同上；保留到全部调用方迁移，避免一次性破坏历史测试 seam |
| `ApplicationService` | `SelectedRewriteService`、`SourceRuntime`、`accessPolicy` 及旧 stub | 这些消费者各自改用最小读取/授权端口，并完成跨模块契约测试 |

## Operation 描述

WorkspaceCore 的 runner 现在接收内部 `operationDescriptor[I]`：操作名使用受控 `operationName`，输入保留具体泛型类型，来源敏感操作携带对应的类型化来源解码器。持久化仍使用原有字符串 operation identity，保证旧记录可重放；HTTP 状态码和响应 envelope 仍不进入应用端口。
