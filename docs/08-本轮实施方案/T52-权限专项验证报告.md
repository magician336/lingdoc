## 当前环境限制

- 原生 Windows 的 `go test ./internal/container -run TestLingDocWorkspaceCompositionSharesApplicationAndSourceRuntime -count=1` 仍可能在编译阶段被本机 cgo 工具链阻断：`sqlite-vec-go-bindings` 需要 GCC/UCRT 能找到 `sqlite3.h`。当前已用 WSL2 安装 `libsqlite3-dev` 完成等价全量验证；若要求原生 Windows 全绿，应安装匹配 UCRT 的 MinGW/MSYS2 SQLite 开发头文件与库，并确保 `CGO_ENABLED=1`、`CGO_CFLAGS`、`CGO_LDFLAGS` 使用同一套工具链。
- 原生 Windows 未连接 Docker Desktop daemon，因此未执行真实 `npipe` Engine 集成测试；仅完成跨平台校验逻辑和本机无 daemon 的 sandbox 单元测试。配置 `DOCKER_INTEGRATION_HOST=npipe:////./pipe/docker_engine` 并启动 Docker Desktop 后，再运行 Docker 集成测试。
- Windows 上 POSIX `/bin/sh` bootstrap 测试按平台跳过；同一 shell 语义已在 WSL2 全量测试中执行并通过。
- 没有配置 `LINGDOC_TEST_POSTGRES_DSN` 时，PostgreSQL 合同测试按约定跳过，不计为通过。
