## 3. 登记表设计要点

形态照 `scripts/lingdoc_parallel_surfaces.py`：

- **declarative 数据**：文件路径 → 拥有的知识、是否遗留、所属批次。
- **loader 校验**：路径不重叠（同一知识不被两个文件声明）、遗留基线一致、必填字段齐全。
- **非零退出**：坏登记表必须响亮失败，**不得静默降级**——沿用 `test_lingdoc_gate_scripts.py` 的 `KNOWN_SCRIPTS` 做法。

**登记表放在 `scripts/`，守护测试放 `scripts/ci/`。** 原因：`scripts/ci/` 是门禁判定层，必须保持「只有一个模块回答『什么会跑』」。

## 4. 证据约定

- 每个批次一个 PR，PR body 引用**当前 head** 的命令与结果。
- 验证证据落 `docs/08-本轮实施方案/T48-验证报告.json` 与 `T48-S*-证据.json`。
- **不贴进 issue**，不在 PR body 里贴大段日志。
- 改名 PR 必须声明**对外契约零变化**，并附契约校验与路由检查的结果。
