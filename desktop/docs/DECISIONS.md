# LingDoc 首版 v2 决策基线

本文件记录已经与 gong 逐点对齐的首版范围。各工作包不得自行扩大范围或重新引入已退出机制。设计稿与本文件冲突时，在 Kimi 完成复审并由 gong 确认新决定前，以本文件为准。

## 1. 项目与正文

- 使用普通目录和一份主 DOCX，不引入 WorkingCopy。
- 不做旧数据兼容或迁移；旧目录暂不删除，但也不进入首版运行链。
- DOCX 是正文权威，不增加另一份正文真值源。
- 不引入 `project.json`。主 DOCX 采用项目根目录的严格唯一规则：只检查根目录、不递归，恰好一份正文 DOCX 才允许打开；零份或多份均明确拒绝并列出原因，绝不取第一个。
- 识别时排除 Word 的 `~$` 临时文件和应用自己维护的一份滚动备份；不得擅自排除其他 DOCX，也不把其他文档静默当成资料。
- 不做六章导航、章节投影、复核冻结、审批链或章节级候选工作流；默认停用的六章旧壳和旧 Delivery 遗留已获准在核对调用方后清理。

## 2. 资料

- 资料由用户手动导入，产品目标支持 TXT、Markdown、DOCX、PDF、PPT；当前原生实现与目标不一致时必须在界面和验收中如实标明。
- 项目问答的默认范围是当前主 DOCX＋全部已导入、可读取的项目资料，不再要求每次提问前勾选，也不设 4 份上限。项目范围不等于把任意未登记文件或应用锁、备份、会话元数据当作资料。
- “默认整个项目”是读取授权范围，不是无条件把所有全文塞入模型。内容较少时可携带全文；超出输入预算时，由原生应用按标题、章节、段落和相关性选择片段，并显示本次实际使用的资料。
- 首版不引入 embedding、FTS5、索引监听或 Python 提取器；先用可测试的确定性原生管线验证效果，再决定是否需要更复杂的检索。
- 保留现有内置资料阅读器、多阅读组和并排阅读；这是一项已确认保留能力，不再按“资料只能交系统默认应用打开”清理。
- 打开项目或导入资料时不为 AI 预建问答上下文；内置阅读器仍可按需解析用于显示，AI 仅在用户发送明确问题或选区任务时读取已授权内容。

## 3. AI 输入与能力

首版主要有**改写＋问答**两个能力，二者都可以结合项目资料。

- 改写必须选中正文；问答必须有用户明确提出的问题。
- 选区 AI 的处理对象永远只有用户圈选内容；当前主 DOCX 默认作为只读上下文，用于术语、指代和文风消歧，不得因此扩大处理对象或改写未选中正文。超长时由应用明确降级为当前章节与邻近段落。
- 选区改写需要附加项目资料时，仍由用户在当次配置中显式勾选；项目问答则默认使用整个项目范围，两者不混用规则。
- 保留多条问答会话的新建、切换和可见记录；记录随项目本地保存并可跨启动恢复，但不写入主 DOCX，也不构成另一份正文真值源。
- 当前会话中界面可见的问答文字可作为后续问题上下文；资料预算与历史预算分开，优先保留近期完整问答轮次，不截断半轮。切换会话后只使用新当前会话的记录。
- DSH 固定版本源码仅作为历史压力判断、裁剪与压缩的参考；首版不引入 DSH／Node／Go 运行时，不在未验证需要前增加摘要调用。
- 选区 AI 保留五类操作：解释、总结、翻译、润色、改写；它们在“改写”下如何归组由后续前端信息架构决定，不在本决策中删除。
- Rust 原生桌面直连 DeepSeek，不经过旧 DS／Go 宿主。
- AI 必须有用户明确提供的输入；只有本节明确授权的主文档与项目资料可以进入上下文，不以隐藏上下文扩大范围。
- 指定 URL 和按任务明确允许的联网搜索保留，默认关闭；结果浮层展示本次网页引用。
- 文件、URL、联网搜索和流式协议以 DSR-02 对官方资料的核查为准，不根据旧代理实现猜测。
- 无明确输入时不生成。

## 4. 选区与结果浮层

- 在编辑器内提供选区 AI 工具条和就近结果浮层，不做系统级悬浮窗。
- 浮层保留原选文与只读结果，只提供复制、固定、关闭。
- 不提供自动采纳、候选编辑、正文替换、diff、候选历史或复核审批。
- 生成期间可以继续编辑。点击操作时冻结原选文；之后选区变化不取消任务、不使结果失效，只控制未固定浮层的显示。迟到响应按 taskId 归属，不得覆盖新任务；文档切换仍须隔离旧文档任务。
- 不为选区 AI 增加正文哈希、正文 revision 或当前选区相等性门禁。任务身份和必要的文档身份足够，不能叠加重复检查。
- “固定”表示跨选区保留且不再跟随选区定位；固定不是历史收藏。发起新任务时仍替换同一个浮层，不增加第二槽位或候选历史；pin 属于当前结果，新任务替换后复位为未固定。
- 未固定浮层在选区变化后收起；后台任务继续，完成后不自动重开。关闭浮层也不取消任务，结果不得自动重开浮层。
- 允许跨段落选区，只要输入来自用户明确选择；保留 4000 Unicode 字符上限，超出时拒绝并提示，不静默截断，不增加单段检查。旧合同的单段措辞由 Kimi 在集成时同步修订。

## 5. 保存与恢复

- 保留最新 DOCX 和一份滚动备份；备份固定为主 DOCX 同目录的 `<主文件名>.bak`（例如 `申请书.docx.bak`），不保留历史副本，详见 ADR 0001 C7。
- Recovery 独立保存，不等同于用户保存，也不直接覆盖主 DOCX。
- 用户退出时明确选择“不保存”后，主 DOCX 保持不变、saved revision 不前进，但对应 Recovery 副本保留；下次启动在恢复页提示，不自动恢复或覆盖正文。T12 必须按此语义编写。
- 保存期间允许继续编辑；按实际落盘的 saved revision 确认，后续编辑仍保持未保存状态。
- 保存采用单在途操作；活动操作或 Unknown 未解决时拒绝新提交，不建立携带过期磁盘基线的保存队列。
- 保存结果未知时查询原 saveId，不盲目重试、不重复轮换备份。
- 保留外部磁盘修改保护，不能用保存操作覆盖外部已变化文件。
- 磁盘内容身份只用于保存边界的外部修改和落盘核验，不扩散为 UI 哈希、候选哈希或正文 revision 门禁。
- 第二实例直接禁止打开项目，不退化为只读模式；项目锁固定为 `<root>/.lingdoc.lock`，使用 OS 排他建议锁，详见 ADR 0001 C10。
- 首版直接拒绝加密主 DOCX，不进入项目编辑或密码试用流程；避免 Recovery 因密码存在而静默停写。以后支持时另行设计保存与恢复验证。
- 项目绑定期间直接拒绝 `file.rename`，提示先关闭项目再到系统文件管理器重命名；首版不重写 binding，也不引入主 DOCX、备份与锁路径的重命名事务。
- 项目绑定期间不得让旧空闲 AutoSave 或其他旁路绕过保存协调直接覆盖主 DOCX。
- 原子替换、Recovery 和现有测试能复用就复用，不重写已经可靠的机制。

## 6. 外部应用与运行时

- 保存后的 DOCX 可由系统默认应用打开，不做 Word 深度集成或 COM 自动化。
- 正文、项目保存和选区 AI 的主链不启动或依赖 DS、Go、Node、Python、ACP、DSH、旧 WASM 宿主。AI 绘图是最新明确保留的例外：只有用户主动打开旧版完整绘图工作台＋next.ai 时才按需启动其 Node 服务，关闭后释放；不据此恢复其他旧宿主。Word 上游 Draw／墨迹不是 AI 绘图的替代入口，项目默认界面不展示该页签；独立 Word 编辑器的底层墨迹能力不因此删除。
- 共享 UI 中旧宿主的可选保存、另存和交付分支，在逐一核对调用方后清除当前原生无用的死分支；仍被其他目标使用的共享接口保留，不整批删除旧 Web 或历史目录。
- 旧目录本轮不删除；先形成可验证的原生闭环，再决定物理清理。
- 不因首版脱离旧宿主而顺带删除打印、独立 Word 编辑器的上游墨迹等无关能力；保留底层能力不等于允许它进入 LingDoc 项目默认界面或替代 next.ai。

## 7. 明确退出的旧概念

首版不重新引入以下概念：

- WorkingCopy、旧数据迁移和旧运行链兼容；
- 自动索引监听、未经边界控制的项目外读取，以及不显示实际范围的全文隐式注入；
- 六章投影、章节级 AI 候选、复核冻结、审批和证据链；
- 自动采纳、diff、候选历史；
- 选区 AI 的正文哈希和 revision 门禁；
- 第二实例只读放行；
- 依赖 DS／Go／Node／Python／WASM 宿主的启动前提。
