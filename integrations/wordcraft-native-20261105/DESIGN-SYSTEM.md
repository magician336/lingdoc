## 0. 产品概念模型

LingDoc 是**单一项目、单一主文稿**的 AI 辅助学术写作工具。界面由三个域构成，视觉升级必须同时服务三者：

| 域 | 形态来源 | 组成 | 核心契约 |
|---|---|---|---|
| **创作域**（正文） | Word 肌肉记忆 | 功能区 ribbon、页签、标尺、页画布、状态栏、Backstage | 正文是唯一持久编辑会话；保存态只来自真实回执 |
| **资料域**（Sources） | VS Code 形态 | 资源树侧栏、只读阅读标签页、分组/分屏（`ReaderGroup`）、跳转回退 | 资料永不替换正文；只读；分屏是显式动作 |
| **智能域**（AI） | AI 原生 | 会话面板、显式上下文（可见、可移除）、出处引用、会话历史 | 无自动建议、无自动写入；上下文与出处必须可见 |

## 1. 设计原则

1. **正文主权**：任何视觉引导都把视线最终交还给页画布；资料与 AI 是「侧翼」，不是主角。
2. **熟悉优先**：创作域布局遵循 Word 的空间记忆（快捷访问栏、页签在功能区之上、状态栏在底部）；资料域遵循 VS Code 的空间记忆（侧栏、标签、分屏）。
3. **显式优于自动**：不设计任何"AI 主动出现"的入口形态；AI 能力以用户动作触发，状态与出处始终可见。
4. **状态诚实**：保存中/已保存/失败、上下文超预算、原文不可核验等状态有独立的视觉语言，不被装饰性元素稀释。
5. **克制动效**：动效只用于反馈与过渡，尊重系统"减弱动态效果"（挂接 `a11y.rs`）；编辑画布区域保持静止。

## 2. 设计令牌

### 2.1 品牌色（蓝白方向）

以明亮蓝为产品主色，沿用引擎既有 `APP_COLOR #0064E6` 族并补全色阶（`theme.rs` 的 `APP_COLOR`/`APP_INK` 即 600/700，保持不动）。

| 令牌 | 值 | 用途 |
|---|---|---|
| `brand/50` | `#E8F0FC` | 选中底色、弱强调面 |
| `brand/100` | `#D8E5F9` | 悬停底色 |
| `brand/300` | `#8FB3EC` | 边框强调、图表辅色 |
| `brand/500` | `#4A7FDB` | 次强调 |
| `brand/600` | `#0064E6` | **主品牌色**：主按钮、活动页签、焦点环 |
| `brand/700` | `#0756B8` | 主按钮悬停、深强调文字 |
| 深色主题 | `#7A93F0` / `#9CB0F5` | 深色下提升明度的 accent 与 accent 文字/悬停 |

### 2.2 中性色（暖灰，配纸面）

| 令牌 | 浅色主题 | 深色主题 | 用途 |
|---|---|---|---|
| `neutral/0` | `#FFFFFF` | `#1B1F1D` | 页画布、卡片 |
| `neutral/50` | `#F6F7F5` | `#222725` | 应用底色 |
| `neutral/100` | `#EFF1EE` | `#2A2F2C` | 功能区、面板底 |
| `neutral/200` | `#E3E7E3` | `#353B38` | 分隔线 |
| `neutral/300` | `#CBD2CC` | `#454D46` | 强分隔线、输入框边 |
| `neutral/500` | `#8A938E` | `#9AA39D` | 次要文字 |
| `neutral/700` | `#5A625D` | `#C3CBC5` | 正文文字（UI） |
| `neutral/900` | `#1F2321` | `#EDF0ED` | 标题文字 |

### 2.3 语义色（独立于品牌色）

| 令牌 | 浅色 | 用途 |
|---|---|---|
| `success` | `#2E8B57` | 已保存、已确认、核查通过 |
| `warning` | `#B07A2A` | 保存中、上下文接近预算 |
| `danger` | `#C44B3F` | 保存失败、阻断、删除 |
| `info` | `#3E6FA8` | 只读提示、出处链接 |

### 2.4 字阶与字体

- UI 字体：Inter（已内嵌）+ 系统中文字体（`theme.rs` 现有 CJK 接入机制保持不变）；等宽用 JetBrains Mono（已内嵌，用于版本号、SHA、代码）。
- 字阶（pt）：`10.5` 辅助 / `12` 正文 UI / `13` 强调 UI / `15` 小节标题 / `17` 面板标题 / `20` 页标题 / `24` Backstage 标题。
- 行高：UI 文字 1.5；说明文字 1.65。
- 文档正文字体不属于 UI 令牌，由文档自身决定。

### 2.5 间距、圆角、描边

- 间距：4pt 网格，令牌 `{4, 8, 12, 16, 24, 32}`；组件内边距默认 8/12，区块间距 16/24。
- 圆角：`2`（小控件）/ `4`（按钮、输入）/ `6`（卡片、标签页）/ `8`（面板）/ `12`（对话框）。
- 描边：常规 1pt `neutral/200`；强调 1pt `brand/300`；焦点环 2pt `brand/600`，外扩 2pt。
- 分层：浮层用 1pt 描边 + 柔和投影（对话框、上下文菜单、toast）；不用多重深阴影。

### 2.6 动效令牌

| 令牌 | 时长 | 缓动 | 用途 | egui 对应 |
|---|---|---|---|---|
| `motion/fast` | 120ms | ease-out | 悬停、按下、焦点 | `ctx.animate_bool` |
| `motion/base` | 180ms | ease-in-out | 面板开合、显隐 | `ctx.animate_bool` |
| `motion/slow` | 240–300ms | ease-in-out | 页签指示条、对话框进出场 | `ctx.animate_value` |
| `motion/pulse` | 1400ms 循环 | ease-in-out | 保存中 / AI 生成中 | `ctx.animate_value` + 重绘请求 |

边界：编辑画布、标尺、页内容不动画；`prefers-reduced-motion` 时全部瞬时完成。

### 2.7 图标规范（`icons.rs` 管线）

- 网格：20×20，内容区留白 3–3.5；端点吸附半格（x.0 / x.5）。
- 笔画：统一 1.5（现状 1.25，在功能区 20px 下偏虚）；圆头、圆转角。
- 双色纪律：主色 `icon`（中性 900 阶）承担轮廓；强调色只用于"动作部件"（箭头、加号、勾、高亮块），一个图标至多一处强调。
- 文字图标（B/I/U 等）用 UI 字体的 600/400 字重，不做手写体。
- 允许的最小管线扩展（低风险的 `Pen` 原语）：圆角矩形半径参数、圆弧（`undo` 已有手绘先例）、独立线帽。不引入外部图标字体或 SVG 资产。
- **文件格式图标例外条款（v1.1，二期决策）**：文件/资料列表中的格式图标遵循 OS 约定分格式着色——PDF 红 `#C4483C`、DOCX 蓝 `#2B579A`、TXT/MD 灰（`text_dim`）；白底 + 折角 + 底部格式字母。功能图标仍坚持双色纪律，文件图标是唯一例外（用户凭 OS 肌肉记忆识别格式）。

## 3. 与现有 `theme::Tokens` 的关系

现有 `Tokens`（theme.rs）约 40 个字段，已经是良好的种子。策略是**扩展而非重写**：

- 保留全部现有字段与名称（`canvas`/`panel`/`ribbon`/`tab_strip`/`accent`/`hover`/`checked` 等），仅把取值迁移到 §2 的色阶；
- 新增字段仅补缺口：`accent_hover`（brand/700）、`focus_ring`、`success`/`warning`/`danger`/`info` 语义组；
- 间距/圆角/动效以 `pub const` 常量模块落在 `theme.rs`（`pub mod space` / `pub mod radius` / `pub mod motion`），不改 `Tokens` 结构体签名以外的任何调用约定，避免波及 60+ 调用文件。
