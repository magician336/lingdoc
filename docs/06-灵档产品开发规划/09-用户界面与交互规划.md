# 用户界面与交互规划

> **后续设计参考**：本文保留完整产品方案；本轮范围见[实施方案](../08-本轮实施方案/01-范围与任务流程.md)，领取以[任务池](../TEAM_DEVELOPMENT_TASKS.md)为准。A/B/C 仅指领域，不分配人员。完整 PCC、复杂权限等不自动成为本轮前置条件。

## 1. 设计总原则

灵档的 UI 不应把用户带入“配置 AI 参数”的复杂后台，而应围绕一个科研项目提供连续工作流：**项目状态、资料依据、待处理问题、版本差异和下一步动作**始终可见。

交互遵循四条规则：

1. **先显示范围再生成**：每次问答、生成或检查前，用户能看到项目、章节、资料和版本范围。
2. **建议与正式内容分层**：AI 草稿、候选证据和规则提示不能伪装成已确认事实。
3. **变更先预览后应用**：研究条件变化通过 ChangeSet 展示影响，用户确认后才进入正式状态。
4. **任何自动过程都能暂停、接管、重试或追溯**：失败不以空白页面结束，陈旧结果不覆盖新状态。

## 2. 整体信息架构

```text
登录/加入空间
└── 工作空间
    ├── 项目列表（含草稿项目，仅成员可见）
    ├── [草稿阶段] 研究条件 / 资料与调研 / 成员
    └── [立项后] 项目总览
        ├── 研究条件
        ├── 资料与证据
        ├── 章节与协作
        ├── 变更与影响
        ├── 技术路线
        ├── 预检与交付
        └── 项目设置/成员/审计

全局入口：搜索、通知、任务、帮助、个人/空间切换
```

草稿阶段的导航**不显示**章节、变更、技术路线与交付入口——它们不是被禁用，而是此时没有对象可作用（见 [`07-建项阶段设计`](07-建项阶段设计.md) 第 7 节）。在草稿期显示灰按钮会让用户以为是自己权限不够。

RuoYi 或其他 root 管理台不出现在普通研究者的主导航中；它只提供组织、模板、用量、审计和支持入口。

## 3. 全局壳层与通用交互

### 3.1 顶栏

```text
[空间/项目切换] [全局搜索] [待办 3] [任务运行中 1] [帮助] [用户菜单]
```

- 项目切换器显示项目名、申报类别、当前 Context Revision 和交付状态。
- 任务图标打开统一任务抽屉：解析、检索、生成、预检均显示进度、取消、重试和失败原因。
- 通知分为“需要我处理”“状态变化”“系统消息”，避免把普通运行日志当成待办。

### 3.2 状态徽章

所有状态徽章可点击打开解释弹窗，至少显示：状态含义、触发原因、基于的版本、责任人和下一步。

```text
[AI 草稿] [待复核] [证据不足] [已确认 v4]
[影响 3] [交付阻断] [可导出]
```

## 4. 项目总览：用户的首页

项目首页不是数据大屏，而是“当前项目是否能继续推进”的工作台。

```text
项目名称 / 申报类型 / Context Revision 2
------------------------------------------------
当前阶段：章节复核       交付：BLOCKED

[继续上次工作] [查看影响 3] [创建变更] [运行预检]

研究条件摘要 | 证据覆盖 | 章节进度 | 未解决问题 | 最近活动
```

首页卡片：

- **研究条件卡**：对象、目标、方法、变量、资源；点击进入结构化编辑，不在首页直接静默修改。
- **证据覆盖卡**：已确认/待核/证据不足的主张数量，可跳转过滤后的证据列表。
- **章节进度卡**：草稿、人工编辑、待复核、已确认的章节状态。
- **影响卡**：按阻断、需要负责人、普通待办排序；展示“为什么受影响”。
- **交付卡**：当前快照、模板版本、预检通过/阻断原因、最近导出。

## 5. 建项向导：四步表单，但可以停在中间

本节的界面流程对应 [`07-建项阶段设计`](07-建项阶段设计.md)；产物、不变量与完成判据以该文为准。

```text
① 创建记录  →  ② 草稿阶段（可停留、可邀请成员）  →  ③ 立项确认
```

向导是一次四步表单，但**可以停在半途**（通常是选完模板、草拟出研究条件之后）：一次走完即直接立项确认，也可以停在草稿阶段去聊、去检索、去上传，之后再回来。因此草稿阶段不是一组新增页面，而是“向导可停留”这件事本身。每一步都支持离开与返回，未保存内容不静默丢失。

### Step 1：申报类别与模板

选择申报类别、年度和模板版本。右侧显示模板覆盖范围与尚未支持的部分。

模板选定后即确定研究条件的**字段集**（模板的必要字段）与立项确认时要生成的章节骨架。草稿期换模板是自由的：同名字段按名保留，原模板独有的字段标为“模板不再需要”（可见状态而非删除），新模板需要的字段标为待填——**不得因换模板清空已填字段**，那可能连带抹掉用户选择过的溯源。

### Step 2：研究条件

用结构化字段填写模板要求的必要字段（当前这一类模板为研究对象、目标、方法、变量、资源和限制，别的申报类别未必相同）。每个字段支持：保存草稿、标记待确认、查看变更历史。

**AI 填写**：用户选择一段或多段会话的轮次范围作为上下文，AI 按模板必要字段生成候选值，直接落入对应字段，默认为**待确认**。每个 AI 产出的值都带溯源（会话、轮次范围、采用片段），可回看。填写与质疑是两条独立通道——系统填完之后，仍必须对它**自己填出的值**提出问题（样本边界不够具体、测量方式未说明、缺样本量依据等）。

### Step 3：成员与权限

邀请成员，为每人选择一个**治理角色**（Admin / Member）和一组**职能角色**（Author / Researcher / Reviewer / Observer，可多选）；资料与交付版本 scope 单独确认。五种预设组合（课题负责人 / 章节负责人 / 研究助理 / 评审人 / 观察者）作为一键选项放在最前——其中「课题负责人」即 `Owner`，由建项产生、不在本步授予，只能经转让变更。预设之外的组合可自由表达，例如科研秘书 = `Admin + Author`，不新增第六种核心项目角色。

**草稿期即可邀请，且一经接受立即生效**——真实的实验室从草稿阶段就开始协作，而不是等立项之后。两处与前不同的地方：

- 草稿期授予的是**不带章节 scope** 的角色；**章节 scope 在立项确认之后**补充，因为章节那时才生成。在此之前该成员的章节写权为空（待指派），这是默认拒绝的直接应用。
- 创建记录时若指定了负责人，系统自动发起一次所有权转让，受让人确认后原子生效（见 [`07-建项阶段设计`](07-建项阶段设计.md) 第 3.2 节）。同一界面同时确定**创建者自己的职能角色**，避免他在转让后只剩只读。

### Step 4：资料范围

选择已有资料库、创建项目资料范围或稍后上传。

### 立项确认

四步完成后进入立项确认页。该页**必须显示两类差异**：

```text
自你上次查看以来，被他人修改的字段：
  研究对象      李老师 → 王同学（3 天前）
  核心变量      + 家庭资源（王同学，2 天前）

仍是 AI 填写、未经人工改动的字段：
  拟用方法      会话 S-12 第 12—18 轮（3 天前）      [查看溯源]
```

负责人确认后生成章节骨架 Ch1–ChN 与 `Context Revision 1`，项目进入 `status = active`、交付状态 `NOT_READY`。草稿期没有 `ChangeSet`，因此**确认页是唯一的可见性关口**，不能省略；否则“别人改了研究对象、负责人没看见就点了确认”会成为默认路径。第二类差异防的是另一半：模型填出、全程无人看过的字段会被整体确认顺带冻结进基线——它不阻止确认（负责人的确认本身就是人工闸门），但必须被看见，且溯源随值进入基线（见 [`07-建项阶段设计`](07-建项阶段设计.md) 第 5.2 节）。

## 6. 资料与证据工作台

### 6.1 资料列表

采用“列表 + 详情抽屉”而不是把所有解析字段铺在表格里。

```text
[上传材料] [新建文本] [筛选状态] [权限] [标签]

文件名       类型   处理状态       权限       操作
前期论文.pdf  PDF   READY          项目内     查看/证据/重解析
问卷摘要.docx DOCX  PROCESSING     项目内     查看任务
```

处理中的资料显示阶段进度：上传、解析、分块、向量化、后处理；失败时显示可理解的原因与重试按钮。

### 6.2 原文预览与证据侧栏

点击“查看证据”进入双栏界面：

```text
左：原文预览（页码/段落/表格定位）
右：EvidenceCard 详情
    [关联主张]
    支持范围 / 限制 / 反驳说明
    状态：候选/待复核/已确认/不足
    [确认] [标记不足] [创建补充任务]
```

用户选择原文片段后，系统生成 `SourceAnchor` 草稿；用户必须确认“它支持的具体主张”和适用范围，不能只点击“引用”就成为确认依据。

### 6.3 证据过滤视图

提供按章节、主张、状态、来源类型、权限和 Context Revision 过滤；支持“只看当前章节未解决证据”。

## 7. 研究助手：对话与任务卡结合

### 7.1 对话工作区

```text
左：项目/章节上下文
中：对话与流式过程
右：引用、工具步骤、待确认项
底部：输入框 + 资料范围 + 输出目标 + [生成]
```

输入框上方固定显示：

```text
当前项目：数字平台课题
当前章节：国内外研究现状
使用资料：M-01、M-03、E-01/E-02
基于版本：Context Revision 1
```

### 7.2 任务卡

不让用户只写一段自由提示词。任务卡字段包括：目标、输入资料、输出格式、字数、不可改变的观点、证据要求和是否允许结构改写。

生成结果提供：

- 接受为新草稿版本；
- 局部插入章节；
- 重新生成选中段落；
- 查看引用和待核问题；
- 对比生成前后差异；
- 标记“不能采用”的理由。

### 7.3 流式运行控制

WeKnora 已有的流式会话和工具运行模式可复用，但 UI 要增加 LingDoc 语义：暂停、停止、继续、重试、基于旧版本的提示、工具调用详情和结果是否可进入正式内容。

## 8. 章节协作编辑器

采用“编辑器 + 证据面板 + 任务面板”的三栏布局。

```text
左：章节树/负责人/状态
中：富文本或 Markdown 编辑区
右：证据、评论、影响、版本
```

核心操作：

- 选中文字 → “关联主张/证据”；
- 点击引用标记 → 打开原文锚点；
- AI 建议以差异块显示，不能直接覆盖人工文本；
- 每次保存生成可恢复的 `ChapterVersion`；
- 提交复核后锁定本次确认范围；
- 其他人编辑时显示占用、冲突和合并预览。

右侧面板必须区分：

```text
证据问题：这句话缺少直接依据
影响问题：研究对象变更后需要复核
格式问题：标题层级不符合模板
协作任务：等待李老师确认
```

## 9. 变更与影响中心

### 9.1 创建 ChangeSet

从首页的“创建变更”、研究条件字段旁的“修改”或章节中的“应用到项目”进入变更向导：

```text
1. 描述想法/修改
2. 结构化确认改变了什么
3. 查看影响预览
4. 选择模拟评估或正式应用
5. 负责人确认应用
```

### 9.2 影响预览

用影响图 + 清单同时呈现：

```text
研究对象
  ├─ 主张 C-02       重新核验证据
  ├─ Chapter 4       必须复核
  ├─ Route R-03      重新生成
  └─ Release RS-01   暂停放行
```

每一项提供“为什么受影响”“基于哪条依赖”“建议动作”和“负责人”。用户可以接受、忽略（必须填写理由）、转派或打开对象详情。

### 9.3 版本时间线

```text
Revision 1 稳定 ── CS-01 应用 ── Revision 2 处理中 ── Revision 2 稳定
                         │
                [证据重检] [章节复核] [路线图检查]
```

旧版本只读可比较；陈旧任务明确标记，不能通过普通“保存”覆盖当前版本。

## 10. 技术路线图与模板检查

### 10.1 路线图编辑器

左侧显示研究步骤和依赖，中央为可编辑图，右侧显示节点来源、关联章节、变量和待解决影响。正文改变后，相关节点出现“可能过期”徽章。

用户可以拖拽/编辑节点，但系统应提示这会影响哪些章节和预期成果；路线图变更进入普通内容版本或 ChangeSet，不能绕过项目状态。

### 10.2 模板检查面板

模板检查跑的是**项目当前内容**，不需要先做快照——作者在写作过程中随时能知道模板必要字段还缺哪些、术语是否走样、哪条论断只有背景证据，不必等到交付前才发现。它与交付前的预检共用同一套规则、同一套严重度和同一套处置方式，区别只在求值对象：模板检查对当前内容，预检对一次具体的 `ReleaseSnapshot`（见 12.2）。同一条规则会在两级各产生一条问题；在一级删除它，另一级只要目标对象版本未变就不再报出。

采用“问题清单 + 定位 + 建议动作”：

```text
[阻断] Chapter 4 缺少样本范围
[警告] 研究目标与预期成果术语不一致
[提示] 该论断只有背景证据
```

可计算格式问题支持“一键修复预览”；论证和证据问题只能给出建议，必须人工接受或关闭并填写理由。

每一条问题（含阻断级）都可以被标记为“误报并删除”——判断由规则和模型给出（判定方为 `computed` 或 `model`），会出错，用户必须能推翻它。删除须填写理由，删除阻断级问题须由 `Owner` 或 `Reviewer` 复核判定。豁免是另一回事：只有警告与提示级问题可以豁免，阻断项不存在豁免（见 12.2、[`08-权限设计与复用WeKnora`](08-权限设计与复用WeKnora.md) 第 3.3 节）。

## 11. 复核与确认中心

负责人进入复核中心后看到按优先级排序的队列：证据不足、确认失效、版本冲突、阻断交付、普通建议。

单项复核采用四区：

```text
当前内容 | 原始依据 | 变更差异 | 决策
```

决策按钮统一为：

```text
[确认] [修改后确认] [退回] [标记不足] [转派] [忽略并说明理由]
```

确认必须绑定对象、版本、核查范围、人员、时间和理由；不能只保存一个无范围的“已审核”布尔值。

## 12. 预检与交付中心

### 12.1 发布快照

点击“准备交付”时，系统先生成 `ReleaseSnapshot` 预览：模板版本、Context Revision、章节版本、证据汇总、确认汇总和未解决问题。预览阶段快照仍可随内容变化重建；阻断问题关闭、负责人请求导出时，才固定为不可变快照。

### 12.2 预检结果

预检对的是**这一份快照**：它把模板检查的规则在冻结的版本集合上重跑一遍，再叠加只有快照才有意义的交付规则（导出完整性、文件可打开性、关键表格与分页保真），因此它是导出放行的唯一依据。按阻断/警告/提示分组，支持点击定位到章节、证据或路线图。只有阻断问题全部关闭或已判定为误报删除、且快照未陈旧，按钮才变为“请求导出”；阻断问题不接受豁免，只有警告与提示可在记录理由后豁免。每条问题都可“误报并删除”，删除后不再计入该分组；删除绑定规则与目标版本，目标对象换版本后问题会在下次预检重新出现，不会变成永久静音。

### 12.3 导出确认

导出前弹出最终确认：

```text
本次文件基于 Revision 2、Template v1、6 个章节版本
未确认项：0
阻断问题：0（阻断项不可豁免）
误报删除：1（李老师，规则 R-07，理由……）
警告/提示豁免：1（李老师，理由……）

[返回修改] [确认并导出]
```

导出后显示文件、校验状态、哈希、版本和恢复入口；用户可重新打开文件或创建“导出损失”问题。

## 13. 成员、权限与管理界面

管理面分两层（租户归 WeKnora、项目归 LingDoc），在 UI 上结合为一个入口；分工与状态联动机制见 `08-权限设计与复用WeKnora.md` 第 8 节。

- **项目成员页**：一张表同时显示租户角色（只读，点击跳转 WeKnora Settings）、治理角色、职能角色、章节责任、资料范围、有效能力和最近操作；租户侧导致的失效状态在此直接呈现，不静默隐藏。
- **邀请弹窗**：按对方状态分支——已在租户的直接授权到项目；已注册但不在租户的，同一次操作内完成租户邀请与项目授权（需租户管理权，否则生成待办并说明需谁协助）；未注册的先引导注册。
- **资料权限页**：项目内/团队共享/仅本人/禁止外部模型；撤销权限需显示受影响证据和章节。
- **任务中心**：按负责人、截止时间、阻断程度和 Revision 过滤。
- **审计页**：确认、导出、权限变更、模型调用和管理员操作；默认不展示研究原文。租户级操作（成员增删、角色变更）在此聚合显示其对项目的影响，但原始记录仍归 WeKnora。
- **管理台**：模板发布、规则版本、配额、来源配置、租户治理，不直接写项目内容。

## 15. 一次用户旅程的页面跳转

```text
项目总览
  → 研究条件（负责人确认）
  → 资料与证据（上传/定位/关联）
  → 章节编辑器（生成候选/人工修改）
  → 变更中心（ChangeSet/影响预览）
  → 复核中心（确认/退回/转派）
  → 路线图与模板检查
  → 交付中心（快照/预检/导出）
```

任何跳转返回项目首页时，都保留当前项目、章节和 Revision 上下文；若用户离开时有未保存编辑、运行中任务或未处理阻断项，必须提示而不是静默丢失。

## 16. UI 验收标准

1. 用户能在 30 秒内回答：当前项目是什么、当前版本是什么、下一步做什么。
2. 任一 AI 生成段落都能看到资料范围、引用、状态和“转为正式内容”的入口。
3. 任一实质变更都能看到影响范围、负责人、处理状态和版本差异。
4. 任一确认都能回到具体对象版本和核查范围。
5. 阻断交付时，用户能定位问题并处理它，或将该条判定为误报后删除（须填写理由）；阻断项本身不可豁免——豁免只适用于警告与提示级问题。
6. 上传、解析、检索、生成和导出失败时都有可恢复路径；错误不以空白页面或无期限 loading 结束。
