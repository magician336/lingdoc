## 1. #412 的答案：路径所有权移交

### 1.1 问题

登记处里 PF-2~PF-5 都是 `done`，但**done 不释放路径**（PF-5 的 summary 原话：「**本面不释放路径**：done 状态仍占用这 12 条路径，后续面不要重复声明」）。下一批面要改它们的文件时，「**一条路径只有一个拥有者**」这条不变量与实际需求直接冲突——#412 记的就是这件事。

### 1.2 三个候选与取舍

| 候选 | 做法 | 问题 |
|---|---|---|
| (a) **保持单一拥有者 + 显式移交** | 新增移交记录；路径任何时刻仍只有一个 owner | 需要登记处加一个字段 + 三条 loader 校验 |
| (b) 允许多面共享一条路径 | 引入「协作改动」字段 | **PR #411 建立的两个检测器都建立在「一个 owner」上**（登记处自检的 `claimed by both`、票面一致性的撞车判定）——一旦允许多 owner，「谁拥有」就没有唯一答案，两个检测器同时失效 |
| (c) done 面自动释放全部路径 | 改状态语义 | 「谁拥有」变成「没人拥有」⇒ 同上，撞车检测失效；且无法表达「A 交了、B 接、顺序有讲究」 |

### 1.3 裁决：**(a) 保持单一拥有者 + 显式「路径移交」记录**

**机制形状**：

- 登记处每条路径**任何时刻只有一个 owner**——不变量**不变**；
- 新增一份**移交记录**：`(路径, 交出面, 接收面, 依据票号, 时间)`；
- loader 校验三条：
  1. **交出面必须是 `done`**——已交面才能交出路径；
  2. **接收面的路径集必须含该路径**——不许凭空接手；
  3. **交出面的路径集必须不含该路径**——移交是**单向、一次性**的，交出即不再声称拥有；
- 撞车检测逻辑不变 ⇒ **PR #411 的两个检测器继续有效**。

**这不是发明**：**PR #389 的实际做法就是这样**——PF-3 让出 `service_facade.go` / `typed_contracts.go` 给 PF-4，PF-4 交面后又能被下一面接。本方案只是把它从**惯例**变成**可校验的机制**（惯例靠人读，机制靠守护测试）。

**为什么不是 (b)**：让「谁拥有这条路径」变成多值，等于把 PR #411 那道机器可判的门禁拆掉。协作改动的事实可以用**移交记录 + 顺序**表达，不必放宽所有权本身。

> **⚠️ 已有实践实现（2026-10-23，PR #446）**：PF-8 用的就是**「把路径从旧面的路径集里删掉、声明到新面」**——**与本节裁决同形**（单向、一次性、旧面不再声称拥有），但**没有新增任何字段**。⇒ 本节设计的「移交记录」字段与三条 loader 校验是**可选加固，不是必需**；M-1 相应降级。详见 §7。
