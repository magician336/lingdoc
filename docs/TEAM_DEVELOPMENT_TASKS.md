# 本轮开发任务池

版本 0.5。**全部任务待领取；不预填姓名，不按个人特长分组，不按 A/B/C 领域分配整包。** 领域仅表示接口和数据职责。领取一个任务不自动获得该领域其余任务，也不自动成为公共问题的总负责人。

先读[范围与任务流程](08-本轮实施方案/01-范围与任务流程.md)。合作方式见[协作约定](06-灵档产品开发规划/05-团队分工与代码边界.md)，字段和行为以[接口约定](08-本轮实施方案/02-接口与Mock约定.md)为准。

## v0.4 → v0.5 任务迁移

本轮当前任务编号以 **T01–T16** 为准。v0.5 没有删除 v0.4 的前端范围，而是把界面、adapter、状态处理和接真责任并回对应领域任务；任务是**交付责任单元**，不是强制单人全栈工作包。一个任务可由多人协作、拆成多个小 PR；下游等待的是已经交出的最小接口，不必等整个上游任务全部完成。

| v0.4 任务 | v0.5 当前归属 |
|---|---|
| T01–T14 | 编号保持；其中 T07–T14 同时吸收对应用户界面切片 |
| T15 项目列表/新建/研究条件界面 | 并入 T07 |
| T16 章节编辑与确认界面 | 编辑/保存并入 T08；待核处置与确认并入 T12 |
| T17 资料/生成/候选操作区 | 分别并入 T09、T10、T11 |
| T18 交付页 | 检查/快照并入 T13；导出/下载/历史标签并入 T14 |
| T19 跨任务错误与恢复 | 新 T15 |
| T20 页面组合与连续流程 | 新 T16 |

## 1. 如何领取

每人先选择一个可推进的主要任务，在对应 Issue/PR 填负责人、实际消费者、评审人、剩余工作量和当前阻塞。下面编号是任务标识，不是已经创建的 Issue 或 PR。

“接真依赖”表示接入真实系统时需要的交付；**不等于必须等这些任务全部完成才允许写代码**。按照同表的固定输入/Mock 可提前推进。接口一旦够用就交出小切片，别等大任务全部完成。

初期可并行 T02–T05 的最小验证以及 T06 的契约适配；已有可用环境时不必等 T01 的全部说明写完。各项验证代码可维护时直接演进为功能，不要求重复实现。界面不再单列为一组“后端完成后再做”的任务：凡是有用户操作的服务任务，都必须同时交付对应的 API adapter、加载/错误/空状态和最小可操作界面。

## 4. 界面作为领域任务的交付切片

界面交付随领域能力完成，不再领取 v0.4 中独立的前端 T15–T18。每个服务任务至少包含一条“用户可操作切片”，由该任务负责人维护 adapter、状态处理、权限边界和对应测试；界面作者可以协作实现组件，但不能把接真、错误处理或验收甩给另一个“前端任务”。

| 服务任务 | 同步交付的界面切片               | 最小验收                                |
| ---- | ----------------------- | ----------------------------------- |
| T07  | 项目列表、新建项目、研究条件表单、成员状态展示 | 创建→填写→立项；失败保留输入；非成员不暴露存在性；不新增成员管理后台 |
| T08  | 章节读写编辑器、保存状态、冲突提示       | 手动编辑不丢待核项；冲突不覆盖；保存重试不重复写            |
| T09  | 资料选择、授权/就绪状态、来源定位       | 只显示允许集合；拒绝越权/未就绪资料；定位可回到原文          |
| T10  | 生成任务启动、进度/失败/取消、候选列表    | 刷新后仍查询同一任务；失败原因可见；不直接写章节            |
| T11  | 候选预览与整章采纳确认             | 明确替换影响；取消不发写请求；采纳后重新读回新版本           |
| T12  | 待核项处置、逐章确认、重新确认提示       | 错误版本/重复处置被拒绝；修改后确认失效；空章可继续交付检查      |
| T13  | 检查结果、阻断原因、冻结快照状态        | blocked 原因可定位；冻结后内容变化不改变快照；当前性动态显示  |
| T14  | 导出进度、下载、当前/历史交付标签       | 失败不提供假下载；下载重新鉴权；编辑后旧文件标历史           |

界面切片可以先用 T06 的固定响应和各任务 Mock 开发，但进入正式演示前必须由领域任务负责人完成接真。组件应保持可挂载到工作台，不另建一套平行业务状态。

| ID  | 任务与交付物                                            | 接真依赖    | 可先用什么              | 验收结果                                           |
| --- | ------------------------------------------------- | ------- | ------------------ | ---------------------------------------------- |
| T15 | 跨任务错误与恢复场景：撤权、冲突、过期、响应丢失、模型和导出失败；维护可复现请求、状态及副作用断言 | T07–T14 | F02–F21，按已就绪接口逐个接真 | 对应实现负责人修自己的问题；不由本任务领取者包办全部修复                   |
| T16 | 页面组合与连续流程入口：挂载 T07–T14 的界面切片，把 F01 接到真实测试环境       | T07–T15 | 固定组件与 F01 参考流程     | 两章完整流程、真实文件及运行方式有记录；消费任务召集提供方协作，组件/接口作者负责本任务接真 |

T15/T16 可先搭测试和组合入口，再随真实接口逐项通过；表中依赖表示最终验收的集合，不要求串行等到末尾才开始。

## 6. 建议怎样拆 PR

- T08：先章节读写，再交 GenerationContext；章节编辑器切片可先用 Mock 独立推进，但仍归 T08 验收。
- T10：先单次任务/候选，再补失败恢复和质量；候选读取接口够用就交 T11。
- T12：确认与 DeliveryInput 分成可独立评审的切片，后者可先用固定确认验证形状。
- T13：规则检查与冻结保存分开评审，但必须共同证明确认/版本不变量。
- T14：任务/渲染与鉴权下载分开，未完成下载校验前不标完整交付。
- 各领域任务的界面切片：API adapter、组件和关键交互可分 PR，但必须挂在对应 T07–T14 的交付记录下；未接真部分标清，不进入正式演示。
- T15/T16：只承接跨任务错误矩阵、页面组合和连续流程，不重新实现领域组件。

任务数量不等于 PR 数。每个任务中的接口、样例、必要测试和接真属于同一交付责任，不另甩给“公共测试人员”。

## 7. 领取卡片

```text
任务：T__ / 名称
负责人：待领取
协作人：领取后按需要填写
实际消费者 / 评审人：领取时确定
用户结果：本任务交付后能完成什么
输入 / 输出：链接已有契约，不另抄字段
界面切片：入口、关键状态、错误恢复和接真责任；无界面时写“不适用”
可先开发：固定输入或 Mock
接真前置：任务编号及所需的最小接口
必验场景：成功、关键失败、状态/副作用
交接证据：可复现操作、测试结果、仍未支持的部分
剩余工作量：区间，含测试联调；未测风险单列
当前阻塞：缺什么、由哪个任务提供、解除标准
状态：待领取 / 进行中 / 待评审 / 待接真 / 交接通过
```

一个开发时段无最小结果/失败定位、持续等依赖、一项任务堵住多个消费者或剩余量超出可投入量时，提前重估。先拆小接口、转移完整任务或结对排障；范围取舍集中说明。不按日排满，不以相同工时数字预先证明均分。

## 8. 与原计划的关系

原 PR-000/1xx/2xx/3xx/4xx 是完整产品历史计划，本轮以本任务池为领取入口，旧版本可在 Git 查阅。未把某个旧 PR 的全部范围搬入本轮，也不声称旧 PR 已完成。外部来源、完整 PCC、复杂模板和机构治理保留后续设计参考。
