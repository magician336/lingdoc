# T01–T16 完成假设下与 Beta 规划的差距清点

> 清点日期：2026-09-25  
> 适用假设：假设 docs/TEAM_DEVELOPMENT_TASKS.md 中 T01–T16 的 PR 均已合并并通过各自验收。本文不把该假设当作当前仓库已实测事实，也不替代真实 PR、CI、端到端环境和业务模板验收。

## 1. 结论摘要

T01–T16 完成后，LingDoc 能交付一条可运行的内部演示纵切片：

> 新建项目 → 填写条件 → 绑定允许资料 → 生成候选 → 整章采纳/人工编辑 → 逐章处置待核项 → 冻结检查 → 生成并下载可编辑 DOCX → 覆盖撤权、冲突、过期、重试和失败恢复。

这条纵切片与 beta 规划存在直接交集，但仍不是 beta 的完整能力。最大的差距不是页面数量，而是缺少四类产品真相：

1. 证据真相：EvidenceCard、ResearchClaim、来源层级和证据确认闭环。
2. 项目变更真相：ChangeSet、PCC、依赖图、影响任务、局部失效和稳定化。
3. 完整模板/规则真相：按申报类别/年度版本化的模板、规则生命周期、两级检查和问题处置治理。
4. beta 运行真相：完整权限组合、审计、指标、回归基准、灰度/回退和安全运行要求。

合理产品标签应是：**内部 beta 前的可运行核心演示切片（two-chapter controlled workflow）**，不是完整对外交付 beta，也不是正式课题申报系统。

依据：[本轮范围与任务流程](../08-本轮实施方案/01-范围与任务流程.md)、[任务池](../TEAM_DEVELOPMENT_TASKS.md)。本轮文件明确写出“固定演示模板、两个代表性章节”“暂缓完整 PCC、外部学术检索、复杂组织权限、机构管理台”，并声明“不等同完整 Beta”。

## 3. 六类关键缺口

### 3.1 建项语义与草稿阶段

Beta 要求创建后处于 draft、Context Revision 0，可停留并由团队共同草拟；AI 填写值与人工改动分开显示并可回看；草稿期可上传资料和受控检索但不得创建正式章节、主张或证据卡；Owner 立项确认后生成章节骨架和 Context Revision 1；草稿候选在 0→1 时不被错误标记为 STALE；草稿可显式丢弃并保留审计/恢复入口。

T07 的“条件版本、立项骨架、固定测试成员”只能证明最小入口存在，不能证明这些建项不变量全部落地。

主要依据：[01-产品蓝图与范围](01-产品蓝图与范围.md)、[07-建项阶段设计](07-建项阶段设计.md)、[03-数据模型与接口契约](03-数据模型与接口契约.md)。

### 3.2 证据和调研闭环

T03/T09/T10 解决的是“在允许资料范围内检索并生成一个候选”。Beta 需要更长的可追溯链：

新想法 → 调研计划 → 受控学术来源/发现层 → 用户选择来源片段或对话片段 → 导入候选资料 → ProjectAsset/SourceAnchor → EvidenceCard → ResearchClaim → 章节引用与确认。

当前任务池没有独立任务承接 Research Agent、来源目录、搜索摘要不得直接成为证据的闸门、AI 对话片段谱系、EvidenceCard 支持/限制/不足、ResearchClaim 依赖和证据重解析后的局部失效。

主要依据：[01-产品蓝图与范围](01-产品蓝图与范围.md)、[10-调研智能体与知识沉淀规划](10-调研智能体与知识沉淀规划.md)、[13-端到端课题申报模拟](13-端到端课题申报模拟.md)。

### 3.3 PCC、变更影响和路线图

T15 的过期、冲突、失败恢复保证一次连续流程不损坏状态，但不等于 PCC。Beta 要求：

ChangeSet → Assess → Apply → 新 Context Revision → 影响任务 → A/B/C 处置 → 重新确认 → Stabilized。

影响对象至少包括证据卡、ResearchClaim、方法/样本/结果章节、技术路线图、交付和确认记录。T01–T16 没有 ChangeSet、DependencyRegistry、ImpactTask 或 RouteNode 任务，因此不能宣称“变更一致性”已完成。

主要依据：[02-领域架构与PCC](02-领域架构与PCC.md)、[13-端到端课题申报模拟](13-端到端课题申报模拟.md)。

### 3.4 模板、规则和问题治理

T02 的固定两章模板是演示输入，不是 beta 模板系统。Beta 还要求按申报类别/年度/版本管理 TemplateProfile，模板检查与导出前 Preflight 分层，问题统一进入 ValidationIssue，区分规则判定与模型判定，支持修复、关闭、警告豁免、误报删除，并对模板升级和误报率进行治理。

T13 已覆盖冻结输入、阻断、digest 和动态当前性的一部分不变量，不能代表完整模板/规则生命周期。

主要依据：[11-模板与规则系统设计](11-模板与规则系统设计.md)、[12-模板与规则系统开发计划](12-模板与规则系统开发计划.md)、[15-质量验收与上线运行](15-质量验收与上线运行.md)。

### 3.5 权限、治理和审计

T07 的固定成员与最小 access-status 是本轮有意收窄的范围。Beta 权限闭环还包括 WeKnora 租户身份上限、LingDoc 治理/职能双轴、资源 scope、项目绑定知识库、成员邀请、Owner 转让、Owner 失效恢复、允许/拒绝审计、撤权后派生内容再鉴权，以及 Admin 不得代行学术确认、ChangeSet 应用或导出放行。

固定测试成员不能解释为完整 beta 权限模型。

主要依据：[08-权限设计与复用WeKnora](08-权限设计与复用WeKnora.md)、[14-权限管理操作模拟](14-权限管理操作模拟.md)。

### 3.6 Beta 质量、运行与效果评估

T15/T16 主要回答“演示流程能否走通、失败后能否恢复”。Beta 还需要完整验收矩阵、单元/契约/集成/E2E/安全/回归分层、脱敏版本化 fixture、结构化关联 ID、解析/检索/变更/陈旧/导出/权限指标、灰度与回退，以及人工投入时间、来源支撑率、漏改数、误报数、未确认项数和导出损失数等效果度量。

主要依据：[15-质量验收与上线运行](15-质量验收与上线运行.md)。

## 4. 覆盖结论

### 已覆盖的核心交集

在任务确实按验收条件完成的前提下，可以合理认为已有：

- 固定演示模板和版本读取；
- 最小运行、迁移、注入和前端 adapter；
- 项目/条件/章节持久化、版本条件写入和冲突保护；
- 允许资料集合、READY 状态、来源定位和当前授权校验；
- 生成任务、轮询恢复、候选 basis、引用和待核项；
- 整章采纳、旧版本保留、幂等；
- 逐章确认和 DeliveryInput 一致读；
- 冻结快照、frozen input、digest、阻断和动态 is_current；
- DOCX 生成、结构/内容校验、失败不提供假下载、下载再鉴权；
- 领域界面切片、跨任务错误恢复和两章 F01 组合入口。

### 部分覆盖，不能升级为 Beta 完成

建项、资料证据、章节协作、模板规则、权限治理、交付保真和联调运行均有最小切片，但都缺规划中的完整对象、流程或验证证据。

### 明确未覆盖

Research Agent；EvidenceCard/ResearchClaim；PCC/ChangeSet/DependencyRegistry/ImpactTask；RouteNode；完整模板/规则治理；完整权限与审计；Beta 级安全、观测和回归；多章节、多模板和正式申报格式保真。

## 5. 建议补齐顺序

### P0：先补产品真相和不可逆边界

1. 建项/草稿阶段与 Context Revision 0→1；
2. EvidenceCard/ResearchClaim 与 Research Agent 导入链；
3. ChangeSet/PCC/依赖图/影响任务；
4. 完整权限与审计边界；
5. 模板/规则对象、两级检查和问题处置。

### P1：再补可用性和完整交付

1. RouteNode 技术路线图；
2. 证据/主张/变更/交付复核工作台；
3. 多模板、多章节和正式业务模板；
4. 表格、图形、分页等 DOCX 保真；
5. 多人协作、批注和任务分派。

### P2：最后用运行证据证明 Beta

1. 安全、契约、集成、E2E 和回归基准；
2. 观测指标、审计查询、灰度/回退；
3. 用户效果度量和真实团队试用；
4. 真实资料、模型、数据库和跨环境验证。

## 6. 不应误算为当前 Beta 缺口的内容

规划文档把以下内容放在 Beta 之后的 P5 生产增强，不应为了“补齐 beta”提前扩大本轮范围：

- 受限服务账号；
- 临时授权；
- 项目级策略模板；
- 敏感材料脱敏/水印；
- 组织级审批流；
- 新的微服务平台或第二套账号系统。

## 7. 发布口径

后续 PR/发布说明建议同时写清：

1. 已完成：T01–T16 的内部两章闭环和失败恢复；
2. 尚未完成：本笔记列出的 P0/P1/P2 beta 缺口；
3. 证明方式：分别给出静态契约、真实服务、真实模型、可打开 DOCX、权限安全和端到端运行证据。

不要使用“Beta 已完成”“完整产品已交付”或“支持证据驱动变更协调”等超出 T01–T16 证据范围的表述。
