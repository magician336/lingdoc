> **用途**：流程第 ③ 步（任务流与状态设计）的落地物。按功能域记录已识别的状态（含冲突/过期/被拒/未保存），不宣称穷尽全部状态，对照当前实现标注呈现程度，作为布局评审（#105）选定结构后的实现输入。

> **基线与归属**：Kimi 原清单依据 PR #106 的 `8a717e9`，主要阅读 Workspace 与 DeliveryPanel；原稿未细读采纳弹窗。Codex 本轮三项 UI 安全补丁独立基于 main `064abbc005215f063d6ca8ec69d874ebc8ceb228`，补读采纳弹窗并验证相关状态。下表其他评级沿用原稿分析，不表示本轮已逐项重验，也不表示独立补丁包含尚未合并的 PR #106。原稿保存在本地 `ui-state-inventory-20261011-kimi-v1.md`。
>
> **评级**：✅ 已呈现（状态可见 + 恢复路径明确）｜🟡 呈现不足（有呈现但关键信息/恢复路径/一致性缺失）｜❌ 未呈现。

## 总体印象

这份前端的状态意识**远高于一般水平**：部分关键异步读写已有"响应回来时项目/章节是否已切换"的守卫；不能据此断言全部路径已覆盖；被拒明细、预览失效、快照当前性、"unknown 不显示"这类容易糊弄的边界都有显式代码注释说明取舍。主要缺口集中在：**刷新/关页保护、错误槽位单一、409 恢复路径不统一、双标签冲突无可视对比**。

## 与 #105 原型（三套布局）的关系

原型里已验证但**正式页没有**的行为：beforeunload 保护（缺口 #1）、过期候选拒绝覆盖人工输入（正式页已有等价守卫）、快照冻结语义（正式页已有等价物）。**本轮三项补丁与布局选择正交**，可从 main 独立评审。原清单把 beforeunload 移植评为“极低成本”不足以覆盖完整未保存判定：保存中、理由确认后的清理和路由离开均需验证。其余项按上表边界后续推进。
