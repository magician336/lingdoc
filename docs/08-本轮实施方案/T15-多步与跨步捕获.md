# T15-06：多步与跨步捕获

状态：实现与合成提供方回归已完成；真实服务结果记录在 `T15-S6-验证报告.json` 和 `T15-S6-证据.json`。

对应 issue #32，承接 #31 的场景执行器。本票将 F05、F08、F12 接入同一执行协议，并允许一次命令运行多条独立场景。每条场景仍从各自的 `starting_state` 构建，不共享项目或动态业务 ID；聚合报告保留各条完整执行轨迹，并为其余场景保留明确的 `not_run` 原因。

## 跨步变量

场景步骤可以声明 `capture`，从响应 JSON Pointer 捕获变量。后续步骤的请求字段和可求值检查可引用 `{{变量名}}`。执行器在运行时保留原始值用于请求和断言，在报告里把已捕获的动态 ID 替换为契约中声明的别名。静态契约校验器检查变量只能在种子变量或更早步骤捕获之后使用、捕获别名不得重复、捕获指针须存在于对应的发布响应示例。

## 三条场景

| 场景 | 多步路径 | 关键判定 |
| --- | --- | --- |
| F08 | 列出章节并捕获章节 ID → 首次提交生成并捕获 run ID → 同键同请求重放 → 同键改请求 | 重放返回同一 run ID 且 `meta.replayed=true`；改请求返回 `idempotency_conflict`。同一 run ID 表明只观察到同一个业务任务，不额外声称后台任务执行质量。 |
| F05 | Owner 与协作者分别读取同一章节版本 → Owner 保存 → 协作者提交旧版本 → 再读取章节 | 第一次保存成功；旧版本保存精确返回 `version_conflict`；读回确认当前正文仍是 Owner 保存的版本。 |
| F12 | 读取草稿 spec revision → 保存新草稿并捕获新 revision → 用旧 revision 激活 → 用新 revision 激活 | 旧 revision 精确返回 `version_conflict`；新 revision 激活成功，且项目状态和 revision 符合检查。 |

## 运行

在真实服务启动并准备好契约所需的可用资料、未就绪资料、协作者和双身份凭证后：

```powershell
python scripts/lingdoc_mock/run_scenario.py `
  --scenario F08 --scenario F05 --scenario F12 `
  --base-url http://127.0.0.1:8080/api/v1/lingdoc `
  --knowledge k-demo=<真实知识 id> `
  --member u-member=<真实成员 id> `
  --identity u-owner=<Owner 令牌> `
  --identity u-member=<协作者令牌> `
  --report docs/08-本轮实施方案/T15-S6-验证报告.json
```

凭证只从本地安全环境注入，不写进命令记录、契约、报告或证据。若一次运行中任何场景失败，命令返回非零，并继续执行后续所选场景；聚合报告保留已执行步骤与失败断言。前置检查或状态构造阶段中止的场景也会单独标记失败。一个必需捕获值未能产生时，该步失败，依赖它的后续步骤标为 `not_run`，不会抛出未处理的 traceback。报告不包含令牌、提供方生成的 ID 或时间戳。
