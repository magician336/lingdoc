### 结构性不足与重构动作

1. **交付组合根 → 低层兼容构造仍可绕过事务端口 → 收窄 `NewReleaseService`/导出构造函数，只接受 `Transactional*Port` → 减少调用者记忆原子审计约束 → 保留缺端口失败测试和组合根编译门禁。**
2. **RuleSet 证据 → 兼容路径仍可能从持久化模板重新构造证据 → 将验证证据的创建下沉到 application service，低层 evaluator 只接受不可变 `VerifiedRuleSetBinding` → 消除重复 hash/身份校验 → 保留 ref-only、hash mismatch、mutation 防护回归。**
3. **验收证据 → SQLite/旧 CI 与当前 head 混在历史文档中 → 每次 Spec 只维护带 SHA、命令和状态的 closeout 表，历史记录只作背景 → 降低错误复用旧 run 的风险 → PR gate 检查矩阵中不得出现无 SHA 的 PASS。**
4. **审计/验证/事务观测 → 指标表按低基数维度持久化，采集器与 HTTP 读回统一收口在 RuleSet application seam，事务能力错误通过 delivery observer 回写 → 减少各调用者自行解释失败原因和分位数算法的变化放大 → SQLite/PostgreSQL migration、HTTP、重启读回和 p95/p99 回归保持为门槛。**
