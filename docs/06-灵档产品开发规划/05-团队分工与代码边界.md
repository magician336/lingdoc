# 按任务领取与协作边界

## 1. 领取任务，不预先圈人

[任务池](../TEAM_DEVELOPMENT_TASKS.md)中的当前 T01–T16 面向所有开发成员开放。负责人、实际接口消费者和评审人在领取时填写，初稿不填姓名，也不要求一人承包某个领域。T07–T14 是端到端交付责任单元，不等于必须由同一人完成后端、adapter 和界面；最小接口达到约定后应尽早交给消费者。

资料服务管理资料/候选，工作区服务管理项目/章节/确认，交付服务管理模板/快照/导出。这些边界规定数据和接口职责；同一领域可由多人通过任务边界合作，一个人也可领取不同领域的任务。

每人原则上推进一项主要功能，另为评审/解除依赖留位置。工作量包括学习、接入、排障、测试和联调；不按 PR 数、任务数或相同预算机械配平。

## 2. 最小交接

| 交接内容 | 提供任务 | 消费任务 | 最早可交什么 |
|---|---|---|---|
| 固定模板及规则 | T02 | T07、T10、T13 | TemplateReader 固定实现和样例 |
| 项目权限、研究条件和当前章 | T07、T08 | T09、T10 | 小型只读接口、固定上下文 |
| 来源与候选 | T09、T10 | T11、T13 | SourcePolicy / CandidateReader 样例，随后接真 |
| 确认及完整交付输入 | T12 | T13 | DeliveryInput，包含空章和未确认章 |
| 快照与导出状态 | T13、T14 | T16 | 成功、阻断、失败、历史版本样例 |
| 可挂载界面切片、输入和回调 | T07–T14 | T16 | 可挂载组件，标明当前 `mock` / `real_api_fake_model` / `real` 状态 |

提供方随接口交可替换固定实现，消费者先开发。固定实现表示可以开始；两边在真实提供方上跑通场景才算交接完成。T07–T14 内部的服务实现、adapter 和界面切片可以由不同实现者并行完成，但都挂在同一任务的交付记录下。

## 3. 代码和数据边界

- 优先单体内小 interface 和构造注入，沿用现有 Go/Vue 工程；不为并行开发新建微服务或第二套账号系统。
- T01 给路由/迁移/模块接入示例；后续每项任务自己接入、维护迁移和测试，T01 领取者不自动承担所有后端工作。
- 资料服务不写章节表，交付服务不修改确认；基础项目授权不递归调用来源授权。
- 前端通过 API adapter 使用共同契约，组件中不维护另一套 Mock DTO；页面组合只组装组件，不承包所有业务逻辑。
- 共用入口文件先合最小注册 PR，再在模块内部实现。格式整理、目录搬迁和无关重构不夹入功能 PR。

## 4. Mock 与接真责任

T06 搭最小 Mock/契约检查入口，**各接口任务自己维护样例和提供方测试**。T15 维护跨任务错误与恢复场景，T16 组织页面组合和 F01 连续流程；出现问题时仍由对应 T07–T14 实现负责人修复，T15/T16 的领取者不会自动承包全部公共工作。

界面使用固定 HTTP 例子，内部服务使用小型 fake；并发、幂等、权限和旧版留存最终由真实服务/测试数据库验证。固定响应没有天然的连续状态。

每交出一个真实接口就接一段，标明 `mock`、`real_api_fake_model`、`real`；失败不暗中回退 Mock。生成→采纳、确认→交付分别由对应消费任务召集双方验证，不设置永久“总集成人”。

## 5. PR 节奏

一个可评审、可回退的结果对应一个短期分支和小 PR，不按 A/B/C 建长期分支，不机械限制行数或天数。

- 普通 PR 指定一位评审人；契约变化由实际消费者评审，全局影响才全员共同看。
- 先交当前交接所需字段、成功/失败样例和内部签名，不等待未来全部接口一次定稿。
- 破坏性变化同步修改提供方、消费者与样例，或明确兼容过渡；不能只在群里通知改名。
- 未接真页面可以隐藏入口合入，标清依赖，不进入正式演示路径。
- 每次开工先处理已收到的评审或回复阻塞，不要求全员持续在线。
- PR 描述写用户结果、接口变化、验证证据、仍为 Mock 的部分与回退办法。

使用仓库当前实际检查：相关 Go 包测试，前端相关测试/类型检查/构建；不把旧项目脚本照搬进来。契约静态检查见[说明](../08-本轮实施方案/README.md)。

## 6. 出问题怎么处理

提供最小请求、测试身份、代码/契约版本、预期和实际结果。优先使用合成资料，不在公共 PR 放真实原文或凭证。

1. 契约明确而实现不符：对应实现负责人修，消费者继续用约定样例。
2. 契约漏了业务规则：提供方和消费者补规则及反例，再改实现。
3. 底座不支持原假设：做最小验证，公开限制，调整实现或范围。

状态使用待领取、进行中、待评审、待接真、交接通过。阻塞写缺什么、谁提供、怎样判断解除。交接记录直接附原 PR：契约版本、启动方式、可复现请求、已过场景与未支持内容，不再新建一套日报流程。
