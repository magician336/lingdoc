# Issue #682：分块与解析输入原文身份

范围：普通上传文件的原文证据；仅内置直读解析的文本可以取得强原文定位。目的地为 PR #755。

原文身份由实际解析输入的完整字节 SHA-256 与分块共同写入；引用时须与同一次存储读取的原文匹配。旧分块没有可信摘要，不能从当前文件反填并声称原来即为该文件。手工资料、URL 和格式转换资料维持各自原有能力边界，不以文件 MD5 宣称抗碰撞身份。

| 验收项 | 不变量 | 状态 |
| --- | --- | --- |
| 上传与解析 | 摘要从实际送入解析器的字节计算；原始分块和摘要同事务 | SQLite 定向测试和两篇公开论文真实上传通过；129 个分块均有摘要及向量记录 |
| 来源覆盖或并发替换 | 现存原文与分块摘要不同则拒绝强原文，引用内容不变也不能绕过 | 摘要不匹配、事务回滚定向测试通过；真实对象存储并发未验收 |
| 历史分块与恢复 | 摘要缺失降级；重新解析创建新的摘要和分块 | 旧分块降级、SQLite 关闭重开读回定向测试通过 |
| 迁移和重启 | SQLite 与 PostgreSQL 新表迁移、数据持久及重启读回 | 独立 SQLite 实际迁移到 60 且重启读回；PostgreSQL 17 单独执行 000139 up/down/up、实际仓储写入读回及事务回滚通过 |
| 应用验收 | 来源读取、权限和证据确认的真实路径；迁移缺失时失败关闭 | 隔离服务真实上传、检索、绑定、模拟授权、原文锚点、证据卡和写作 job 通过 |

输入信任边界：该摘要证明当前原文与解析器当时读取的字节一致，并不单独证明用户上传提交时的原字节；若要求上传时身份，还需持久化上传摘要并在解析时比较。跨服务对象存储和 DB 提交并非一个全局事务。

## 隔离真实资料验收

- 使用欧洲 PMC XML 提取的两篇 CC BY 4.0 论文文本副本：DOI `10.7717/peerj-cs.2521` 与 `10.1093/bioinformatics/btae420`。副本保留来源、作者和许可，并注明转换及省略表格/图形的边界；定位针对上传的文本副本，不声称 PDF 页码定位。
- 两篇分别生成 78、51 个就绪分块；实际向量检索和关键词检索均命中对应资料。SQLite 中共 129 条分块、129 条解析输入摘要、129 条向量记录。
- 真实 Qwen 生成调研提案；模拟确认计划与资料授权后，真实调研运行的本地论文命中可创建原文锚点、主张、证据卡和上下文。真实 Qwen 写作 HTTP 任务成功生成 fresh 候选稿，并包含论文来源引用。人工确认、项目目录和额度均为隔离测试设置。
- 初次真实调研两轮返回本地命中但 Crossref 为零；Crossref 同词直接查询可返回结果。原因是本地结果在前，核心按每轮上限截断，挤掉外部结果。修复后同一组检索词复测：19 条本地命中、20 条 Crossref 记录；以目标论文标题模拟编辑检索词后得到 17 条本地命中、20 条 Crossref 记录，目标 DOI 命中测试目录并以 metadata-only 保存及模拟确认。
- 在修复后新建另一个隔离项目重新串联：真实 Qwen 计划、人工确认模拟、真实本地和 Crossref 两轮检索（13 条本地命中、20 条 Crossref 记录）、原文锚点、证据确认、上下文及真实写作 HTTP/worker job 均通过；fresh 候选稿包含已上传论文的引用。该过程仍使用临时目录、额度和模拟确认，不代替正式研究者验收。
