## 结构性缺陷与重构方向

1. **生产学术政策与累计配额由组合层拼装**：`academicResearchPolicyReady`、`ResearchExecutionGate`、`ProjectResearchBudgetLedger` 与 `ResearchAdapter.ConfigureAcademicResearchPolicy` 分担相关规则；调用方必须知道何时配目录、何时配账本。变化会同时触及领域模型、宿主 adapter、生产组装和测试。建议将它们收敛为一个受版本约束的学术访问策略端口，由单一持久化服务原子预留搜索/返回/模型额度并返回所用策略快照；回归门槛为并发超额、进程重启读回、未知结算和规则改版负向测试全部通过。
2. **来源政策版本需跨项目目录和全局目录共同维护**：结果、候选和 task basis 都携带版本，再由候选创建/确认重新读取。该双时点复核是必要的，但当前只在 workspace adapter 可取得合并快照，核心层仍持有多个字段和错误分支。建议把不可变 `PolicyDecision`（版本、规则 ID、许可/撤稿/重复状态）作为端口返回值，并由领域层只比较一个决策版本；回归门槛为全局与项目规则单独/同时变更均使旧候选不能创建或确认。
3. **元数据发现与定位型证据仍是两个能力层**：Crossref 的数据类型没有原文定位，`InspectResearchOriginal` 必须拒绝，因此不会形成 evidence card。保持该边界正确；后续定位适配器应单独实现，不要把 Crossref 元数据字段映射成 Locator。回归门槛为没有原文哈希与定位就永远不能产生正式 EvidenceCard。

## 最高优先级动作

获批全局白名单与额度策略明确后，先实现一个持久化学术预算/策略模块，并在生产 composition root 注入。它能消除最关键的“功能看似可用但生产必须禁用”的配置分散，并集中并发、重启和审计恢复语义。当前缺少输入，不能代替业务人员制定白名单或额度数值。
