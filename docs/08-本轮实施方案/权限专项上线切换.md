# LingDoc 权限专项上线切换

本文记录 #46 权限专项在 PR #43 `Repository → Transaction` 架构上的上线顺序。身份、租户成员、租户角色、知识库共享和 API Key 仍由 WeKnora 提供；LingDoc 只保存项目成员的治理角色、职能 capability 与资源 scope。

## 决策链

每次项目操作按以下顺序计算：

```text
active tenant member
  ∩ WeKnora TenantRole ceiling
  ∩ ProjectMember governance/function capability
  ∩ chapter/asset/delivery scope
  ∩ current KB share / source authorization / API-key route policy
```

写操作在同一个 `Repository.Transaction` 中完成授权、版本检查、业务写入和幂等记录。撤权后授权失败发生在幂等记录读取之前。

## 三种运行模式

| 模式 | 行为 | 适用阶段 |
| --- | --- | --- |
| `log` | 计算新策略并写入审计事件，返回旧策略结果；记录 `allow`、`deny`、角色、capability、项目和原因 | 灰度比较 |
| `enforce` | 新策略是最终结果；拒绝使用既有 `not_found`、`source_access_denied`、`invalid_state` 和版本错误 | 默认生产模式 |
| `rollback` | 停止新成员 capability/scope 写入，保留兼容的 owner/collaborator 读取和旧路由策略；不删除 sidecar 数据 | 迁移异常或回退 |

当前代码通过 `workspacecore.NewServiceWithAudit` 注入审计端口；生产组合根将授权事件写入 WeKnora `audit_logs`。没有审计依赖时，核心策略仍可运行，测试和本地迁移不需要额外服务。

## 迁移与回退

1. 先执行 SQLite `000025_lingdoc_member_permissions` 或 versioned `000104_lingdoc_member_permissions`，确认迁移版本和 sidecar 表存在。
2. 旧 `lingdoc_members.role` 保留，读取时映射为 `owner` / `member`；新 sidecar 写入治理角色、职能角色、scope 和状态。
3. 先启用 `log`，比较项目成员、角色降级、scope 变化、来源撤权和导出阻断事件。
4. 审计事件与关键负向测试稳定后切换 `enforce`。
5. 回退时停用新赋权入口并保留 sidecar；旧项目仍可通过兼容字段读取，恢复不删除已写审计事件。

## 验证命令

```powershell
go test ./internal/lingdoc/workspacecore ./internal/lingdoc/workspace ./internal/router
go test ./internal/lingdoc/workspacecore -run TestPostgresMigrationAndRepositoryContract -count=1
```

第二条命令需要隔离测试库的 `LINGDOC_TEST_POSTGRES_DSN`；未设置时测试明确显示 `SKIP`，不能当作 PostgreSQL 通过证据。
