## 四、发现的盲区及补充方式

16 项盲区在 #209 中均**未**补测试。理由：本票是纯验证票，且其中多数（DC10、DC11 等）在现有 fixture 下不可达，补测试需要新增 fixture 能力。

> **状态更新（#212）**：以下建议已由 #212 实施，结果见第八节。

建议的补充方式（按性价比排序）：

1. **DC3 / DC14（`result_receipt_stale`）** —— 最高优先级。需构造一个 DONE 的 `RECOMPUTE`/`RETRIEVE_CANDIDATES` 任务，其结果回执在稳定化前失效（例如 ResearchRun 未完成或 basis 过期），断言 `result.Blockers` 含 `result_receipt_stale`。两侧入口各一条。
2. **DC1（Owner context revision 一致性）** —— 需构造「ChangeSet 的 `TargetContextRevision` 不等于当前 revision」的场景，断言 `ErrVersionConflict`。现有 `TestStabilizationRefusalWritesNothing` 只覆盖了「不存在的 ChangeSet」。
3. **DC4 / DC5 / DC15（`closure_stale` 与确认要求）** —— 需构造 DONE 非 BLOCK_RELEASE 任务，其 closure evidence 指向的章节版本在稳定化前被替换，断言 `closure_stale`。DC9 的 fixture 已接近可用（`replaceTargetChapterBody`），复用即可。
4. **DC10 / DC11** —— 需新增「稳定化时模板未绑定」与「未安装规则检查器」两个 fixture。
5. **DC6（ResearchClaim 人工复核）** —— 需构造 `REVIEW_REQUIRED` + `ResearchClaim` 目标任务，人工决策不是 `reviewed` 或 basis 过期。
6. **DC7 / DC18（BLOCK_RELEASE preflight）**、**DC8 / DC16（route）**、**DC17（rules）**、**DC13 / DC19（闸禁的 stabilized 存在性与 STALE 独立失败）** —— 各自需要一个专门的漂移 fixture。

补充时**不得**削弱既有断言或修改期望值；新测试应与现有阻断—修复往返用例并列。

对 #210 的直接含义：稳定化同源化若按「两条路径行为等价」的假设合并实现，会同时改变两侧语义 —— 尤其是让 Owner 路径获得闸禁的全量来源复检（行为变严），或让闸禁失去 `ErrImpactObjectUnavailable` 的错误返回（行为变松）。这两处都必须显式裁定，不能默认对齐。

### 仍未覆盖的部分及原因

- **DC4（闭环证据对象被替换后的 `err != nil` 半支，`impact_service.go:1144`）** —— 未补，且在当前实现下难以从
  `StabilizeRevision` 到达：DONE 非 BLOCK_RELEASE 任务的闭环证据会先进入 `checkedImpactWrite` 的 refs 列表
  （`impact_service.go:1077`），任何版本漂移都会在 `currentImpactObject` 处以 `ErrVersionConflict` 让整次稳定化**报错**退出，
  走不到后面循环里的 STALE 转换分支。该分支当前只能由「证据对象不可读」而非「版本被替换」触发，本轮未能构造出这种状态，
  故**如实记为未覆盖**，未用恒真断言充数。DC9 已覆盖同类语义的另一条路径（`impact_object_unconfirmed`）。

  （`impact_service.go:1135`、`release_gate.go:275`），守护该条件已生效；单独构造它需要一条完整、真实的 ResearchRun/ResearchTask/
  研究资产闭环，成本远超收益，故未做。
- **来源授权复检（第五节第四项不对称点）** —— 不在 20 项条件之列，本票未处理。
