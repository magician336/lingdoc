# G4 RuleSet 服务切片（2026-10-15）

本切片继续实现 Issue [#140](https://github.com/magician336/lingdoc/issues/140) 与现有 Draft PR #151；只交付 RuleSet 的安全服务/API 边界，不表示 G4 全部完成。

## 已实现

- `GET /api/v1/lingdoc/rule-sets/definitions`：读取服务端白名单规则定义。
- `GET /api/v1/lingdoc/rule-sets/{ruleSetID}/versions` 与 `GET .../{version}`：读取当前租户内的版本历史和指定版本。
- `POST /api/v1/lingdoc/rule-sets`：仅创建草稿；拒绝未知 JSON 字段、超大请求、尾随 JSON、客户端发布状态与伪造哈希。
- `POST .../{version}/publish`、`/withdraw`、`/recall`：通过领域状态机推进版本生命周期；发布哈希由服务端计算，撤回/召回保留历史。
- 路由层将生命周期写入限制为租户 Owner/Admin；存储层在数据库事务中重新读取 `tenant_members`，拒绝非 active 成员及非管理员写入。版本数据与审计记录同事务提交。
- 所有路由已接入 LingDoc router、API-key full-access 路由策略和共享 OpenAPI；响应使用统一的 `data/request_id/meta` 或 `error/request_id` 外壳。
- 修复 PR #151 独立复核指出的三项边界：RuleSet 发布/绑定前拒绝空及未知 severity；ID/version 的领域与 OpenAPI 上限统一为 64 字符，与 SQLite/PostgreSQL 迁移一致；审计 `target_id` 使用 64 位十六进制 SHA-256 标识，完整 ID/version 保留在审计详情中。
- 回归用例覆盖无效 severity、64/65 字符边界，以及最大合法 ID/version 下的 SQLite 审计写入；另为隔离 PostgreSQL 集成测试加入同一最大长度反例。

## 未完成（Issue #140 仍需后续切片）

- `TemplateVersion` 尚未引用确切 RuleSet 版本；本切片只允许草稿项目副本显式绑定已发布的精确版本。
- `ProjectTemplateCopy` 已保存完整的不可变 RuleSet 快照；项目编辑不能绕过该快照修改旧版内置规则。本切片尚未实现受限 binding 覆盖配置。
- Template Check 与 Preflight 现已按 `preflight` 场景消费副本快照，并以模板规则与 RuleSet 身份/版本/哈希形成的组合哈希标识结果。
- ValidationIssue 的问题 ID 和规则集哈希会随上述组合哈希固定；ReleaseSnapshot 冻结输入包含同一完整 RuleSet 快照。导出读取冻结后的阻断结论并拒绝不通过的快照，不再依赖“当前规则集”。
- 尚未完成从 HTTP 绑定到规则检查、快照及导出的完整 Docker 端到端验收，也未覆盖并发项目绑定及绑定审计的独立数据库读回。

因此 PR #151 应保持 Draft；TemplateVersion 引用、受限 binding 覆盖、端到端重启与并发验收仍未完成，不能据此宣称 #140 已完成。
