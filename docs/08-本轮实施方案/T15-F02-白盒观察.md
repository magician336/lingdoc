# T15-07：F02 的「未发生」被验证

状态：2026-09-27 完成。对应 issue #34。F02「空资料不扩大范围」现在有明确的 `F02-WB-01` 白盒观察点；真实 HTTP 请求与白盒依赖计数写在 [T15-S8 验证报告](T15-S8-验证报告.json) 和 [运行证据](T15-S8-证据.json)。

## 契约与观察范围

`contracts/scenarios.json` 将 F02 声明为唯一允许携带 `white_box_observation` 的场景，并指向 `TestStartEmptyAssetScopeHasNoDownstreamEffects`。测试对 `generation.Service.Start` 的依赖接缝计数：输入解析、幂等读取、运行记录创建、任务入队和模型调用。空 `asset_ids` 请求必须在所有这些下游边界前以 `ErrInvalidRequest` 返回，五个计数全为 0。

白盒观察只读，不修改服务实现。HTTP 报告与白盒结果分开记录：真实服务只证明 S1 起点读回吻合且 `startGeneration` 返回 `400 invalid_request`；五个“未发生”结论来自同一 `Service.Start` guard 的依赖计数测试，不冒充真实服务进程内探针。输入解析器是通往知识检索的服务依赖，因此计数为 0 能说明该路径没有被调用；它不声称拦截或观测任意进程外搜索。

执行器对 F02 强制要求计数对象的键与契约清单完全一致、每项为整数零。其它场景声明白盒观察点会被静态校验和执行器拒绝。这样“未发生”的结论不能从 HTTP 400 推断，也不能漏掉白盒证据后仍报告通过。

## 复现

确认本机 8080 的 LingDoc 服务可用，并准备 gitignored 的 `.scratch-t15-03/env_facts.py`（只在本机使用）。运行：

```text
python scripts/lingdoc_mock/run_f02_white_box.py
```

脚本先从本机 fixture 登录，然后调用场景报告器。报告器会在任何起点写入前直接执行契约声明的 Go 观察器；只有进程退出成功、恰好输出一条 JSON 计数记录且五项全为 0，才继续写入真实服务起点并驱动 F02。没有外部计数注入参数，凭证只在进程内，不写到仓库或报告。

## 实测

- Go 白盒测试：PASS；`input_resolver_calls`、`repository_find_replay_calls`、`repository_create_run_calls`、`enqueue_calls`、`model_generate_calls` 均为 0。
- 起点 S1：项目已立项、`spec_revision=1`、两章均无版本、绑定资料为空；真实服务读回 `mismatches: []`。
- F02-01：`startGeneration` 返回 HTTP 400；`/error/code` 为 `invalid_request`；报告判定通过。
- 服务端生产代码未修改。白盒边界是应用内 `Service.Start` 依赖计数，真实 HTTP 报告不包含运行进程的模型、检索或数据库探针。

复核与回归命令及其结果见 issue #34 的提交记录；真实 HTTP 与白盒证据由本节链接的 JSON 保留。
