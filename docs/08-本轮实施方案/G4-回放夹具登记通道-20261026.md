# G4 回放夹具登记通道（Spec #768，票 #769 + #771）——波次文档

日期：2026-10-26。基线：`g4-fixture-registration-int`（含 #769 全部工作）+ `g4/771-ruleset-projection`。
本文补齐 #769 交接遗留的波次文档，并作为 #772（前端）的接口形状交接。

## 1. 通道架构（两票合并视图）

回放夹具登记通道是发布门禁的运行期治理入口，替代"仅部署期配置装载"的旧决定（Spec #768 修订声明）：

- **一个登记操作**：`templategovernance.Service.registerFixtures`（fixtures.go）。形状校验（400 边界）、试放（`JudgeReplayFixture`，422 证据族）、append-only 批量插入、幂等（治理操作表）、成功/失败审计只在该操作实现一处。两个 HTTP 端点都是它的薄拼写，差异仅在"回放目标"的解析（D3）：
  - 模板路径（#769）：`Service.RegisterFixtures` — 回放目标 = 存储的 draft 模板版本本身。
  - 规则集路径（#771）：`Service.RegisterRuleSetFixtures` — 回放目标 = **投影版本**：`ruleReplayVersion`（rule_catalog.go，规则集发布用的同一个投影函数）把回放底版定义重绑 draft 规则集并重算内容/策略摘要；底版为内置 demo 模板时走其 demo 分支，无存储版本前置（引导路径）。
- **一条存储与判据**：`ReplayFixtureStore`（mergedFixtureStore：内置集=内存后端 + 租户行）+ `JudgeReplayFixture`/`JudgeReplayCoverage`（replay.go，发布 Verify 提取出的共享判定）。登记回执、覆盖读回、发布 Verify 三方对同一输入同结论。
- **pin 语义**：夹具行以 (tenant, template_id, version, content_hash, fixture_id) 为主键，另存 ruleset 引用与 policy_hash。底版/规则集草稿内容变化 ⇒ 投影/版本内容摘要变化 ⇒ 旧行自然失活；发布侧 `Verify` 的 pin 预检以 `FixturesForPin`（按当前 pin 精确取集合）回答，存在但 pin 不符 ⇒ `ErrStaleReplayPin`（422 template_replay_required，明示"对当前 pin 重新登记"）；从未登记 ⇒ 422 replay_required。**重登记=对当前 pin 重新提交同 id 批次**（append-only，旧行保留）。

## 2. 端点与请求/响应形状（#772 前端交接）

前缀：`/api/v1/lingdoc/template-catalog`。所有写操作要求人工账号（机器主体 403 `human_decision_required`）+ `Idempotency-Key` 头（8-128 字符）。

### 2.1 规则集路径登记（#771 新增）

`POST /template-catalog/rulesets/{rulesetId}/versions/{version}/replay-fixtures`

请求体 `RegisterRuleSetFixturesInput`：

```json
{
  "ruleset_id": "org-rules",          // 与路径一致
  "ruleset_version": "1",
  "template_id": "template-demo",     // 回放底版；引导路径用内置 demo
  "template_version": "1",
  "fixtures": [{
    "fixture_id": "org-reg-...",      // 不得与内置集 id 精确冲突（400）
    "rule_id": "goal-present",        // 必须是 draft 规则集中启用的绑定
    "scene": "write_check",           // write_check | preflight
    "polarity": "positive",           // positive | negative
    "target_ref": "field/research_goal",
    "input": { "project_id": "...", "target_version": "1", "fields": {...} },  // template.EvaluationInput
    "expected_status": "PASS",        // computed 系→PASS/ISSUE；model_assisted→UNKNOWN
    "review_reference": "review:..."  // 复核依据，必填
  }],
  "reason": "治理理由"
}
```

201 响应 `data` = `RegisterFixturesReceipt`（与模板路径同一形状）：

```json
{
  "template_id": "template-demo",     // 回放底版（=投影所在版本）
  "version": "1",
  "content_hash": "…",                // 投影内容摘要（服务器固定）
  "policy_hash": "…",
  "projection": {                     // 仅规则集路径返回；模板路径无此字段
    "ruleset": { "ruleset_id": "org-rules", "version": "1", "ruleset_hash": "…" },
    "replay_base": { "template_id": "template-demo", "version": "1" }
  },
  "registered": [{ "fixture_id": "...", "rule_id": "...", "scene": "...", "polarity": "...", "target_ref": "...", "ruleset": {...} }],
  "coverage": { "complete": false, "entries": [...], "unsatisfied_declared_example_refs": [...] }
}
```

幂等二态：同键同请求重放同一回执（`meta.replayed=true`）；同键异请求 409 `template_governance_idempotency_conflict`。草稿变更后重放同键 ⇒ 409 `template_governance_version_conflict`。

### 2.2 模板路径登记（#769，未变）

`POST /template-catalog/profiles/{templateId}/versions/{version}/replay-fixtures`，体 = `{template_id, version, fixtures, reason}`；回执同上但无 `projection`。

### 2.3 覆盖读回（#769 建端点，#771 加投影查询参数）

`GET /template-catalog/profiles/{templateId}/versions/{version}/replay-coverage?ruleset_id=&ruleset_version=`

- 无查询参数：该模板版本当前 pin 的覆盖矩阵（`ReplayCoverageView`）。
- `ruleset_id` + `ruleset_version` 成对给出：改读"该 draft 规则集经发布同一投影函数在当前底版上算出的投影"的覆盖矩阵——视图 `content_hash/policy_hash` 为投影 pin，`projection` 字段携带规则集与底版引用；两参数只给一个 ⇒ 400。
- 管理者专属；非管理者防枚举 404；机器主体 403。

### 2.4 错误形状（与发布同族）

400 `invalid_request`（形状/语义/内置 ID 冲突/超限，零写入）；403 `human_decision_required`；404 防枚举（附 `permission_denied` 失败回执）；409 `template_governance_idempotency_conflict` / `template_governance_version_conflict`；422 `template_replay_required`（试放证据/覆盖不全/旧 pin 失活）；503 `template_governance_unavailable`（fail-closed）。

### 2.5 审计

Action `lingdoc.template.register_fixture`。成功与失败都留 `audit_logs` 回执；details 恒携带 `ruleset` 引用，规则集路径另携带 `replay_base` 引用（D10 双引用）。管理员审计历史 `GET /template-catalog/profiles/{templateId}/audit-events` 的白名单含该 action，且按 `details.replay_base.template_id` 把规则集路径事件归入底版模板的历史（双方言 SQL：SQLite `json_extract` / PG JSONB 路径）。

## 3. #771 实施摘要

- `internal/lingdoc/templategovernance/fixtures.go`：`RegisterFixtures` 重构为单操作 `registerFixtures`（`registrationRequest` 参数化回放目标解析、幂等目标、审计身份）；新增 `RegisterRuleSetFixtures`、`RulesetProjectionRef`/`ReplayBaseRef`/`RegisterRuleSetFixturesInput`/`RuleSetCoverageQuery`；回执/视图增加 `projection`（omitempty，模板路径字节不变）；`ReplayCoverage` 增加投影查询参数。

- `internal/lingdoc/workspace/template_governance_routes.go`：`POST /rulesets/:rulesetId/versions/:version/replay-fixtures`；coverage 处理器读 `ruleset_id`/`ruleset_version` 查询参数。
- `internal/lingdoc/templategovernance/audit_history.go`：白名单已有 register_fixture（#769）；新增 `replay_base.template_id` 匹配（双方言）。
- `docs/08-本轮实施方案/contracts/openapi.json`：补登规则集登记端点、coverage 查询参数、`RegisterRuleSetFixturesInput`/`ReplayBaseRef`/`RulesetProjectionRef` schema 与结果/视图的 `projection` 字段。
- 无新表、无新迁移（复用 #769 的 `lingdoc_template_replay_fixtures`，形状守卫已登记）。
