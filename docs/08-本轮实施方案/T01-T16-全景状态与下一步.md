## 建议执行顺序

### 1. 以当前 `main` 重建红项账本

不要再等待 PR #25 合并。以 `d04ac58` 为基线，重新运行撤权读取、撤权下载、未就绪资料、生成警示、确认/冻结和失败恢复场景；历史 200 响应和旧 F15 结果只作为修复前证据。

### 2. 完成 Beta 真实验收环境

固定真实模型、授权资料、PostgreSQL/SQLite 运行方式、服务重启步骤和第二人复现命令。WSL2 与 Windows 的 toolchain 限制要单独记录；真实文件必须在 Word/WPS 可用环境中打开、编辑、保存和重开。

### 3. 运行当前 HEAD 的 F01 和浏览器流程

针对 `d04ac58` 执行完整 23 步 F01，并在浏览器跑通项目、资料、生成、候选采纳、章节编辑/确认、冻结和 DOCX 下载。每个未运行场景继续写 `NOT RUN` 或 `BLOCKED`，不能用 CI 绿灯代替。

### 4. 更新交接与矩阵证据

将新运行结果写入当前基线对应的验收报告，区分代码已合入、自动化 PASS、真实服务 PASS、人工文件 PASS 和仍未运行；再判断是否达到 Beta 首版可试用门槛。
