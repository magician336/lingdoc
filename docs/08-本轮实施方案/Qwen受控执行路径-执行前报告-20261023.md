- 不要求 DeepSeek 的 provider 白名单（`provider == "generic"`）；

### 4.2 「没有 usage 就记 unavailable，不推算冒充」

- 生成路径判定：`internal/lingdoc/workspace/generation.go:558` —— 无 usage ⇒ `reservation.unknown("usage_unknown")`。

- 有 usage 时：`usage_status = "reported"`，输入/输出/总分别是 provider 的数（provider 没给 total 时，total 取它给的两个计数器之和 —— 这是对**已上报数字**做加法，不是估算请求）。

### 4.3 费用列的口径（不伪造）

- Qwen profile：`cost_basis = "not_applicable"`，费用列恒为 0，含义是「**没有计价口径，未核算**」；`pricing_basis` 写成一句人话「No price basis: this profile controls tokens and call count, and no money amount is computed.」（`internal/lingdoc/workspace/generation_qwen_acceptance_budget.go:138`）。

## 7. 失败后不会自动重试、不会产生第二次请求

### 7.1 代码链

- `internal/lingdoc/generation/service.go:557-561`：模型失败 ⇒ `Repository.Fail(...)` ⇒ **`return failed, nil`** ⇒ handler 看不到 error。
- `internal/lingdoc/generation/tasks.go:130-146`：handler 只在 `err != nil` 时才考虑重试；`err == nil` ⇒ 直接 ACK（`return nil`）。
- `internal/lingdoc/generation/tasks.go:33,49`：`asynq.MaxRetry(3)` 是兜底预算；`tasks.go:79` `taskFailureRetryable` 对 4xx 等永久失败返回 `asynq.SkipRetry`（PR #521）。
- 受控路径自身：失败 ⇒ `reservation.unknown("outcome_unknown")` ⇒ 账本 blocked ⇒ 下一次尝试在 `reserveChat` 就被拒（`generation_acceptance_budget.go:199`），**不会走到 provider**。

### 11.2 「若今天就要执行一次受控 Qwen 调用，还缺哪几项」

1. **L5 协调项（阻塞项，本轮主动停下）**：`internal/lingdoc/workspace/generation.go:405` 的 `facts.reservedNanoUSD = generationAcceptancePerCall` 仍会把 DeepSeek 的单次预留额（12,000,000 nano-USD）写进 Qwen 的 `generation_run` 行。**要么**由管理会话授权改这一行（1 行，profile 感知），**要么**明确接受「DB 行费用列在 Qwen profile 下无意义，必须与 JSON 账本（`cost_basis=not_applicable`）一起读」这一口径，并把它写进验收记录。
2. **凭据可用**：`SYSTEM_AES_KEY` 与库中密文同源且长度 32；`LLM_API_KEY` 为明文同值（⛔ 不能写 `${DASHSCOPE_API_KEY}`）；启动日志里没有 `[crypto] … decrypt failed`。
3. **模型行存在**：`models` 表里有一行 `type=KnowledgeQA`、`name=qwen3.8-flash`、`provider=aliyun`、`base_url` 与白名单逐字一致；且它是**唯一**一行满足此条件（两条同名 ⇒ 选择器 fail closed）。
4. **窗口静默**：队列 pending/active 为 0；执行窗口内没有用户 chat、没有 KB 摄入/摘要、没有 wiki 任务、没有模型调试端点调用；执行前后各留一次只读快照。
5. **现场单次授权**：真实调用需要单独授权（本轮没有）。授权后按下面的核对表逐项对账，任何一项对不上就**立即停止并报告**：
