## 5. 口径定义（不可变契约）

服务端 `RuntimeMetrics.counts` 的键是 `category/status`（`runtime_control.go:421`）。category 白名单 12 个、status 白名单 10 个（`runtime_control.go:337`）。

| 指标项 | 口径（counts 键） | 备注 |
|---|---|---|
| 异步失败 | `task/failed` | 「异步」限定为 category `task`；G6 计划 §7 把 ChangeSet / ImpactTask / 稳定化结果单列 |
| 异步重试 | `task/retry` | |
| 陈旧结果 | `task/stale` | |
| 重复副作用 | `task/duplicate` | |
| 权限拒绝 | 所有 `*/rejected` | 包含 `download/rejected` |
| 撤权拦截 | 所有 `*/revoked` | 包含 `download/revoked` |
| 下载再鉴权 | `download/rejected` + `download/revoked` | **是「权限拒绝」「撤权拦截」的下集**，UI 必须标注该关系 |
| 预检问题 | `preflight/failed` + `preflight/rejected` + `preflight/conflict` | 只统计问题类状态——**成功的预检不是问题**；其中 `preflight/rejected` 同时计入「权限拒绝」 |
| 导出损失 | 所有 `*/loss` | |
| 外部依赖不可用 | `dependency/unavailable` | |
| G5 allow/deny | **无对应键** | 后端 status 白名单里没有 allow / deny；显示「后端未提供该项观测」，不伪造 0，不改名硬凑。界面文案保留 G5 归属（「G5 授权判定（allow/deny）」），不改成泛指的「权限放行与拒绝」 |

**缺观测的表达**：某项的全部复合键在 `counts` 中不存在 → 显示「无观测」；键存在但值为 0 → 显示 0。服务端 `metrics.missing`（例如 P95/P99 缺样本时的 `latency_p95_p99`）必须一并消费。

**完整展开表**是权威视图，定向汇总只是它的投影；两者同时呈现。
