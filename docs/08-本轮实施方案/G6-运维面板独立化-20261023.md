## 1. 目标

把 G6（运行观测 + 真实试用）的前端从 G3 的面板里**独立出来**，并让值班人员在 Workspace 里有自己的入口位——不必先进「变更与运行质量」再切 tab。

## 2. 前提事实（2026-10-23 核实）

- G6 的端点与类型此前寄生在 G3 的文件里：`frontend/src/api/lingdoc/mainlineChanges.ts`
  （16 个 G6 端点函数与全部 G6 类型，与同文件里的 G3 段：变更集、影响任务、语义草稿、计算回执混在一起）。
- G6 的界面此前寄生在 G3 的面板里：`frontend/src/views/lingdoc/ImpactOpsPanel.vue`——
  四个 tab（正式变更 / 依赖与影响 / 运行与恢复 / 真实试用）挤在一个 600+ 行的组件里。
- PF-1（#325）刚交付的 G6 指标口径表 `frontend/src/views/lingdoc/runtimeMetrics.ts` 也在 G3 面板的目录里，
  且**它用相对路径读后端 Go 源**核对词表：
  ```
  new URL('../../../../internal/lingdoc/workspacecore/runtime_control.go', import.meta.url)
  ```
  ⇒ **移动它或它的测试文件时，这个相对路径会失效**，必须同步更新并实跑确认守护仍成立。
- Workspace 的挂载机制：`frontend/src/views/lingdoc/Workspace.vue`——`FullPanel` 联合类型、
  抽屉、`fullPanelLabel`、触发按钮、组件 import、ref 声明。
- **本分支与 main 的关系**：本分支基于最新 `origin/main`（`a1d817ff`）。main 在 PF-1 交面之后
  又长出了 owner 可用性（PF-4 / Spec #49：归档能力、`OwnerUnavailableNotice`、`useOwnerAvailability`）
  与研究提案（PF-5）等改动，其中 `ImpactOpsPanel.vue`、`ImpactOpsPanel.test.js` 与
  `Workspace.vue` **本分支也要改** ⇒ 这三个文件按 hunk 手工合并：
  - `ImpactOpsPanel.vue`：保留 main 的 `OwnerUnavailableNotice` 与 `ownerActionsFrozen`
    （Owner 应用 / 驳回两个按钮的置灰条件），删掉 G6 搬走后遗留的 `runtimeMetrics` 导入；
  - `ImpactOpsPanel.test.js`：模块桩清单里删掉 `./runtimeMetrics`（G6 已搬走），
    保留 `@/composables/useOwnerAvailability`（main 新增）；
  - `Workspace.vue`：保留 main 的 `ProjectArchivePanel` 与 `OwnerUnavailableNotice`，
    另加 G6 面板的挂载位。

## 3. 范围与边界

### 3.1 保留路径的授权

`frontend/src/views/lingdoc/Workspace.vue` 是**保留路径**，归集成点所有。票面原写「未获授权前不要改」。

**维护者已在本轮显式授权**（2026-10-23 问卷裁决：「本轮做 #384，我显式授权你改 Workspace.vue」）。

但仍有一条约束：**只加 G6 面板的挂载位，不顺手重构 `Workspace.vue`**。

⚠️ 已知的前置风险：PF-6（#330）将来集成时也要改 `Workspace.vue`，两边会撞车——这正是票面原本要求
「等前端面落地后一起做」的原因。本轮由显式授权覆盖，但 PF-6 的执行者需要知道 `Workspace.vue` 已被本票动过。

**与 `PF6之后的下一批开票定稿.md`（PR #447）的关系**：那份定稿把本票判为「等候选 1（编号 52，工作台入口
与面板路由模型）开票 **且** 等 PF-6 落地之后」再开工，并打算加一条 `#384 blocked_by 候选 1` 的原生依赖边。
**本轮按维护者显式授权提前交付**（只加挂载位，不重构 `Workspace.vue`）⇒ 那条依赖边**没有加**（本票已交付，
指向未开票的依赖会让一张已完成的票永远显示为被阻塞），但 PF-6 与候选 1 的执行者必须知道：
`Workspace.vue` 里已经有 `'operations'` 这个面板成员与它的挂载位；候选 1 的「面板可注册」模型要把它收编进去。

### 3.2 命名约束（硬）

main 刚完成编号命名收口（Spec #48），命名登记表 `scripts/lingdoc_naming_registry.py` 的棘轮基线已降到
**0/0/0**——**新增任何 legacy 文件或标识符都会打破棘轮**。

规则见该文件的 `FILE_DEFECTS`：

| 规则 | 含义 |
|---|---|
| `numbered` | 名字里带工作编号（G1–G7、Spec 号等）——**禁止** |
| `frontend_camel` | 前端 `.ts` 文件名必须 camelCase |
| `frontend_vue_case` | 前端 `.vue` 文件名必须 PascalCase |
| `numbered_identifiers` | 文件体里定义带编号的标识符 |
| `weak_name` | 临时名、调试残留、纯 copy 之类 |

⇒ **不能**建 `g6Runtime.ts` / `g6Trial.ts` / `G6OpsPanel.vue`。本面采用的命名：

| 新文件 | 形状 | 承载 |
|---|---|---|
| `frontend/src/api/lingdoc/runtimeControl.ts` | camelCase ✓ | 运行控制（pause/resume）、事件、指标、告警、告警规则 |
| `frontend/src/api/lingdoc/trialWindow.ts` | camelCase ✓ | 试用窗口全套（窗口、样本、报告、决策、签署） |
| `frontend/src/views/lingdoc/RuntimeOpsPanel.vue` | PascalCase ✓ | G6 运维面板（运行与恢复 + 真实试用两个区块） |

命名登记表只登记**违反规则**的文件；合规的新文件不需要登记，但
`python -m unittest discover -s scripts/ci -p 'test_lingdoc_naming_registry.py'` 必须绿。

### 3.3 行为不变

拆分后 G6 的行为必须与拆分前**完全一致**：

- 指标视图：十二项定向汇总 + 完整 `counts` 展开表 + 「无观测」/「后端未提供」的诚实表达
  （拆分后口径表又接上了后端补的 `permission/deny` 观测，见 §5 的 M5）；
- 暂停 / 恢复：5 种运行范围（tenant / project / template_version / ruleset_hash / runtime_mode）、
  CAS 版本、恢复前的复验（快照 current + check=passed + 导出属于该快照）；
- 运行事件链（按 `correlation_id` 过滤）、告警与告警规则表单；
- 试用窗口：创建 / 锁定 / 暂停 / 关闭、样本记录与人工裁定、决策提案与三方签署；
- epoch / 身份过期守卫（`epoch` 计数器 + `readSequence` + `currentIdentity`）；
- `mutate()` 的幂等键复用（同 payload 复用同一把键，成功后清槽）；
- 只读默认（`readonly` prop 默认 `true`）。

## 4. 不可变契约

- `mainlineChanges.ts` **只留 G3 段**（变更集 / 影响任务 / 语义草稿 / 计算回执），G6 段整体搬走，
  **不得**留下两套并行的 G6 客户端。
- `ImpactOpsPanel.vue` **只留 changes / impacts 两个 tab**，G6 的两个 tab 搬进 `RuntimeOpsPanel.vue`。
- `Workspace.vue` 的 `FullPanel` 联合类型加一个成员（本轮取 `'operations'`，不用带编号的 `'g6'`——
  编号不表达知识），并加挂载点、`fullPanelLabel` 条目与触发按钮。
- G6 契约断言从 `frontend/src/api/lingdoc/mainlineChanges.test.js` **迁移**到新模块的测试文件
  （`runtimeControl.test.ts` / `trialWindow.test.ts`），断言内容不变——16 条路径、路径编码、幂等键、响应外壳。
- `runtimeMetrics.ts` 及其测试**未移动文件**：口径表与它的测试都留在 `views/lingdoc/`，
  读后端 Go 源的相对路径原样有效（M5 实跑确认）；口径表**内容**随后端补的 `permission/deny`
  观测演进（见 M5）。
- **合并带来的既有能力保留**（本分支基于最新 main）：`ImpactOpsPanel.vue` 的
  `OwnerUnavailableNotice` 与 `ownerActionsFrozen`（Owner 应用 / 驳回置灰）、
  `Workspace.vue` 的 `ProjectArchivePanel` 与 `OwnerUnavailableNotice` 全部保留，
  G6 拆分没有削弱它们。
