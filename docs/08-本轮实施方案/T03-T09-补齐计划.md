# T03 / T09 补齐计划

## 目标

在 #4 工作区基础合并后，保住 T03 的检索、来源定位和证据契约，并把 T09 从领域实现推进到可被工作台消费的资料与来源能力。

## 执行顺序

1. **基线保护**：合并 T09 领域实现时保留 T03 的 `internal/evidence`、F22、S7 证据和来源锚点 ADR；迁移版本与 #4 的工作区迁移不重复。
2. **领域交接**：确认 `AssetGateway`、`SourceResolver`、`SourcePolicy.Validate` 的接口和报告一致，补上重解析版本与跨项目归属的回归断言。
3. **HTTP 接入**：在现有工作区路由上接入资料绑定、允许集合和来源复核；复用工作区幂等存储；固定错误信封、F02/F07/F22 语义和项目不可见 404。
4. **权限与原文适配**：接入当前项目成员权限、知识库读取权限和 `UsesBuiltinConverter`；无法证明原文逐字一致时保持弱定位。
5. **界面切片**：在工作台中挂资料选择、就绪/授权状态和来源定位，覆盖加载、空、拒绝和错误状态。
6. **验证与交接**：运行领域、HTTP、前端类型检查及完整测试；更新 T03/T09 报告，明确真实失败回路、解析产物和 PG runner 等仍未覆盖项。

## 当前切片验收

- T03 文件和 F22 在合并后仍存在，契约测试通过。
- T09 领域测试通过，`SourcePolicy.Validate` 可复核已产出的来源。
