### 1. 先处理安全与授权红项

先修 T08/T09 的 `listChapters` 撤权后读取，以及 T14 的 `downloadExport` 撤权后下载。F07 与 F19 的观测都显示当前请求成功返回 200，不能只依靠现有 CI 绿灯。修复后重跑这两个场景，并把真实运行报告更新为新证据。

### 2. 补齐 T09 与 F15 的修复后验证

修正 T15-10-R1 的未就绪错误分类；对 T12/T13 的 `52651d8` 修复重跑 F15。另行处理 T10 的模型输出缺少警示；这项与确认状态修复是两个不同问题，不要用一个 F15 总结掩盖。

### 3. 完成 PR #25 集成审查

PR #25 当前所有列出的 CI 均通过，但它仍是 Draft、`REVIEW_REQUIRED`、`BLOCKED`。先确保上述真实授权红项已清除并检查修复后的 CI，再完成独立审查、标记 Ready for review 并合入 `main`。

### 4. 更新并合入 PR #39

PR #39 是离线矩阵工具，不会修复运行行为。待新实跑证据进到目标分支后，重建矩阵并更新 PR #39 的 base/提交，使其基于最新集成结果；确认检查通过后再合入。

### 5. 由 T16 做完整用户验收

针对真实测试服务执行完整 23 步 F01，并在浏览器跑通 T07–T14 的两章流程。验收记录至少应覆盖：真实启动方式、登录和资料授权、生成与候选采纳、章节编辑/确认、冻结、DOCX 下载，以及文件实际打开、修改、保存和重开。F06/F09/F13/F14 若仍无法注入或复现，应保持 `not_run` 并写明原因。
