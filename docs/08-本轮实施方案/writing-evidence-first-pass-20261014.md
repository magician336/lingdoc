## 修复及失败归因

1. 后端 Preflight HTTP 适配器把幂等键误传为 proof_id。现按核心契约传入正文回执编号，幂等键独立；真实 Gin/核心服务边界回归验证参数及缺键/机器身份拒绝，不伪造绿色检查。
2. 正式变更未稳定时仍拒绝冻结；现在返回明确的 422 `context_unstable`，指引当前检查回执和 Owner 稳定化。没有放宽权限或绕过阻断。
3. 候选原文按钮此前读取了受保护内容却未显示来源栏；成功且当前项目一致后才展开，拒绝/跨项目晚响应不会展开旧内容。
4. Kimi 修复所选卡删除/清空的旧行残留与读取中状态；Root 补父接线及准确的“取消本次选用”标签，修正测试 props 的未知类型声明。
5. 自动化原始失败保留：稳定化脚本错等“当前基线已稳定”，产品实际是“当前变更已稳定”；下载脚本误等历史按钮；证据回看脚本未等待受保护读取和滚动。后续按真实 200 回执只读复核，不重复稳定化/导出，不改写旧失败为通过。UUID 选择器错误也作为驱动失败保留。DOCX 完整性脚本最初错误要求显示内部待核 UUID；人工查看后改为逐条比较实际候选的待核陈述、四条保留警示与理由，不修改产品或原文件。
