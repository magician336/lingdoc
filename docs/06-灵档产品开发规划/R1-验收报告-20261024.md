## 原路径与新路径

原来：用户离开 LingDoc → 去平台资料库首次上传 → 回项目输入 knowledge_id 或按名称找已解析文件 → 绑定 → 检索。

现在：当前项目“上传与项目资料” → 选择材料库和文件 → 沿用平台上传确认与文件限制 → 观察真实处理状态 → 绑定当前课题 → 用原文关键词核实该绑定材料的项目检索命中。上传、索引、绑定和命中四件事独立反馈，不靠上传成功或 parse_status=completed 放行。

### 曾发现的真实失败，不抹掉历史

main@78f31f16，同一幂等键直接并发绑定时一条201、一条500；请求 `d39dff92-6afc-418c-b9bc-91eaa591953a`，PG报 `lingdoc_operations_pkey / SQLSTATE23505`。原因是两事务都未读到操作记录，后到写入冲突。修复限定原 BindIdempotent：回滚后重新读已提交记录，校验 BodyHash 才重放。SQLite守护、race和修复版真实PG HTTP均通过；最初FAIL日志保留在本轮本地输出目录，不把旧FAIL标成PASS。
