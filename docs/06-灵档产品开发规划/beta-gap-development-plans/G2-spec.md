# G2：项目内依据引用、回看与最小复核

## Problem Statement

课题组作者已能检索项目资料、编辑章节、确认并导出，但章节引用主要由来源 ID 和正文标记表达。作者缺少与章节版本一起保存的用途/限制说明；来源回看与章节写作之间也需要完整的版本、授权与恢复闭环。资料重解析、来源消失或撤权后，旧引用及旧确认不能继续被当作当前有效依据。

本 spec 按第二阶段减量范围交付 G2 的依据回看切片，不承诺完整证据工作台或调研智能体。

## Solution

作者在现有章节工作台中选择或复用项目内允许的来源片段，查看来源版本、定位与上下文，并可填写用途/限制备注。显式保存时，正文、引用和备注共同形成不可变章节版本。重新打开章节时，系统重新核对授权、资料版本和定位，展示可用、待核或不可用状态及恢复动作。

引用变化后需要重新确认。失效或撤权来源不能借备注、旧缓存或旧确认进入当前生成、冻结及交付流程；历史版本保留，历史读取仍受当前授权约束。

## User Stories

1. As a 课题组作者, I want 选择项目内已授权且就绪的资料片段, so that 我能为章节保留可追溯依据。
2. As a 课题组作者, I want 从已有章节复用引用, so that 我不必重复寻找同一片段。
3. As a 课题组作者, I want 看到来源资料版本和可读定位, so that 我知道依据对应哪份材料。
4. As a 课题组作者, I want 打开引用片段及其允许的上下文, so that 我能核对表述是否脱离语境。
5. As a 课题组作者, I want 知道定位校验的强弱及回看限制, so that 我不会将分块自洽误认成已核对原文件。
6. As a 课题组作者, I want 给每条章节引用补充用途和限制, so that 审阅者理解该依据支持到哪里。
7. As a 课题组作者, I want 允许用途和限制暂时留空, so that 我可以继续写作并明确看到尚未补充的信息。
8. As a 课题组作者, I want 显式保存正文、引用和备注为同一个版本, so that 它们不会彼此错配。
9. As a 课题组作者, I want 自动保存工作副本与正式提交保持区分, so that 备注编辑不会绕过工作副本的版本保护。
10. As a 课题组作者, I want 服务重启后读回已保存引用及备注, so that 我能继续写作。
11. As a 课题组作者, I want 响应丢失后安全重试, so that 一次保存不会生成多个章节版本。
12. As a 课题组作者, I want 并发冲突时保留未提交输入, so that 我能比较后重新提交。
13. As a 课题组作者, I want 移除引用时同步更新正文标记和引用集合, so that 不会留下悬空或隐含引用。
14. As a 审阅者, I want 查看对应章节版本的引用和备注, so that 我的确认针对明确版本。
15. As a 审阅者, I want 引用或备注修改后重新确认, so that 旧审阅结论不会自动沿用。
16. As a 课题组作者, I want 来源版本变化时看到待核原因, so that 我能重新检查并主动选择当前片段。
17. As a 课题组作者, I want 定位失效时系统保留历史记录并提示恢复入口, so that 系统不会静默替换我的依据。
18. As a 项目成员, I want 撤权后受限正文和摘录停止返回并从界面清除, so that 旧缓存不能绕过当前授权。
19. As a 非项目成员, I want 系统按已有策略隐藏项目及来源存在性, so that 我无法读取其他项目的资料。
20. As a 课题组作者, I want 来源授权不确定时明确拒绝敏感操作, so that 故障不会被当作授权成功。
21. As a 课题组作者, I want 旧项目继续读取并默认没有备注, so that 增量升级不会伪造历史确认或丢失既有引用。
22. As a 课题组作者, I want AI 只消费当前允许的来源并保留待核边界, so that 候选材料不会冒充已确认证据。
23. As a 交付负责人, I want 冻结时捕获准确的章节、来源版本及备注, so that 后续编辑不会改变已冻结内容。
24. As a 交付负责人, I want 当前导出及下载继续检查来源权限与当前性, so that 失效或撤权依据无法通过旧交付入口放行。
25. As a 课题组作者, I want 恢复来源后经过重新核对和确认继续导出, so that 我能从失败状态恢复。
26. As a 验收成员, I want 按记录复现两章成功与关键失败流程, so that 可试用结论有真实证据。

## Implementation Decisions

- 复用工作区章节版本写入与读回、evidence 来源复核、生成上下文、确认及交付模块。扩展现有接口优先于另建引用保存服务；客户端无需编排两个独立写事务。
- 引用使用信息表达章节对来源的用途与限制，不升级为 ResearchClaim 或 EvidenceCard，不表示研究结论已成立。
- 用途/限制为可选人工信息。未填写要如实展示；不能因填写备注而提高来源校验等级或绕过权限。
- 引用和备注随不可变 ChapterVersion 保存。正式修改创建新版本并使旧确认不可用于新版；工作副本自动保存仍沿用 G7 的检查点与显式提交规则。
- 服务端取得真实操作者、资料版本和来源校验结果。客户端来源状态、授权结论、时间和创建者不能作为可信输入。
- 正文来源标记、source_ids 和引用备注的归属必须一致；拒绝备注指向本章节未引用的来源。删除引用时同步移除新版使用信息，保留旧版记录及待核历史。
- 章节写入、引用信息和幂等结果共享原子事务与预期章节/条件版本；相同键同请求重放前仍核对当前权限，相同键不同请求拒绝。
- 需要增量持久化字段或表，并提供 PostgreSQL/SQLite 对称版本迁移与旧数据兼容。具体存储形状由实现 ticket 对现有事务的最小扩展决定；本 spec 不预设独立表或独立 CitationUsageStore。
- 实时状态复用 SourcePolicy 的授权、归属、资料版本和定位判据。保留 ADR-0001 的 rune 坐标、强弱两档及序列化失效信息限制；持久化快照不能代替当前复核。
- 来源重解析或定位变化不静默迁移到新文本；撤权/缺源/版本失配不能人工豁免。不可用时保留允许显示的状态与恢复动作，受限正文、摘录和可能泄露内容的备注不得返回。
- 不把章节“已确认”等同于研究主张已证明。有权待核材料沿用既有显式模式与待核项处置；无权材料禁止进入任何 AI 输入。
- 工作台复用现有请求封装、来源面板与保存流程。失败保留允许保留的自写输入；切换项目、退出或撤权后清除受限内容，乱序响应不能写回其他项目或新版本。
- 冻结输入捕获章节对应的引用使用信息，纳入既有完整性校验；旧快照不可原地改写。当前交付与历史交付标签及重新授权下载语义沿用原契约，不把历史快照自动升级为当前。

## Testing Decisions

- 主测试 seam 是现有工作区应用接口：保存章节版本、读回章节与引用、确认及准备交付。测试通过调用者入口观察结果和副作用，不以私有函数调用次数或字段复制验证行为。
- 来源授权/定位变化复用现有 SourcePolicy seam 的固定 adapter 构造反例；生产接线另做真实权限和数据库集成验证。此 seam 方案待用户确认后发布。
- 沿用现有章节保存、来源权限、幂等重放和交付冻结测试的模式：生产迁移创建隔离数据库，竞争写入、重启读回、查询不可变旧版本和副作用。
- 必验成功：新增与复用引用、空备注、填写备注、正式提交、刷新/重启读回、旧版备注不变、重新确认后冻结及真实文件交付。
- 必验失败：跨项目来源、重复或悬空引用、来源版本失配、定位失效、资料未就绪、撤权、授权依赖故障、条件/章节版本冲突、相同键不同请求及响应丢失重试；失败不得产生部分写入。
- 撤权测试检查所有敏感响应及生成/交付输入，不只验证状态码；覆盖受限正文、摘录、用途/限制和历史读取。
- 前端行为测试覆盖取消无写请求、失败保留自写输入、冲突恢复、状态提示、退出/撤权清理和乱序响应隔离；类型检查与构建验证 adapter 契约。
- 持久化验证同时覆盖 PostgreSQL 和 SQLite 的生产版本迁移、兼容旧项目、约束及事务一致性；不可用环境记录 BLOCKED/NOT RUN。
- 两章连续流程由第二人复现；真实授权来源、重启恢复、撤权/重解析及恢复后确认与导出必须实际执行。真实 DOCX 在 Word/WPS 打开、修改、保存并重开。
- 验证记录区分 mock、real_api_fake_model 和 real，逐项记录 PASS/FAIL/NOT RUN/BLOCKED；本次写 spec 不生成实现通过结论。

## Out of Scope

外部来源发现平台、ResearchTask/ResearchRun、通用调研智能体、ResearchClaim/EvidenceCard、多锚点争议证据体系、自动判断研究结论、解析产物平台、PDF/OCR 新定位能力、完整引文格式系统、通用图谱或权限引擎。G7 工作副本完整实现和 T01–T16 收尾也不由本 spec 接管。
