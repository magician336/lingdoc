# LingDoc 工作台结构评审

这是供团队选择工作台结构的独立交互原型，不替换正式 Workspace 页面。所有正文、来源、核查事项均为合成数据，无产品 API、模型或身份登录。

## 打开与比较

使用 Node.js 22，在仓库根目录运行：

```sh
node prototypes/workbench-layouts/serve.mjs
```

在同一台电脑打开 http://127.0.0.1:5194/ 。服务仅监听回环地址；结束时在启动终端按 Ctrl+C。若端口已占用，请先确认占用进程归属，不要直接结束其他服务。

顶部按钮直接切换三种结构，切换保留当前未保存输入：

- A 研究工作台：章节目录、正文编辑、来源与核查三栏同时可见。
- B 修改审阅台：原文与候选并排，显示差异后选择采纳或放弃。
- C 专注写作台：正文优先，辅助面板按需打开。

建议依次检查：编辑一段后切换 A/B/C 是否保留输入；打开资料和核查视图；选择正文并生成合成改写、查看差异、采纳；逐项核查并确认、冻结，然后下载 HTML 示例；缩窄窗口检查排版与滚动。

“打开真实产品”只是本机 5193 入口的参考链接，原型无需该服务即可运行。生成改写为固定合成示例，不代表模型质量；下载的是 HTML，不是产品 DOCX。刷新仅恢复点击保存后的正文，确认与冻结不冒称服务端持久化。

## 已有验证与复跑

`verification-result.json` 是 **2026-10-09** 的独立 Edge 合成浏览器验证摘要，35/35 通过，附四个静态运行文件的 SHA-256。该记录不是本轮产品 E2E，也不是协作者验收。截图在 screenshots/。

Windows 已安装 Microsoft Edge 时，可在服务启动后运行：

```sh
node prototypes/workbench-layouts/verify.mjs
```

runner 使用独立 Edge profile，结果和临时文件只写入被忽略的 verification/，不操作已打开的个人浏览器。当前入口固定为 5194；非 Windows 环境可先手工评审，不宣称此 runner 跨平台通过。

## 评审范围与后续
