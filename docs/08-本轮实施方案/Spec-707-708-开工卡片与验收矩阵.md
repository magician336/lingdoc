## 开工卡片

**用户可见结果**
贡献者跑一次 Go 测试即可看到表形状守护的第一条闭环：真实 SQLite 迁移链建到最新 → gorm 自己的 schema 解析器读出登记行结构的期望形状 → 逐列比对（列存在性 + 可空性双向 + 类型归一化宽松比对）。守护用红/绿两组样本自证有效性；失败信息同时给出表名、列名与两侧形状。

**范围内**
- `internal/database` 新增守护测试模块（测试文件 + 测试助手），含：
  - 显式登记清单结构定义与清单（本票 1 个真实条目：candidateadoption `adoptionIdempotencyRow` + 表 `lingdoc_candidate_adoptions`；红夹具条目仅用于守护自测，不进生产清单）；
  - 真实迁移链执行（`RunMigrationsWithOptions`，接缝与既有 `TestSQLiteMigrationsCreateVersionedSchema` 相同）；
  - 产物侧形状读取（`PRAGMA table_info`）；
  - 判定规则（唯一出处，集中注释在守护文件一处）+ 三类红样本 + 绿样本。
- `docs/08-本轮实施方案/` 文档（本文件）。

**范围外**
- 任何生产代码、既有迁移内容、既有守护测试断言的改动（零运行时变更红线）；
- AST 扫描「未登记 = 红」（#709）、PostgreSQL 侧比对（#710）；
- 外键/索引/触发器/default 值的形状比对；受检清单扩到全部 51 个行结构；
- codegen 路线（Spec #707 明确留作后续演进）。

**前置依赖**
- 无阻塞前置；#709（清单交叉强制）以本票清单结构为基线，#710 复用同一套判定语义。

**真实消费者**
- 本地开发者与 CI（app 工作流 verify job：全 Go 构建+测试，天然执行本守护测试）；
- #709/#710 子票（清单结构、判定语义、失败信息格式的复用方）。

**领域不变量与事务边界**
- 期望侧唯一出处：登记行结构的形状只来自 gorm 自己的解析器（`schema.Parse`，即 gorm 执行写入/建表所依据的同一份知识），不重抄、不 mock；
- 产物侧唯一出处：真实迁移链执行产物（`RunMigrationsWithOptions` 建到最新 → `PRAGMA table_info`），不许手造假 schema；
- 判定规则唯一出处：列存在性 / 可空性双向强制 / 类型归一化表 / 长度规则全部集中在守护文件一处注释+代码，任何调整只改这一处；
- 红夹具与生产清单分离：故意不匹配的夹具登记项只存在于守护自测中，永远不进生产受检清单，避免守护自身常红；
- 只读检查：不写任何生产路径、不进启动路径、不改数据。

**成功 / 失败 / 恢复场景**
- 成功：登记行结构与迁移产物逐列一致 → 守护零违规；
- 失败（三类红，全部走真实迁移链产物）：
  1. #693 形态：值类型 + `not null` 声明 ↔ 实际可空列；
  2. 反向可空性：指针字段（无 `not null`）↔ 实际 NOT NULL 列；
  3. 列存在性：结构体声明了迁移产物中不存在的列；
  4. 类型：声明类型与产物类型归一化后不同族；声明类型不在归一化表内（棘轮：补规则，不许静默放过）；
- 恢复：守护只报告不修改；修复路径 = 改漂移的那一侧（迁移或行结构），或（对未知类型）按注释在归一化表补规则。

**持久化 / 并发 / 审计证据**
- 持久化：迁移链建库到版本 56（fresh 临时库，不触生产数据）；
- 并发：N/A（纯只读守护，无并发语义）；
- 审计：N/A（无用户可见状态变更）。

**当前风险与未决决策**
- 风险 1：真实行结构 `adoptionIdempotencyRow` 是 candidateadoption 的**非导出类型**，且本票禁止改生产代码 → 采用「store 既有导出 API（`AutoMigrate`）在一次性测试库上触发 gorm 解析 + 从 gorm `Config.cacheStore`（reflect/unsafe 只读）捕获解析结果」的测试侧机制。若未来 gorm 升级改动 `cacheStore` 字段，守护会**显式失败**（找不到解析结果报错，不静默跳过），届时的解除动作是把该机制改为导出助手（如 workspacecore `AuditEventRowColumns` 先例，#709/#710 可一并做）。已记入矩阵风险行。
- 风险 2：Windows 本机 cgo/gojieba 级 init 崩溃属已知环境限制；`internal/database` 预计不受影响（仅 cgo sqlite），如遇崩溃按规则如实登记并尝试 WSL2，CI（app verify job）为权威证据。
- 无未决业务规则。
