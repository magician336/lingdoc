# G5-C7：兼容层收尾与复杂度验证

> 对应 GitHub Issue [#179](https://github.com/magician336/lingdoc/issues/179)，父 Spec [#177](https://github.com/magician336/lingdoc/issues/177)。
> 本票只收尾 C1–C6 已完成的接口收敛，不新增权限、路由、UI、数据库表或业务流程。

## 1. 审查基线与方法

审查基于集成分支 `codex/g5-complexity-convergence` 的 C1–C6 tip（`553706b`）。先用 CodeGraph 建立调用关系，再用 `rg` 对生产 Go 文件（排除 `*_test.go`）复核，最后按 Workspace、generation、candidate adoption、delivery 四个消费面运行行为测试。

CodeGraph 在本工作树重新初始化并完成索引；`codegraph sync` 在本票提交前重新执行。消费者清单记录的是生产代码调用方；测试替身单独列出，不把测试依赖误判为生产依赖。

- `workspace.CoreProjectAuthorizer` 与 `workspace.NewServiceWithAuthorizer/WithAudit/WithAuditMode`：仅为旧 re-export，仓内无生产调用方；核心构造器仍保留在 `workspacecore`，因为容器尚未迁移。

## 3. 复杂度回归结论

- **模块接口**：HTTP Handler 只保存 `ProjectApplication`、`MembershipApplication`、`ChapterApplication`、`TemplateApplication`、`ChangeSetApplication` 等 focused ports；`ApplicationService` 只在兼容边界和跨模块适配器出现。
- **事务边界**：mutation callbacks 通过 operation-specific ports 获取能力；`Transaction` 只在 Repository、读侧、授权和 runner 处出现，未再向业务 callback 扩散。
- **授权边界**：Workspace 内部使用 `AuthorizationRequest` / `AuthorizationPolicy`；旧 capability 字符串只在兼容和审计边界生成。
- **来源边界**：`sourcepolicy.Reviewer` 负责唯一判定，消费方只把 `Verdict` 映射成自己的错误或展示状态；没有新增第二份授权规则。
- **操作编排器**：`operationDescriptor[I]` 保留受控 operation name、具体输入和来源解码器；持久化 identity 仍保持旧字符串格式，确保既有 replay 数据可读。

## 5. 范围与风险

本票没有改变 G5 权限、成员、Owner、来源撤权、审计、重放、版本冲突或路由语义。仍保留的兼容层都具备明确生产消费者和移除条件；它们是后续迁移的边界，不是第二套业务规则。下一次移除前必须先完成清单中列出的消费者迁移，并复跑 C1 行为护栏以及 Workspace、generation、candidate adoption、delivery 契约测试。
