## 2. 跑法

### 2.1 启动后端

```powershell
# 仓库根目录
$env:GOCACHE='D:\gocache-lingdoc'
$env:GOTMPDIR='D:\gotmp-lingdoc'
$env:CGO_CFLAGS='-I C:/Users/ASUS/AppData/Local/Temp/lingdoc-sqlite-inc'
make run            # 等价于 go build -o <bin> cmd/server 之后执行产物
```

后端默认监听 `http://127.0.0.1:8080`。**未带凭据访问 `GET /api/v1/version` 返回 401 是「服务存活」的信号**，不是故障。

确认当前后端 head（结论必须挂在确定的代码版本上）：

```powershell
# 登录后调用，读取编译期注入的 commit_id
GET /api/v1/system/info   ->  { "data": { "commit_id": "7f5fd8c", "build_time": "..." } }
```

本轮实跑的后端 head：**`7f5fd8c`**（build time `2026-10-19 17:42:56 UTC`）。

### 2.2 打开页面

```powershell
cd frontend
npm run dev      # vite dev server
```

浏览器打开 `/demo/g3`（路由免鉴权，无需登录）。

- **免登录快照模式**：直接打开即得历史快照视图，不发任何真实请求。
- **真实模式**：点「创建演示账号并运行」——运行时自建账号与隔离项目，走到「登记立项阅读 → 激活 → 两个章节就绪」；重复运行可用「用已保存的账号登录并运行」复用账号，但**每次运行都新建项目**。运行标识（如 `g3r-mvfqelp2-dab7f17b`）派生幂等键，两次运行不会撞键。

### 2.3 导出证据 JSON

| 方式 | 产物 | 落点 |
|---|---|---|
| 页面「导出整链证据 JSON」按钮 | `G3-验收台-8-证据-<runId>.json` | 浏览器下载目录 |
| `npx tsx scripts/g3demo/run-evidence.ts --live` | 同上命名的一份 + 汇总体 `G3-验收台-8-整链证据-<日期>.json` | `docs/08-本轮实施方案/`（仓库内） |
| `npx tsx scripts/g3demo/run-{chain,changeset,dependencies,stabilization,blocked,model}.ts` | 各票的证据 JSON | `docs/08-本轮实施方案/`（仓库内） |

所有证据都落 `docs/08-本轮实施方案/`，**不写进 Issue**（`docs/agents/issue-tracker.md:54-56`）。

### 2.4 跑法上的一条纪律

页面与 node 脚本**共用同一份执行器**（`frontend/src/views/lingdoc/g3demo/runner/*.ts` 是纯 TS + 注入式 HTTP 客户端）。页面侧用 `g3HttpAdapter.ts` 接既有 axios 实例，脚本侧用 `scripts/g3demo/fetchClient.ts` 接 fetch。**两处跑的是同一套代码**，所以「脚本实跑通过」可以证明执行器本身，但**不能**替代浏览器里的交互验收（见矩阵 CON-16 与第 6 节）。

### 3.1 七态词表

`PASS` / `PASS (follow-up)` / `N/A` / `WARNING` / `NOT RUN` / `BLOCKED` / `TODO` —— 只有这七个值，本文件与验收台页面都不引入自造词（前端实现见 `g3Status.ts:13-21`）。

### 3.2 七态之外的免责口径（本文件的用法）

1. **历史快照**：跑在另一个 head 上的历史证据，徽标「历史快照 · 非本次运行」，不得与本次运行的结论混读。
2. **模型依赖**：依赖真实模型的结论是非确定性的，**一律不判 `PASS`**，记 `WARNING`（模型不可用或缺外部凭据时记 `NOT RUN`）。本文件第 4 节矩阵 CON-07 走这条口径。
3. **环境限制**：宿主环境局部限制（如检索渠道未配）记 `WARNING`，并**与产品断言分开记录**——本文件第 6 节把这类限制单独成节，不混进矩阵的产品断言行。

判据原文**照录**主基准，一个字都不改写（`g3Matrix.ts:5-9`）。本文件因此**不复述** AC-G3-01…16 的正文，只给行号锚点，避免二次转述走样；核验方式见第 5 节第 4 条。

2. **阻断级规则问题「接受不处理」（dismiss）返回 500**：对阻断级**规则问题**调用 disposition 的 `action=dismiss` 时服务端返回 500 `internal_error`（`resolve` 返回 201、`waive` 返回 400）。注意与**影响任务**的 dismiss 区分：阻断级影响任务的 dismiss 返回 422 `invalid_state`（本轮实测，非 500）。（G3-GAP-09。）
3. **求值不读 disposition**：`delivery.Evaluate` 与 `TemplateGovernanceRuntime.Check` **都不读 disposition**——人工处置只是工作流元数据，处置后重检结论不变（blocked → blocked）。因此 AC-G3-09 的「问题不再阻断当次求值」那半段在当前后端上不成立；「规则问题与任务分离」那半段成立（对应 ImpactTask 仍 `OPEN`、稳定化仍 `BLOCKED`）。（G3-GAP-10。）
4. **目标对象版本被替换后稳定化是 409 而不是 `closure_stale`**：复写章节版本替换目标对象后 `POST .../stabilize` 直接返回 409 `version_conflict`（阻断原因 0 条、失效任务 0 条），`closure_stale` 分支实际不可达。AC-G3-12 的「保持 BLOCKED 并创建 / 重投对应任务」那半段没有可观测落点；本轮改走「按新基线重投变更集 → 重投任务闭环 → 再次稳定化」才回到 STABILIZED。（G3-GAP-11。）
5. **缺故障注入能力**：产品 API 没有受控且默认关闭的「任务 / 审计写入失败」开关，AC-G3-03 的应用原子性边界无法从 HTTP 面观测整体回滚，当前仅由后端 Go 集成测试覆盖，**不能**冒充页面实跑。（G3-GAP-01。）
6. **缺 RouteNode 写端点**：技术路线节点只有 `GET /projects/{projectId}/route-nodes`，既造不出 AC-G3-08 的「必需节点缺失 / 版本落后」，也造不出 AC-G3-16 的「临时版本与取消未冻结编辑」。（G3-GAP-02 / G3-GAP-03。）
7. **缺「AI 批量提出候选依赖」端点与「助手草稿解释分组」**：依赖边的确认 / 修改 / 拒绝三态有端点，但批量提出候选依赖没有端点；助手草稿的「确定受影响 / 可能受影响」解释分组没有实现。（G3-GAP-04 / G3-GAP-05。）
