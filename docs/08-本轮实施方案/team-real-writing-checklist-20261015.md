# 小组真实试写操作清单（首轮，2026-10-15）

> **只留模板（2026-10-16）**：gong目前尚未选题/排期；本轮不要求人工填写或开跑。下方950一键入口是既有、已记录版本的试写候选。#122同步main后的新源码/CI不是该旧进程的版本证明；实际试写开始前由负责人重新记录正在运行的构建身份。禁止把空白表或合成操作填成真人试写通过。

目标：用一个真实课题检验“找资料—写两章—核查—交付Word”是否顺手，收集最值得修的三个问题。建议1–2位成员、一次45–60分钟；这是小范围使用观察，不是G6正式统计窗口，也不用于证明科研效果或总体效率提升。当前仍是未合并候选，未开跑，不预填参与者/成功结果。

本机真实试写入口已准备：资源管理器双击 `D:/Mon3tr/projects/lingdoc-dachuang/acceptance/full-workflow-first-pass-20261013/real-writing-ready-20261015/开始真实试写.cmd`。它复用已绑定的950候选，以独立普通测试账号和独立浏览器正常登录；测试密码由当前Windows用户DPAPI保护，无需每次输入，不关闭鉴权。该账号初始0课题，与旧演示资料分开；在「切换课题」创建本次真实试写课题。同目录有 `试写操作卡.md` 和空白 `试写记录表.txt`。入口的首次登录/重复进入/失效会话原输入保留已用独立浏览器实测，不代表真实试写已经发生。

B若实际参与，使用另一独立普通账号和浏览器配置；此一键账号不冒充B或多人验证。屏幕共享的旁观不算B登录/协作通过。旧合成演示仍可从原 `final-handoff-20261015/打开演示.cmd` 回看。公网托管、隧道和新增端口开放不在本清单范围。

### 模型默认设置

现有授权仅覆盖既有合成材料/选定证据与指定合成模板，**不自动覆盖新的真实课题资料**。没有本次外发确认时：采用人工写作、来源回看、证据记录和Word交付路线，AI步骤记NOT RUN。不得用假模型结果写成真实AI通过。

若已明确获准：只选本课题允许模型使用的片段和证据卡；沿用已配置模型、输入/输出上限与负责人确认的共享剩余预算，不另购服务、不自动反复重试。首次失败保留提示与版本再判断，不为完成清单连续重新生成。

## B. 成员实际操作：按顺序走一遍

| 步骤 | 怎么操作 | 看什么/留下什么 |
|---|---|---|
| 1 进入（约3分钟） | A使用专用测试账号登录，打开灵档项目。记录实际版本和开始时间 | 能否直接找到工作台；第一次需要求助的位置 |
| 2 创建真实试写课题（约5分钟） | 首次空白首页，在中央“课题名称”填“试写-课题简称-日期”，保留“两章演示模板·1”，点“创建课题”。已有课题时再用“切换课题”中的“新课题名称”；目录收起时先“显示目录” | 新课题应独立于合成演示和既有项目；命名不含隐私信息 |
| 3 条件和立项 | 在“研究条件”写真实主题/本次目标，先“保存研究条件”，再“立项并创建章节” | 保存成功、出现研究问题/研究方案；不要把草稿创建当立项完成 |
| 4 找资料并回看（约8分钟） | 打开“调研与证据 →”，从“1 调研”检索负责人已准备/绑定的资料，在“2 摘录”查看原文，选择实际相关的一段 | 找到的段落是否能支撑写作；能否回到原资料/位置；入口找不到即记录，不让观察者立即代操作 |
| 5 做一张证据卡 | 在“3 证据”说明片段支持/反对什么、适用范围和局限，按界面人工确认后“选用于正文” | 主张与原文是否一致；证据编号/版本可见；选中不等于正文被自动改写 |
| 6 写两章（约10分钟） | 返回文稿，按需要收起目录/辅助区，人工写研究问题与研究方案；试一次标题或列表、撤销/重做、查找；留意“保存文稿”状态 | 写作区是否开阔，常用入口是否容易找到；正式提交前核对正文 |
| 7 可选AI | 仅在A节外发许可已确认时，点“选段改写”，查看选定证据的关系/版本/范围/局限，再明确生成；比较候选，决定采纳或取消 | 是否真的改进表达、引用是否对、无依据内容是否新增；未许可/无需求时记NOT RUN而不强制调用 |
| 8 待核和正式确认（约5分钟） | 点顶部“核查”，从事项定位原句/数字与来源，逐项填处置理由；无依据的结论保留警示。按状态先“提交为正式版本”，再确认当前版本 | 是否知道“核什么、对应哪句、凭什么处理”；按钮不可用时能否知道原因；保存文稿不等于正式提交或确认 |
| 9 检查、冻结、生成、下载（约5分钟） | 点“交付”→“交付检查”；有阻断先读说明。检查通过后“冻结当前内容”，在该快照“生成 DOCX”，完成后从导出文件条目下载；必要时“刷新交付历史” | 冻结、生成和下载是三步。选择本次通过检查的快照；找不到下载入口/一直无结果即记录，不反复点被阻断旧快照 |
| 10 Word往返（约5分钟） | 将这次实际下载文件保留为original-export.docx；用Word打开，核对两章/引用/待核附录。另存edited-copy.docx，改一句、保存关闭、重新打开 | 改动保留、无缺章/乱码/明显格式损坏；记录Word版本。只用本次下载文件，不能拿旧样例替代；没Word则NOT RUN |
| 11 反馈（约5分钟） | 填C节表，列最值得修的3个问题；每人写1处有帮助、1处更费劲的地方 | 记录真实观察；没有改善也照写，不编造成功率或统计结论 |

若步骤4/5的入口或资料操作不通，允许按原目标继续纯手写和交付，但相关步骤保留BLOCKED/FAIL；观察者帮助、Agent/API代操作、人工录入和自动解析分别记录。不能把代操作后的成品写成成员独立完成全部页面流程。

### 可选：B实际协作（主流程之后，约5–10分钟）

- A在“成员与协作权限 →”向B的测试身份发邀请，限定可写章节和可用资料；B在自己的浏览器会话接受。
- B在分配章节改一句并保存，未分配章节应不可写。不要更改真实租户成员身份或转移生产项目Owner。
- 如需要查双窗口冲突：两个窗口先读取同一测试章节，再分别改动、依次正式提交；第二次应明确冲突、保留输入，不能覆盖第一份。不要为完成测试反复覆盖有价值的稿子。
- B没有独立登录/邀请/操作时，本段记NOT RUN。Owner失联旁路、租户停用/恢复和扩大试用管理均为延期专项，本次不强制走。

## D. 这一轮怎样结束
