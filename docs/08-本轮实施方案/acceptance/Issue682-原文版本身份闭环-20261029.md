# Issue #682：上传原文的完整内容身份

日期：2026-10-29。目的地：PR #755 分支 `codex/issue-682-research-acceptance`。

## 用户可见结果

本地知识库文件在绑定到项目后记录完整原始字节的 SHA-256。证据卡读取原文时同时校验当前完整内容和引用定位；原路径被覆盖、内容变更、原文无法读取或没有既有摘要时，旧来源不能被误当成原文未变并继续正式确认/写作。

## 事务与领域不变量

- 哈希在服务端存储读取端计算，使用原始字节，不使用片段/摘要/旧 MD5/file_size 代替。
- SHA-256 与资产修订同存于现有不可变修订的 `metadata_json`；API 资产 schema 不增加字段。
- 每次授权读取前刷新源存储摘要。摘要变化产生新的 asset revision；旧引用的 revision 不匹配即失败关闭。
- 读取引用时，原始全文摘要必须等于当前已存摘要，且引用文本仍在对应定位上；缺少任一证明时 `StableOriginal=false`。
- 8 MiB 以上或不支持读取的来源继续不可作为已验证原文，不截断后伪称完整摘要。
- 不复制或延长保留论文原文，不改变用户授权与文件保留策略。

## 验收矩阵

| 场景 | 期望 | 证据 |
| --- | --- | --- |
| 首次绑定可读文件 | 摘要随修订持久化，重复读取稳定 | Fingerprint / binding tests |
| 原路径同长度覆盖，引用句未变 | 刷新时生成新修订；旧证据失效，不能确认/消费 | Overwrite regression + application seam |
| 当前文件无法读或超过读取上限 | 不声称原文稳定；没有部分摘要 | Negative reader cases |
| 历史资产没有 SHA-256 | 首次能取到时产生新修订；取不到时继续 fail-closed | Legacy migration/refresh cases |
| SQLite 关闭并重新打开 | 摘要和修订号读回一致 | `TestOriginalContentSHA256PersistsAndRefreshAdvancesRevision` |
