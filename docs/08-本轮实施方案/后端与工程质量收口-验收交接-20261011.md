# LingDoc 后端与工程质量收口：验收交接

日期：2026-10-11

## 交付范围

本变更补充一个可复跑的后端质量收口入口、结构化状态矩阵和 CI 日志归档；不新增业务状态、不改前端页面、不改数据库迁移。自动化只使用仓库的合成测试夹具，不读取用户项目正文或模型凭证。

## 干净环境复跑

本地建议使用 Linux、WSL 或 Git Bash，准备 Go（支持 CGO）、Python 3.12 和 Docker Engine。命令从仓库根目录执行：

~~~bash
python -m unittest discover -s scripts/acceptance -p 'test_*.py' -v
python scripts/acceptance/lingdoc_backend_closeout.py \
  --output-dir artifacts/backend-closeout \
  --require-postgres
~~~

PostgreSQL 优先使用环境注入的 LINGDOC_TEST_POSTGRES_DSN，但脚本只接受 host 为 localhost、127.0.0.1 或 ::1，且数据库名和用户名都必须是 lingdoc_test。值不会写入报告或日志。没有安全测试 DSN 时，脚本尝试启动 postgres:17 临时容器，创建合成 lingdoc_test 账号和数据库，绑定随机回环端口、不挂载持久卷；正常结束或异常退出都会停止容器。验收开始前会再创建随机命名的 lingdoc_fault_* 测试数据库和独立测试账号，仅应用 LingDoc 所需版本化迁移；故障场景完成后，仅对这份带所有权标记的临时库执行反向 down migrations，确认 LingDoc 表已撤销，再 up 一遍确认当前 schema 可恢复，最后删除该库和账号。不会复用、回滚或清理用户数据库。Docker 不可用、数据库未就绪或测试库准备失败时，相应 PostgreSQL 场景为 BLOCKED；不回退到应用数据库。

Go 组执行 race 测试、vet 和 server build；G6 状态/脱敏报告单测一并复跑。CI 另外保留原有 API 合同重复运行、前端测试/类型检查/构建、LingDoc 契约检查和全仓构建入口。

~~~text
产物目录：
  postgres-fixture-create.log  隔离故障测试库创建与迁移日志
  postgres-migration-rollback.log 临时测试库 down/up 往返日志
  postgres-fixture-cleanup.log 清理临时测试库/账号的日志
  go-test.jsonl            Go 测试事件（供逐场景矩阵解析）
  go-vet.log               Go 静态检查日志
  go-build.log             服务端构建日志
  g6-quality-tests.log     G6 验收报告器测试日志
  report.json              当前 commit 的机器可读状态
  summary.md               人工快速查看的状态摘要
~~~

测试报告会过滤常见 DSN 密码、Bearer token 和模型密钥形状；报告仅包含环境版本、测试名称、状态及安全的测试库元信息。不要把真实 DSN、密钥或研究项目数据写入命令行日志或 artifacts。

## 失败/恢复矩阵

每个自动场景会由 go test -json 的当前运行事件计算状态；缺少预期测试为 BLOCKED，测试跳过为 NOT RUN，测试失败为 FAIL。矩阵关联的测试名集中维护在脚本的 GROUPS 常量中。

| 类别 | 自动化覆盖 | 边界 |
|---|---|---|
| SQLite fresh/upgrade migration | 版本化 schema、旧版本保留数据、LingDoc migration batch | 真实用户库回滚不自动执行 |
| PostgreSQL migration/repository | 隔离测试 schema 中执行 LingDoc migration 与 repository contract | 需 disposable lingdoc_test 库 |
| PostgreSQL migration rollback | 专属随机 LingDoc 测试库执行 reverse down、检查表撤销、再 up 恢复最新 schema | 仅合成库；不代表生产数据回滚或备份恢复 |
| 撤权与下载鉴权 | 分享撤权后章节/来源/已导出文件读回 | 不代替生产 OAuth/浏览器检查 |
| 版本冲突 | 陈旧版本确认、交付、变更集写入拒绝 | 由并发/版本回归提供证据 |
| 重复提交与幂等 | 候选采纳、确认、冻结、导出、规格重试；真实路由中提交后丢弃首个响应再重试 | 未模拟真实网络连接中断 |
| 模型超时与任务取消 | 假 provider 的 deadline、运行中 cancellation、队列取消、重试取消 | 真实上游 provider 超时未在线上调用中验证 |
| 重启读回 | SQLite store reopen 与快照 ID 持久化 | 不等于重启完整服务进程 |
| 文件损坏与恢复 | 篡改已存导出字节被拒、失败渲染恢复重试 | PostgreSQL 项要求测试库 |

已明确列为 NOT RUN 的外部流程：真实上游模型超时、完整服务进程重启、真实模型+浏览器端到端，以及生产/演示数据库的 down-migration 回滚。CI 会在隔离合成库中自动做 down/up 往返，但不能替代真实数据备份恢复演练。确定性假 provider timeout 和服务提交后丢弃响应的重试均由 CI 自动化覆盖，但不能替代真实模型或网络环境的验收。

### 状态含义

- PASS：本次运行发现对应测试且全部通过。
- FAIL：至少一个对应测试失败，或自动检查失败。
- NOT RUN：测试存在但被跳过，或该流程目前没有执行器。
- BLOCKED：缺少必要运行环境/测试事件，或没有安全的 PostgreSQL 测试库。
- 自动检查可 PASS 而整体 closeout 仍为 BLOCKED：后者必须等所有未运行的真实流程由负责人员补证，不把 CI 绿灯说成产品验收完成。

## 迁移、回滚与发布检查

本 PR 不新增迁移。CI 从干净 SQLite 数据库和独立 PostgreSQL schema 运行当前 up migration / repository 检查，并在随机命名、运行结束即删除的测试库中验证 LingDoc down/up 往返；不对开发、演示或生产数据库执行清理。真实库的 down migration、备份恢复和发布回滚仍须在单独隔离环境演练，禁止把本脚本的容器删除当作业务数据恢复证据。

发布前逐项核对：

1. 同一 head commit 的 Go、LingDoc API/数据库、前端、契约、构建和并发 CI 全部通过。
2. report.json 中 SQLite migration、撤权下载、版本冲突、幂等、取消、重启读回、文件损坏等自动项没有 FAIL/BLOCKED。
3. PostgreSQL migration 与 `postgres_migration_rollback_roundtrip` 项是 PASS；否则不得宣称双数据库迁移收口完成。
4. 本次发布要求的真实模型、完整服务重启、response-loss、超时、浏览器和迁移回滚项由负责人单独验收，留存去敏日志和恢复读回。
5. 确认密钥来自安全环境注入，不进提交、命令输出、报告或截图；检查下载鉴权仍按当前授权失败关闭。
6. 发布前完成备份、升级兼容性和回滚责任人确认；失败时暂停发布，不在生产自动执行 down migration。
