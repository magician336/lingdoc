# G6 质量运行门禁

本文记录 G6-01 至 G6-06 的可复现门禁入口。它们使用 Python 标准库生成稳定 JSON，结果统一使用 `PASS`、`FAIL`、`NOT RUN` 或 `BLOCKED`；Beta 指标另用 `readiness=NOT READY` 表示样本或分母不足。没有真实权限、日志、回退和试用观测时，不把计划当作通过证据。

所有切片可以由一个总入口组装：

```text
python scripts/lingdoc_mock/g6_run.py --output artifacts/g6-run.json
```

总报告保留 G6-01 至 G6-06 的门禁结果和脱敏摘要；运行矩阵执行器自己的 JSON 仍保留各模式的独立 `reports`，统一入口只接受并输出状态化矩阵字段，避免把子报告中的凭证或正文带入总报告。任一 `FAIL` 优先，缺少真实证据则为 `BLOCKED`。可用 `--main-path-report`、`--runtime-matrix`、`--events`、`--security-observations`、`--rollback-observations`、`--samples` 和 `--window` 注入已脱敏的外部观察。

## G6-01/G6-02 主路径和运行矩阵

主路径的 contract-only fixture 可重复生成，并显式包含一个“失败后无正式副作用”的失败读回：

```text
python scripts/lingdoc_mock/g6_main_path.py --mock-fixture --report artifacts/g6-main-path-mock.json
```

该命令只证明脱敏报告形状、主路径覆盖和失败副作用断言；真实 API 仍需由 F01 runner 产生报告。运行矩阵由现有 `run_scenario.py` 驱动，统一入口通过 `--runtime-matrix` 纳入 G6-02；也可以把三个模式各自的脱敏 F01 报告按 `mock`、`real_api_fake_model`、`real` 键写入 JSON，再用 `--main-path-reports <path>`、可选的 `--runtime-dependencies <path>` 和 `--provider-semantics <path>` 由 `g6_run.py` 组装矩阵；两种入口不能同时使用。三种模式保持独立，只有三种模式、共享 fixture、依赖状态、provider semantics 以及每模式的主路径/关键失败证据都明确时才可得到矩阵 `PASS`。场景证据通过 `--scenario-evidence <path>` 以状态化 JSON 注入，写出前只保留 fixture、结果、步数、HTTP 状态、无副作用和回读状态，不接受正文或 token。

## G6-03 安全矩阵

G6-01 的完整主路径入口复用现有 F01 workflow：

```text
python scripts/lingdoc_mock/g6_main_path.py --report artifacts/g6-main-path.json
```

[`g6_main_path.py`](../../scripts/lingdoc_mock/g6_main_path.py) 从同一份 F01 声明派生项目、资料、章节、检查、发布、导出和下载覆盖；它要求另一个失败 fixture 提供正式副作用读回，缺少该观察时完整报告保持 `BLOCKED`。它不会复制 F01 业务流程。

```text
python scripts/lingdoc_mock/g6_security.py > artifacts/g6-security.json
```

[`g6_security.py`](../../scripts/lingdoc_mock/g6_security.py) 固定覆盖撤权后的正文/来源/导出/下载、跨租户、跨项目、scope、共享 Agent、审计查询、旧快照、缓存和预签名 URL 重放。每个案例带 `P0/P1/P2`、预期状态、处置动作和 `quality_evidence` 引用。脚本只接受状态码、明确的 permission decision 和（SEC-12）`metadata_only=true` 作为实时输入；正文、来源原文、请求体和令牌会被拒绝，不写入报告。未提供同一 fixture 的实测状态时，案例为 `BLOCKED`；所有预期状态都被观测且匹配时才可为 `PASS`。

## G6-04 观测和告警

```text
python scripts/lingdoc_mock/g6_observability.py > artifacts/g6-observability.json
```

[`g6_observability.py`](../../scripts/lingdoc_mock/g6_observability.py) 校验请求、异步任务、变更、检查、快照、导出、下载和审计事件是否能以同一 `correlation_id` 串联。结构化事件只允许脱敏 ID、状态、版本、耗时、错误码、资源类别和运行模式；正文、来源原文、令牌及模型输入字段会被拒绝。`alert_coverage` 必须为每个失败信号绑定暂停、重试、回退、阻止导出或通知动作，`uncovered_scope` 明确列出未覆盖事件/信号。事件链或动作映射不完整时报告为 `BLOCKED`。

## G6-05 迁移、灰度和回退

```text
python scripts/lingdoc_mock/g6_rollback.py > artifacts/g6-rollback.json
```

[`g6_rollback.py`](../../scripts/lingdoc_mock/g6_rollback.py) 固定检查旧对象兼容读取、新字段未知安全、灰度按租户/项目/模板/规则/运行模式暂停、历史对象不变、逆向 ChangeSet 和恢复后权限/下载复验。它只评估布尔观测，不修改迁移状态、revision 指针或发布文件。默认是 `BLOCKED`；完成一次 P0/P1 演练并逐项传入观测后才可为 `PASS`。

## G6-06 Beta 指标

[`g6_metrics.py`](../../scripts/lingdoc_mock/g6_metrics.py) 接受锁定的试用窗口和脱敏样本，保留原始提交数、真实样本数、排除的非 real 样本、分子、分母和缺失分母。窗口还锁定纳入用户、项目、运行模式、模板/规则版本、回退结果、未覆盖风险和 `process_evidence`（授权、主路径、关键失败、人工复盘、修复/回退、关键场景复跑）；风险只能是脱敏短代码。只有 `runtime_mode=real` 且 `quality_result=PASS` 的样本进入效果率；样本量或分母不足输出 `BLOCKED` + `readiness=NOT READY`，P0/P1 或真实依赖阻断输出 `BLOCKED` 并给出 `pause`，满足门槛才给出 `expand`。因此不能用 mock/fake 样本补足真实效果分母。

```text
python -m unittest scripts.lingdoc_mock.test_g6_quality
```

本轮实现的完整回归命令为（POSIX）`NO_PROXY=127.0.0.1,localhost python -m unittest discover -s scripts/lingdoc_mock -p 'test_*.py'`，Windows PowerShell 等价命令为 `$env:NO_PROXY='127.0.0.1,localhost'; python -m unittest discover -s scripts/lingdoc_mock -p 'test_*.py'`，结果为 191/191 `OK`；另执行 `python -m compileall -q scripts/lingdoc_mock` 与 `git diff --check`。根目录 Go 测试在 Windows 工作树上会受本机缺少 `sqlite3.h` 的 cgo 工具链限制，不能作为 G6 Python 门禁的失败依据。

这些门禁是质量证据接缝，不替代 G1–G5 的权限、日志、迁移和产品实现；真实验证仍需在隔离租户和可追溯环境中执行，并把状态码/事件/回退观察结果脱敏后传给相应入口。
