# G5-C1：复杂度基线与行为护栏

> 对应 GitHub Issue [#178](https://github.com/magician336/lingdoc/issues/178)，父 Spec [#177](https://github.com/magician336/lingdoc/issues/177)。
> 本文记录本轮重构前的可观察行为和当前消费者。它不引入新的权限、路由、UI 或数据表。

## 1. 主 seam 与测试边界

本轮把 `workspace` 应用边界作为唯一主 seam。测试观察两个层次：

1. **最高应用 seam**：`internal/lingdoc/workspacecore.Service` 的 typed mutation result 方法（例如 `CreateProjectResult`、`SaveSpecResult`、`SaveChapterResult`）。调用方只看到领域值和 `Replayed`，不看到事务、JSON 响应字节或 HTTP 状态。
2. **代表性 HTTP seam**：`internal/lingdoc/workspace.Handler` 的 `PUT /api/projects/:projectId/spec` 和 `POST /api/projects/:projectId/change-sets`。Handler 只负责请求解码、状态码、错误码和 envelope，应用服务负责领域结果。

测试不读取数据库作为断言旁路，也不绑定私有 helper 的调用顺序；持久化测试只在应用 seam 的行为需要跨请求验证时使用真实迁移数据库。

### 端口依赖的读取规则

- `Handler` 只通过 `Read`、`Write` 和 `Sources` 端口工作；HTTP 测试不构造 `Transaction`。
- `SourceRuntime` 是装配适配器，负责把同一来源复核判据接到 Workspace、候选采纳、确认和交付。
- `Service.operation` 是核心域内部模块；外部调用方不得依赖其 `op`、`target`、`body` 或事务 callback 形状。
- `HandlerDependencies.Service` 是兼容入口，迁移完成前保留；新增代码应优先提供 focused ports。
