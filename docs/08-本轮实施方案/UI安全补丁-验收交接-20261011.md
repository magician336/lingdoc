## 协作者操作

- 在合成项目中快速输入正文，900ms 内刷新；取消离开，应看到原输入。保存中或故意断开后端导致保存失败时重复验证。正常保存后离开应不误报。
- 填写待核理由但未确认，离开应提醒；确认成功后仅保留表单不应继续提醒。修改研究条件、引用用途和模板草稿也应提醒。
- 未填理由时确认按钮旁显示数量；逐条填写后解除该理由阻断。工作副本尚未提交时显示提交要求。保护条件保持服务端规则。
- 用测试代理/合成服务使采纳 POST 成功、随后 GET 失败：显示已采纳、采纳按钮禁用；多次“重新读取章节状态”只能发 GET，不得再发 POST；读回恢复后显示服务器当前版本。
- 交付遇版本冲突后延迟父级读取，先显示刷新中；读取失败不能显示成功；读取恢复后才能提示重试。原动作由用户明确重试。

## 限制与回退

beforeunload 由浏览器决定是否/怎样显示，通常要求先有用户交互；不能保证浏览器崩溃、移动端强杀或关闭时网络保存。此补丁不建设离线草稿恢复、跨标签正文合并或全局任务通知。

本次未运行真实后台/模型/Word/生产 OAuth 或 PostgreSQL；合成浏览器检查不是完整产品验收。Go 源码未改，不重复后端全量回归；本地未运行大型全仓生产构建，构建检查由 PR CI 执行。跳过用例仍如实保留，不等于通过。

回退可撤销本补丁提交，不涉及清库、迁移或权限降级。PR 保持未合并，独立评审和用户验收分别进行。

## 2026-10-13：PR #109 研究条件辅助表单 P1 修补

评审遗漏经复核收窄为真实路径：已立项项目先修改主题或目标，使 `specChanged` 为真并显示理由/章节选择；输入理由或勾选章节后，再把主题和目标都改回已保存值。表单虽然被 `v-if` 隐藏，其 ref 仍持有输入，原判定会把页面当成 clean。初始条件未改时，这个辅助表单不可填写。

修订结果：辅助输入按项目记录提交意义快照（理由 trim、章节 ID 排序且复制数组），默认空态为 clean。恢复主题/目标不再绕过辅助输入的刷新、路由离开、项目切换、同项目条目点击或显式重读确认。取消保持全部当前输入；目标项目、章节、资料和 ChangeSet 的初始读取全部成功后才重置表单，失败保留原项目与草稿，避免旧理由和旧项目章节 ID 串入新项目。

成功生成 preview 只确认其提交快照，辅助 dirty 清零；尚未应用的主题/目标仍由 `specChanged` 保护，不能把预览当成整页已保存或已应用。preview/apply 失败保留理由、选择和可重试状态。成功 apply/reject 后 reset 辅助输入；其内部重读通过局部 `conditionsHandled` 参数略过已经处理的条件输入，正文、模板、保存中请求及未确认待核理由仍要求确认。若用户取消这次因其他草稿触发的确认，保留正文和当前元数据，服务端应用成功由状态行继续承认；后续显式重新读取仍需用户处理草稿。本修补未建设保留全部草稿的局部项目刷新生命周期。

改动文件：`Workspace.vue`、`uiSafety.ts`、`uiSafety.test.ts`、现有 `frontend/tests/ui-safety.browser.mjs` 与两份验收/状态说明。无 HTTP DTO、后端、数据库、依赖或其他工作树修改；施工阶段未提交/推送；根代理验证后更新原 PR #109，仍不合并。
