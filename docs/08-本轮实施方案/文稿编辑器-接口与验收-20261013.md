# 连续文稿编辑器的接线与验收

本切片沿用工作副本、正式章版本、确认、冻结与导出体系；`body_markdown` 仍是唯一正文，Tiptap JSON 只在编辑器内部。工作副本保存不是确认。旧纯文本、旧快照及文件保留；未修改章不应重写正文。完整 G1–G7 不因本切片宣布完成。

## 交互与权限边界

空章可直接手写，不要求先有资料或 AI。两章在同一文稿中阅读编辑，章标题/章界受保护，每章独立 CAS 保存。资料按知识库/文件名称选择；全库资料、课题绑定许可集合和正文实际引用应分别显示。LingDoc 是写作主线，原生 WeKnora 知识库/对话为明确可返回的支持入口。

保持身份、项目成员、章节权限与来源授权。输入或工作副本正文改变后，旧正式确认不能授权当前草稿；正式版本与历史导出仍按各自版本展示。失败/409/迟响应不得清除当前输入或伪报已保存。

## ReviewAnchor

ReviewItem 新增可选 `anchor`，无锚点是章级事项，不能猜测段落。范围以该章 `body_markdown` 的 UTF-16 索引表示（不是 Go byte、也不是 ProseMirror position），字段为 `start_utf16/end_utf16/quote_markdown/working_copy_revision/chapter_version_id/status`。`status` 为 `located` 或 `stale`。

定位必须同时核对版本、范围和原文。正文改变时仅原 quote 唯一精确出现才重定位；被删除、改变或重复时标 stale，需显式重新关联。陈旧定位不随刷新复活。修改只增工作副本 revision，不产生正式章版本或确认。锚点随正式提交和冻结输入保留；旧版本不变。

`PUT /api/v1/lingdoc/projects/:projectId/chapters/:chapterId/working-copy/review-items/:itemId/anchor`

```json
{
  "expected_chapter_version_id": null,
  "expected_spec_revision": 1,
  "expected_working_copy_revision": 2,
  "anchor": {"start_utf16": 3, "end_utf16": 5, "quote_markdown": "引用"}
}
```

沿用 `Idempotency-Key`。`anchor` 必须出现；`null` 明确解除关联。只允许修改既有 item 定位，不允许改 statement/origin 或凭空添加 item。成功为现有 `Envelope<WorkingCopy>`，revision 增一；409 不覆盖；新写和同键重放均复查当前来源授权。

## 真实确认读回

`GET /api/v1/lingdoc/projects/:projectId/chapters/:chapterId/confirmations/current`

返回 `Envelope<Confirmation|null>`。Confirmation 保留现有 `id/chapter_id/chapter_version_id/spec_revision/template_version/asset_versions/actor_user_id/created_at/valid/review_decisions` 全记录，不用前端空草稿替代。

只返回当前有效正式确认；没有或已过期返回 null。即使正式确认存在，未提交的工作副本仍不能作为该确认的正文。前端必须比较真实正式章与工作副本正文/来源，不以“确认中的章ID等于确认中的章ID”自证有效。

## 格式与 Word

首批支持段落、正文二至四级标题、粗体/斜体、有序/无序列表和 `[[source:id]]` 引用。章一级标题来自模板。列表保留起始数字、嵌套和续段；字面量星号、反斜杠转义、实体和中文 emoji 的呈现必须前后端一致。不支持表格、图片、公式、代码/引用块、复杂分页；旧不支持块保存原文且交付明确拒绝，不能静默压平。

后端 Goldmark 1.8.6 解析 Markdown AST，WordprocessingML 写出标题样式、强调 run 和真实列表编号。校验生成文件的文字顺序、样式/run、numPr、numbering 的起始/类型及包关系/Content-Type，不只检查 ZIP 非空。页面外观仍由模板控制，并不承诺与浏览器像素一致。

## 必须实际验收

共同语义样例 `internal/lingdoc/docx/testdata/editor-md-golden.json`：中文/emoji、引用跨强调、转义/实体、列表起始与嵌套、旧不支持块。还需实际界面走空课题→两章手写→保存/重开→定位/处置→正式提交/确认→检查冻结→浏览器下载 DOCX。Word 打开编辑保存重开须使用这次下载文件。

定向反例包括：跨章选段/删除、A 请求在途继续写 B、409 输入保留、旧确认失效、重复句锚点、来源撤权后的新写和幂等重放、旧 Get 与已采纳回执交错。UI 布局检查 1440/390px 与原生125%/150%缩放；组件合成结果与真实后端证据分开。

实现、测试、真实浏览器/Word、用户验收和合并是不同状态。每轮证据记录候选 SHA/源码 hash、实际运行程序与前端快照身份。本 PR 不自动合并或部署。
