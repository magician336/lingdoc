# G7 持续写作首版纵切片

状态：首版范围与 G7-01 契约冻结草案，待评审；不是已实现或已验收声明。父任务：GitHub #53。首个冻结基线：`origin/main` `e328c56bb47d22e348850589e4dc9ddbad8d265e`（2026-10-03）。

## 目标与边界

在现有 LingDoc 工作台和已立项项目里，用户可以恢复章节工作副本，对明确选中的一段生成 AI 改写候选、先看差异再决定是否局部采纳，最后显式提交为新的不可变章节版本。保存、候选、采纳和提交不得覆盖用户较新的输入；每次敏感操作都重新检查项目与来源授权。

首版只沿用现有 `body_markdown`、章节来源标记和两章演示模板。暂不做实时协同、OT/CRDT、通用富文本/评论系统、EvidenceCard/ResearchClaim 新对象、自动 ChangeSet、完整申请书自动撰写或第二套编辑器。来源标记与 review items 在工作副本、候选和显式提交间必须保留；review items 是服务端管理的数据，不由自动保存请求覆盖或清空。候选记录生成时通过校验的来源 ID、资料修订、定位和摘录哈希快照，但读取、采纳、提交时仍须重新校验当前权限；快照本身不是授权凭据。显式提交原子创建不可变 ChapterVersion，并把工作副本基线推进到该版本、递增修订号，使旧候选失效。遇到不能安全合并的状态时返回冲突，不能静默覆盖。

## G7-01 交接基线与复现入口

- 主分支基线：`e328c56bb47d22e348850589e4dc9ddbad8d265e`。开工后若 `origin/main` 前进，应在 PR 中记录实际起点 SHA 并重跑契约验证。
- 本地依赖启动：在本地确认 `.env` 已按 `.env.example` 配置、Docker Compose 可用后运行 `make dev-start`；另一个终端运行 `make dev-app`。API 基址为 `http://127.0.0.1:8080/api/v1/lingdoc`。`make dev-start` 只启动 Docker 依赖，不启动后端。不要把 `.env` 内容贴到 issue、PR 或聊天中；此处不把本机 Docker/数据库当前状态写成已验证。
- 身份：契约场景别名 `u-owner` 表示已认证项目 Owner，不是登录名或 bearer token。已有本地端到端证据使用 `e2e@lingdoc.local`，凭据不会进入仓库；复现者须使用自己获准的本地测试账号/短期令牌，通过 `LINGDOC_TEST_TOKEN` 注入。不得把 token 写入 PR、命令历史或验证报告。双人并发场景另需协作者身份，G7-01 单人读取/保存不需要伪造协作者。
- 两章合成 fixture：`docs/08-本轮实施方案/contracts/scenarios.json` 中的 `S1`，模板章节 `question`（研究问题）与 `method`（研究方案），均为空正文、无来源；状态为已立项，不包含真实科研材料。可设置获准的短期 `LINGDOC_TEST_TOKEN`，然后运行 `python scripts/lingdoc_mock/run_scenario.py --scenario G7-01-chapter-read-write --base-url http://127.0.0.1:8080/api/v1/lingdoc --report .scratch/g7-01-read-write.json`。runner 会构造 S1，读取研究问题章节，显式保存，再 GET 读回版本和正文；报告只作当前本机验证证据，不包含 token。它验证已有章节接口，不会验证本计划的新 G7 路由。

## 现有代码核对（基线 SHA）

- `GET /projects/{projectId}/chapters` 已注册于 `internal/lingdoc/workspace/http.go`，由 workspace 应用读取两章及正文、来源、review items。
- `POST /projects/{projectId}/chapters/{chapterId}/versions` 已注册为 `saveChapter`；它显式创建不可变章节版本，带期望章节版本/条件版本、`body_markdown`、`source_ids` 与 `Idempotency-Key`。不得把这个路由说成工作副本自动保存。
- `workspacecore.Service.Authorize` 实施项目能力检查；章节保存经 `SourcePolicy` 对正文声明的来源复核，且已存在撤权先于幂等重放的测试。引用现状可查 `internal/lingdoc/workspacecore/service_facade.go`、`workspacecore/service_test.go` 和 `workspace/save_chapter_policy_test.go`。
- `POST /projects/{projectId}/generations`、候选读取/采纳服务是现有整章生成切片；没有持久化工作副本接口，也没有绑定选段位置与工作副本修订的 G7 候选/局部采纳契约。不得把整章 `acceptCandidate` 等同于局部采纳。
- 服务启动与读写命令可复现，不代表 G7 新路由可用。G7-01 的第二开发者真实服务复现必须由另一位开发者留下 SHA、运行命令、成功读回与破坏契约后的失败证据；本 PR 作者自测不能替代这项验收。

## G7-01 退出条件与未验证项

机器契约检查应验证所有成功样例、拒绝所有反例，并在故意让缺字段反例变为可接受时使检查失败。真实服务上新增 G7 行为暂不适用，因为路由尚未实现。第二开发者复现、服务重启恢复、真实模型请求和 Word/WPS 导出由后续任务负责，必须分别记录 `PASS`、`FAIL`、`NOT RUN` 或 `BLOCKED`，不能以设计检查代替实跑。
