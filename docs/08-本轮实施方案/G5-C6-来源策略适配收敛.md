# G5-C6：来源策略适配收敛

> 对应 GitHub Issue [#184](https://github.com/magician336/lingdoc/issues/184)，父 Spec [#177](https://github.com/magician336/lingdoc/issues/177)。

## 本轮边界

本切片只收敛来源复核的领域 verdict 与消费方适配边界，不新增资料权限、来源类型、交付能力、路由、UI 或数据表。候选采纳、章节确认、Workspace 章节读取、生成和交付继续保留各自的错误与展示语义。

## 共享判定模型

`internal/lingdoc/sourcepolicy` 提供唯一的 `Reviewer` seam 和 `Verdict` 模型。`sourceRevalidator` 是当前实现，负责重建引用、资料授权、坐标和版本复核，并按请求顺序交回逐项 verdict；消费方不再复制这套判据。

`candidateadoption.SourcePolicy` 与 `workspacecore.SourcePolicy` 现在都是共享 `sourcepolicy.SourcePolicy` 的兼容别名。它们仍保留是因为候选采纳和 Workspace Core 的错误映射不同，但不再各自声明同一方法签名。

## 适配边界

- 候选采纳把共享 verdict 聚合为 `ErrStaleInput` 或 `ErrSourceAccessDenied`，确认服务继续从可用 verdict 提取资料版本；
- Workspace 章节读取把共享 verdict 映射为 `available`、`needs_review` 或 `unavailable`；
- 交付冻结和 currentness 只使用共享 verdict 中已复核的来源，不重新计算授权或坐标；
- Workspace 适配器每次调用重新取得当前 `Reviewer`，保留运行时替换资料网关的 currentness 语义；
- Workspace 读侧不再通过 `*candidateAdoptionSourcePolicy` 具体类型断言获得 verdict。

## 行为护栏

资料撤权、坐标失效、资料版本变化、重复 source ID、空引用、item-level status、候选采纳和交付 currentness 继续由 C1/C2/C4 既有测试覆盖。本票新增 Workspace 章节读取对共享 verdict 的 `available` 与 `needs_review` 映射测试。

## 删除条件

`sourcepolicy.SourcePolicy` 兼容别名可在所有候选采纳与 Workspace Core 调用方迁移到直接领域 verdict 后删除；本切片保留它们以避免扩大业务改动和破坏现有测试 seam。
