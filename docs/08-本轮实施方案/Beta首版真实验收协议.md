# Beta 首版真实验收协议

> 2026-10-12 产品负责人确认。决策票：[固定 Beta 真实验收环境与复现协议](https://github.com/magician336/lingdoc/issues/115)。本文定义验收条件，不记录实跑通过；完整 G1–G7 开发沿另一条路线推进。

## 1. 人员、环境和输入

- **一位执行者**完成整套验收，不要求第二位开发者独立复现。
- 使用干净工作树、新测试身份、新隔离数据库和本次独立报告；不复用旧动态 ID、令牌或旧报告结论。
- 后端和测试运行于 WSL2 Ubuntu；持久化使用隔离 PostgreSQL；浏览器与 Microsoft Word 运行于 Windows 宿主机。
- 仅使用固定合成科研材料、演示模板与两章样例；不要求真实课题组材料。材料须实际经过 WeKnora 接入、处理和检索，不能只把分块记录直接灌入库冒充资料解析通过。
- 运行模式为 `real`：API、权限、队列、文件、模型、WeKnora、DOCX 均使用真实依赖。Mock 或假模型可辅助诊断，不能替代通过结论。

## 2. 验收执行顺序

1. 记录代码完整 SHA、环境、数据库/迁移版本、模板版本、合成材料哈希，以及模型提供方、模型名称、参数和调用预算。具体值由执行者在运行前填入报告，不允许留空。
2. 按仓库启动说明准备隔离依赖、执行迁移并启动后端和前端，建立新的测试身份，导入合成材料并确认处理就绪。
3. 对真实服务执行 `contracts/workflow.json` 的 F01 当前全部24个节点：原23个业务步骤加当前生产装配要求的 activation-read 前置请求。保存逐步报告、读回断言和人工语义检查；不得为维持旧步数关闭生产门槛。
4. 在真实浏览器核对项目、资料、候选预览与取消、采纳、章节编辑/确认、冻结和下载交互；注明哪些动作通过 UI 执行，哪些通过 API 执行。只展示成品不能称为整个页面流程通过。
5. 重启后读回项目、章节、来源绑定和交付文件，检查持久化和下载哈希。
6. 完成 Word 人工检查，并归档脱敏证据和总结果。

执行器入口见 [本轮实施方案 README](README.md) 的“提供方联调执行器”；启动配方见 [真实服务启动](T15-真实服务启动.md)。旧启动配方中的版本和本机路径须按本次 SHA 与环境核对，不直接继承历史 PASS。

## 3. F01 和生成内容的通过条件

F01 必须完成全部原23个业务步骤、当前必需的前置节点及相应断言；仅有 `completed_steps` 计数不能代表验收通过。至少检查：

- 章节正文非空，引用指向合成材料中的有效来源，来源定位可读。
- 待核事项显式标记，模型不声称已读取实际未授权的材料。
- 候选、采纳、确认和冻结绑定正确正文版本；数据库副作用通过读回核对。
- 文件来自本次真实渲染和下载，文件哈希与导出记录一致。

真实模型措辞可以变化，不要求逐字匹配样例；结构、证据语义、安全和版本关系必须满足约定。

## 4. Word 人工检查

只要求 Microsoft Word，不要求 WPS，也不固定某个 Word 版本。报告记录 Word 产品版本、Windows 版本和原始 DOCX SHA-256。

执行者打开下载文件、修改一处正文、保存、关闭并重新打开；检查修改保留，正文、标题层级、引用和基本格式仍可用。记录保存后文件哈希和检查结果。程序库 roundtrip 不能替代此检查。

## 5. 模型切换与失败记账

- 使用真实模型；服务限流时允许换用其他真实大模型。
- 切换时记录原因、原模型/新模型、参数、受影响步骤和实际调用账本。不得将不同模型的结果写成同一模型结果。
- 被限流的尝试保留记录；替换模型完成相应生成及其后续引用、采纳、确认、冻结和文件检查后，才可用于通过结论。
- 主流程缺依赖或无法继续为 `BLOCKED`，业务行为违反断言为 `FAIL`，没有执行为 `NOT RUN`；不以 Mock 降级宣称通过。
- 限流以外的余额不足、不可用等故障若无法解决，则保留 `BLOCKED`，不自动扩大已授权的切换条件。

## 6. 总门槛和证据目录

**只有一位执行者完成 F01 原23个业务步骤及当前必需前置节点、业务语义/读回断言、浏览器检查、重启恢复和 Word 检查，且真实依赖均已验证，才标记 Beta 首版通过。** 主流程不能含 `FAIL`、`BLOCKED` 或 `NOT RUN`。非主流程反例单独列出结果、原因和后续责任，不用总平均覆盖。

报告建议保存到 `docs/08-本轮实施方案/acceptance/beta-first/<完整SHA>/<运行标识>/`：

- `README.md`：执行者、SHA、环境/依赖版本、实际命令、总结果、范围与未运行项。
- `f01-report.json`：逐步结果、人工断言和脱敏读回证据。
- `runtime-manifest.json`：数据库/迁移、材料哈希、模板、模型参数、预算与模型切换记录。
- `browser-check.md`、`restart-readback.json`、`word-check.md`：页面、恢复和 Word 检查证据。

令牌、密钥及未脱敏原始响应不写入仓库。工具链错误与业务断言失败分别归因。协议制定完成不等于验收已经执行或通过。
