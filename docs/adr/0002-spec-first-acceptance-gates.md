# ADR 0002：为 Spec 交付设置前置验收门禁

**状态**：accepted
**日期**：2026-10-17

## 背景

PR #151 从 RuleSet 生命周期切片逐步扩展到项目绑定、版本迁移、并发事务、真实数据库、HTTP 消费和审计读回。期间出现多轮评审阻断：早期通用 CI 已通过，但完整 Spec 仍缺少项目迁移、组合 override、生产审计入口、事务 reader 和成功迁移审计等证据。代码、PR body、历史 SHA 和 Draft/Ready 状态也多次不同步，造成返工。

## 决策

所有 Spec 开发采用两道门：

1. 写代码前完成验收矩阵，明确用户入口、领域不变量、事务边界、成功/失败/权限/恢复、持久化/并发和证据；
2. 提 PR 前用当前 head 完成矩阵和证据闭环，未完成时保持 Draft。

`AGENTS.md` 只保留硬门槛，详细流程集中在 [`docs/agents/development-rules.md`](../agents/development-rules.md)。跨模块、持久化、权限、并发和审计变化必须通过真实 application/HTTP seam 验证；直接 store 测试和通用 CI 不单独构成完整交付证据。

## 取舍

- **收益**：在实现前暴露未决决策；让 reviewer 面对稳定的交付目的地；减少“绿 CI 但 Spec 未完成”的往返；让证据随当前 head 演化。
- **成本**：开工前需要维护矩阵，简单的纯文字或机械改动仍需判断是否适用。
- **边界**：纯文字、换行和单文件机械重命名可跳过完整矩阵；跨模块或改变契约的改动不能跳过。

## 后果

新的开发计划、PR 模板和 reviewer 流程应链接这套规则。Issue 只有在最后一个交付切片的矩阵全部完成并经过合并后验收时才能关闭。
