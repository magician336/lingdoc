# 5. CI 门禁按 diff 内容分级：纯格式提交跳过测试类 job

**状态**：已采纳（2026-10-20，由 #284 的开发与 G3 缺口收口评审产生）

**后续**：[ADR 0006](0006-gate-surface-by-contribution.md) 修订了本决策的适用范围。本决策处理「只重排版的推送」，0006 处理「基线合并」；两者合起来构成同一条判据的两半：验证单元是 (被测面内容, 基线内容)，两者都没变就不重测。[ADR 0007](0007-gate-decision-deep-module.md) 进一步把这两条判据的实现收进一个判定模块，**不改变**本决策的口径；#304 把格式快判的实现折进判定模块 `scripts/ci/lingdoc_gate_decision.py`，本决策原来新增的 `scripts/ci/lingdoc_format_scope.py` 随之删除。

## 背景

仓库的 CI 边界只按**路径**判定：动了 `internal/` 或 `frontend/` 下的文件，就重新排队整套矩阵。这对「纯文档 / 纯证据提交」已经处理过（`docs/agents/development-rules.md`「文档提交的 CI 边界」），但代码路径上的**纯格式**提交没有对应机制。

这类提交在本仓是高频的：自动格式化产物（`go fmt ./...`）、只修订注释的提交、import 排序。它们不改变任何行为，却要触发约 17 分钟的全量矩阵。2026-10-20 的 G3 缺口收口（#283）就是一次实例：一次 `errcheck` 写法规范化的返修触发了完整重跑。

值得单独记录的是那次返修的**性质**：`defer rootSQL.Close()` 改成 `defer func() { _ = rootSQL.Close() }()` 是「语义等价但非格式」的重写，**任何格式判定都不该把它当成格式改动**。本决策因此明确了一条边界：快门禁只服务于**机器能证明语义未变**的改动，不服务于「人觉得差不多」。

## 决策

### 一、判据：两个机器可判定的口径，都满足才算

1. **gofmt 等价**：改动后的文件正是 `gofmt` 对改动前的文件会产出的结果。
2. **只改注释与空白**：去掉注释、去掉字符串字面量之外的空白之后，两版的 token 序列逐行相同。

两个口径都不需要人来判断，也都不需要相信提交者的一句声明。

### 二、覆盖范围：只 Go 文件

仓库没有前端格式化器，前端的「格式」没有机器定义。用「忽略所有空白」的弱判定也不行：**字符串字面量里的空白是有意义的**，`"a b"` 与 `"a  b"` 在弱判定下会被当成相同，那是把行为改动判成格式改动。

### 三、跳过的范围：只有测试类 job

跳：Go 测试、前端测试、integration、workspace-concurrency、mock、镜像构建，以及 PR gate 里的 provider tests 与 frontend 步骤。

不跳：**lint**（它就是格式的裁判）、contracts 校验、`git diff --check`、检查边界发布。

### 四、兜底：判不出来就跑全量

范围解析不了、gofmt 不可用、文件被增删或改名、含编译期指令（`//go:`、`//line`）——任何一种情况都判为「不是格式改动」。快门禁的收益是省时间，代价不能是漏掉一次回归。

### 五、只在 PR 更新时生效

首次打开、重新打开、手动 dispatch，以及 push 到 main，都不走这条快门禁。PR 第一次被人看到时，整套矩阵必须跑；之后每次推送若只是重排版，才可以省。

### 六、接线要求：被 job 级条件引用的 output 必须在该 job 的 outputs 中声明

**job 的 outputs 是显式白名单**：step 往 `GITHUB_OUTPUT` 写了键，不等于下游 job 能读到它。下游只能用**该 job 在 `outputs:` 里声明过**的名字去引用，漏声明时取到的是**空字符串**。

后果是**静默失效**：`needs.scope.outputs.format_only` 为空 → `'' != 'true'` 成立 → 跳过条件恒真 → 测试 job 照跑。判定器明明判定对了，门禁却没有生效，而且**不报任何错**。

这条在 2026-10-20 的线上验证（#288）里被真实抓到：#287 合并后，七个工作流的 scope job 只声明了 `run`，`format_only` 从未声明，于是**所有工作流上的快门禁都从未真正生效过**。

由此定下接线纪律：

- 跨 job 引用某个 step 的输出，必须在该 job 的 `outputs:` 里显式声明；**step 级引用**（`steps.<id>.outputs.<name>`）不需要声明，可以直接用。
- 新增或修改门禁条件时，用**守护测试**断言「工作流文件里声明的 outputs」与「脚本写出的键」一致——只测脚本输出不够，因为本地求值不会模拟这层白名单。
- **守护测试自己必须有工作流在跑**。PR gate 的「Test CI scope scripts」步骤运行整个 `scripts/ci` 测试套件（`test_lingdoc_*.py`），且**无条件执行**：纯格式提交也必须跑它。测试没被任何工作流引用，等于保护网没挂上——2026-10-20 的线上验证正是这样发现 `test_lingdoc_format_scope.py` 从未在 CI 执行过。
- 门禁条件的本地求值必须模拟 job outputs 的白名单，否则会得出「本地正确、线上失效」的结论。

**后续（#301）**：这条快门禁不再由工作流自己组合条件。工作流改为直接消费判定模块给出的**单个布尔量**，纯格式快判已经折进这个布尔量里；上面那条「漏声明就静默失效」的纪律不变，守护测试照旧断言每个 `jobs.<id>.outputs` 的键名与工作流 `if:` 里读到的名字一致（另加一条：键名必须符合 GitHub workflow schema 的 `^[_a-zA-Z][a-zA-Z0-9_-]*$`，因为带点的 output 名连声明都过不了 schema）。

## 被否决的备选方案

**按标签或提交信息声明「这是格式改动」。** 需要人贴标签或写声明，等于把判定权交给提交者，而门禁的价值恰恰在于判定不依赖提交者的自觉。机器能判的就不该让人判。

**给 git 也加 `NO_PROXY` 式的按域名绕过。** `git` 走 libcurl，不认 `NO_PROXY`；而给 `github.com` 配空代理会把它改成走不通的直连。按内容分级不依赖任何网络层改动。

**把「语义等价但非格式」的重写也算进去。** 那需要理解语义，无法机器判定，只能靠人眼。本决策只覆盖能证明的两类。

## 影响

- 新增 `scripts/ci/lingdoc_format_scope.py`（判定器）与 `scripts/ci/test_lingdoc_format_scope.py`（单测）。（历史记录：#304 把格式快判的实现折进判定模块 `scripts/ci/lingdoc_gate_decision.py`，这两个文件随之删除；判据本身一字未改。）
- `scripts/ci/lingdoc_change_scope.py` 与 `scripts/ci/lingdoc_pr_scope.py` 增加 `format_only` 输出与判定理由。（历史记录：这两个脚本也已随 #304 删除。）
- 七个工作流的测试类 job 与 PR gate 里的两个测试步骤改为在 `format_only` 为真时跳过；lint 与 contracts 步骤不动。其中六个是跳整个测试类 job（`app.yml`、`frontend.yml`、`lingdoc-mock.yml`、`lingdoc-workspace-concurrency.yml`、`lingdoc-interface-integration.yml`、`lingdoc-f01-runner.yml`），`lingdoc-review.yml` 是跳 PR gate 内的 provider tests 与 frontend 两个**步骤**。
- 「先写接口」的含义在门禁上同样成立：判定器的接口是「给一个 diff 范围，回答它是不是只重排版」，不暴露 git 细节给调用方。

## 风险与限制

- 判定器本身是 CI 的一部分：它出错可能导致一次本该跑的测试没跑。因此判据一律保守，且**任何异常都判为「不是格式改动」**。
- `gofmt` 判据依赖 `gofmt` 在 PATH 上；缺席时该口径不可用，只剩注释/空白口径（更保守，漏判更多而不是误判）。
- 快门禁会让「格式提交」这条路径上的测试覆盖**看起来是空的**。判定理由随检查边界发布，就是为了让人能看出这次是被跳过还是没写。
- **门禁接线本身是失效点**：判定器再对，如果 job 的 outputs 没声明那个键，条件会退化成恒真且不报错。2026-10-20 的线上验证（#288）正是这样抓到一个「所有工作流上快门禁都从未生效」的缺陷。修复方式与守护测试见决策第六节。
