# 后端接口与联调计划

设计基线：LD-V1-20261103-R1。

2026-11-03。本轮只读核对本地源码并准备交接，未改后端、未启动服务、未执行 HTTP 写入。目标是让 Kimi 的新设计接真实能力，不要求新界面服从旧页面结构，也不把现有代码自动视为已验收产品。

核对基线为 `worktrees/native-ui-s0-kimi`。当前 7199 前端真实接通 WordCraft 编辑与 DOCX 副本导出；项目保存、资料和会话持久化、意见处理与变化回看未接通。以下“已有”指源码存在或有历史验收，不表示 7199 已可使用。

## 一 先分清三个接口边界

| 边界 | 已有路径或命令 | 前端应如何使用 |
|---|---|---|
| WordCraft 引擎 | `host_request`：`status`、`open`、`selection`、`insert`、`inspect`、`export`、`ack`；已有章节级 `focusSection` | 由单一原生 Adapter 调用，保持宿主实例；不要以 HTML 编辑器代替，也不要把章节定位当任意段落精准定位 |
| DS 文件宿主 | `POST /api/open`、`POST /api/save`、`POST /api/version` | 同源且带宿主运行配置提供的 `X-Host-Token`；不把令牌写进组件、日志或设计稿 |
| Go 文档版本 | `/api/docx/projects/{projectId}/...` | 负责项目版本登记和交付状态；与 DS 的磁盘版本分别维护 |
| Go 产品业务 | `/api/v1/lingdoc/projects/{projectId}/...` | 项目、资料、会话、影响任务等；统一 API Adapter 处理返回包装、身份、幂等与冲突 |

本地启动还有 `GET /api/local/research/bootstrap`，提供项目和知识库等运行信息。不要把端口、项目 ID 或测试身份写死。新前端联调须由同源代理或既有运行器接入；不能直接用 7199 跨域请求后端并放宽既有回环/Origin 检查。

## 二 首批可复用的真实接口

以下产品路径均相对于 `/api/v1/lingdoc`，`p` 表示项目 ID。

| 用途 | 源码已有合同 |
|---|---|
| 项目列表、详情、创建 | `GET /projects`、`GET /projects/{p}`、`POST /projects`；创建字段 `name`、`template_id`、可选 `template_version` |
| 条件字段 | `PUT /projects/{p}/spec`：`expected_spec_revision`、`fields`、可选 `field_metadata`。已用于写作后的变更还应走 ChangeSet 评估流程，不能直接覆盖后假装没有影响 |
| 项目资料 | `GET/POST /projects/{p}/assets`；绑定请求为 `knowledge_id`。绑定不等于上传文件，也不等于授权模型读取 |
| 来源查看 | `GET /projects/{p}/sources/{sourceId}`、`.../context`、`.../document`；邻近原文和文档读取是不同结果。前端按可读性及当前性展示，不能把失效来源当有效证据 |
| 检索 | `POST /projects/{p}/retrieval`。请求结构以 `RetrieveSourcesInput` 为准，不能用原型的前端筛选冒充检索 |
| 会话 | `GET/POST /projects/{p}/agents/{agent}/sessions`；`GET/POST /projects/{p}/agent-sessions/{sessionID}/turns` |
| 关系与影响 | `GET/POST /projects/{p}/dependencies`；`GET /projects/{p}/impact-tasks`；`POST /projects/{p}/impact-tasks/{taskId}/actions` |
| 条件变化 | `POST /projects/{p}/change-sets/drafts`、`POST .../change-sets/{id}/assess`、`GET .../change-sets/{id}/impact-assessment`；原有 apply/reject 路由仍存在 |

文件上传走另一个已有入口：`POST /api/v1/knowledge-bases/{id}/knowledge/file`，表单字段 `file`。本地适配限制不超过 8 MiB、扩展名属于 bootstrap 返回格式；格式与解析失败必须直达 UI。不要由前端承诺任意文件都能解析。

会话创建用 `G2Expectation`：`expected_project_version`、`expected_context_revision`、`expected_version`。发送消息是 `user_input` 加 `AgentContextInput`，其中有 `source_ids`、`source_excerpts`、`document_selection`、`card_refs`、`sensitive_context_confirmed` 等。现有 `agent` 不等于产品的构思/写作模式；模式归属、历史迁移和上下文继承需明确适配，不能直接改名字冒充隔离。现有请求不是已核实的 SSE 流式合同；设计应兼容普通等待/失败/重试。

写请求普遍要求 `Idempotency-Key`，并对版本做校验。未知结果应重试原请求，不生成新键重复写入。不同 API 错误包装不同，Adapter 统一为可读错误，但保留原错误码与请求依据。

## 三 保存必须复用完整事务

已有链：捕获原生 `documentId/revision` → `export` → DS `save` → Go 登记 → 读回 → 原生 `ack`。

- 原生导出携带 `expectedDocumentId`、`expectedRevision`、`expectedDiskVersion`。
- DS 保存携带 `bytes`、`sha256`、`saveToken`、`documentId`、`revision`、`expectedDiskVersion`；回执需要核对内容摘要、字节数、身份、原版本和 `verified`。
- Go：`POST /api/docx/projects/{p}/versions`，请求为 `expectedDiskVersion`、base64 `data`、可选 `citations`，并带幂等键。`GET .../versions/latest` 获取最新登记版本，`GET .../versions/{version}/delivery` 获取交付状态。
- 原生 `ack` 只能确认真实回执对应的修订。保存期间继续输入时，旧修订已落盘不等于当前编辑器已保存。

已有 `WorkspaceSaveCoordinator` 和宿主实现应优先复用。出现 409、摘要不符、DS 已落盘但 Go 未登记、ack 待处理时，界面分别显示事实并保留编辑内容。不要另建一套只按 React `saveState` 变绿的保存逻辑。项目保存与确认/冻结/正式导出分开，未完成申报内容仍应能保存。

## 四 人工意见与变化任务不要混为同一对象

本地已有工作副本审核锚点接口：`PUT /projects/{p}/chapters/{chapterId}/working-copy/review-items/{itemId}/anchor`，字段包括 `expected_chapter_version_id`、`expected_spec_revision`、`expected_working_copy_revision`、`anchor`。它不是已核实的“导师自由评论创建、回复、解决”完整接口。

人工意见对象需新增或明确复用方案：意见正文、作者/来源、文档及修订、锚点与原文摘录、处理决定、处理结果版本、状态历史。首版允许人工录入导师意见，避免同时引入多人实时协作。纯文本搜索命中不应自动变成可信定位；旧锚点失效时保留意见并要求重新定位。

已有影响任务 action 输入含 `expected_version`、`target_revision`、`action`、`reason`、`closure_evidence`，可选 `human_decision`、`assignee_id`。动作枚举和允许迁移须逐项对应服务实现。前端“需要修改”“暂缓”“已完成”不能直接随意写入。决定与完成结果应分开，完成时关联实际保存版本或无需修改的说明。

2026-11-02 固定远端审计记录还包含句级位置提示、人工选段引用和 AI 定位建议；本地候选路由不具有该完整清单。其位置来自章节 Markdown 的 UTF-16 偏移，不能直接传入 WordCraft。先确定采用的后端版本，再做原生锚点适配；本轮主执行者已于 2026-11-03 通过 GitHub 连接器重新核验 main，仍为 acb9ac744f5c6fbe68bc672ecf08eb03e7db1a22；这是上游源码基线，不等于本地候选或运行服务已升级。

## 五 第一批实施顺序与验收

| 薄切片 | 交付与验收 | 前置依赖 |
|---|---|---|
| 打开、保存、重开 | 编辑真实 DOCX，保存后关闭重开内容一致；保存中继续输入仍显示未保存；冲突/超时不丢内容；下载副本与保存版本摘要一致 | 固定文档身份、真实运行配置、保存协调器 |
| 来源查看 | 上传一份支持格式资料并绑定项目，显示原文/段落/来源状态；访问失效明确提示；查看不自动发送模型 | 解析服务、来源鉴权与原文接口 |
| 人工意见 | 录入一条意见，绑定当时正文，人工修改并保存后记录结果；改动造成锚点失效能回看原摘录 | 意见对象合同、原生锚点验证、可靠保存 |
| 条件变化 | 改一个已登记条件，生成影响评估，查看关联正文，记录决定与处理结果；重复请求不重复建任务 | 真实依赖边、ChangeSet/ImpactTask、意见与任务区分 |

前端可以并行设计所有状态和交互；未联调的操作明确标为演示。后端先提供固定测试数据与真实响应样本，再绑定组件。想法快照、匿名化活页、可编辑路线图另列接口验证项，不假定上述接口已经覆盖它们。
